# 高可用（HA）部署说明

> 目标：多 API 实例同时跑，**写确认 / 审计 / 调用日志 / 历史** 不因落在不同机器磁盘而串台或丢数据。  
> 本期方案：**共享 `DATA_DIR` 卷 + 跨进程文件锁 + SQLite WAL**。  
> **不是** Redis/Postgres 集群、也不是 K8s 全套；上线放量前够用。

---

## 架构

```text
浏览器 / MES iframe
        │
        ▼
   nginx (lb :8765)
        │
   ┌────┴────┐
   ▼         ▼
 api-1     api-2     …（compose --scale api=N）
   │         │
   └────┬────┘
        ▼
  共享卷 DATA_DIR（./data 或 NFS）
   ├── writes/pending|audit.jsonl
   ├── api_calls/calls.jsonl
   ├── history/conversations.db（WAL）
   ├── uploads|exports|…
   └── .locks/*.lock
```

探活沙箱（`:8001`）仍建议**每环境一个**；多 API 共用同一沙箱 URL 即可，沙箱本身不要求多副本。

---

## 关键改动

| 能力 | 说明 |
|------|------|
| `DATA_DIR` 环境变量 | 所有实例指向同一目录 |
| `InterProcessLock` | `writes` / `api_calls` 跨进程 `flock` |
| SQLite `WAL` + `busy_timeout` | 历史多实例读写更稳 |
| `/health` | 存活 + `instance_id` |
| `/health/ready` | 数据目录可写 + 锁可用；失败 503 |
| `instance_id` | 写入审计 / 调用日志，便于排障 |
| `docker-compose.ha.yml` | nginx + 可 scale 的 api |

---

## 本地验证双实例

```bash
# 构建并起 2 个 API + lb + web
docker compose -f docker-compose.ha.yml up -d --build --scale api=2

curl -s http://127.0.0.1:8765/health
curl -s http://127.0.0.1:8765/health/ready

# 无 Docker：无 LLM 锁冒烟
make smoke-ha
```

单机开发仍用 `./scripts/dev.sh`（单进程），与 HA 代码路径兼容。

---

## 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `DATA_DIR` | `<repo>/data` | **多实例必须相同**（共享盘路径） |
| `INSTANCE_ID` | `HOSTNAME` 或 `pid-…` | 日志/审计里标识本实例 |
| `CORS_ALLOW_ORIGINS` | `*` | 上线改为 MES 域名 |
| `MES_SERVER_PORT` | `8765` | HA 编排里是 nginx 对外端口 |

## 运维注意

1. **共享盘**：NFS/云盘需支持 `flock`；不支持则需改数据库方案（后续）。  
2. **写确认**：`claim_action` 在锁内 CAS，双点确认只会成功一次。  
3. **Agent 单例在进程内**：每个 API 进程各自一份 Agent；热更代码仍需滚动重启所有副本。  
4. **会话粘滞**：SSE 长连接一般粘在某一实例；pending 落共享盘，另一实例也能确认。  
5. **回滚**：去掉第二副本、改回单机 `dev.sh` / `docker-compose.yml` 即可；数据仍在 `data/`。

---

## 明确不做（本期）

- Redis / Postgres 替换文件存储  
- 探活沙箱水平扩展  
- 自动故障转移编排（K8s HPA 等）  
- SSO（另项）

---

## 验收

1. `make smoke-ha` → `SMOKE_OK`  
2. `--scale api=2` 后 `/health/ready` 为 ready  
3. 实例 A 触发导入挂起，实例 B（经 lb）确认写入成功且只执行一次  
4. 审计 JSONL 中可见不同 `instance_id`
