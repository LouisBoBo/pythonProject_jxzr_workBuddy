## 1. 目标流程（真实开发场景）

```text
（可多轮）本机写码 → 文件已在目标目录，可不 commit
用户：「提交今天的代码」/「把这批改动提交」…
  → 汇总本批文件列表（见 §3）
  → 只审这些文件（规则门禁；可选加深）
  → 确认卡：阻断/警告 + 文件清单
  → 人点「确认提交」→ API 工作分支 git add/commit（不经模型）
  → 人点「跳过」→ 不 commit
```

### 1.1 Happy / 边界 / 失败

| | 表现 |
|--|------|
| **Happy** | 用户触发 → 本批审过 → 无阻断 → 确认 → 工作分支 commit |
| **边界：无可提交文件** | 说明「今天/本会话没有已同步改动」 |
| **边界：非 git 仓** | 可审、不可提交；卡上说明 |
| **边界：有阻断** | 禁止确认提交（P0/P1 均阻断；除非 `LOCAL_DEV_COMMIT_ALLOW_BLOCKED=1`） |
| **失败：git** | 报错；文件仍在磁盘 |

## 2.5 路由隔离（与全量审码车道，硬约束）

**你的原则：全量审码与提交前审核完全独立、互不干涉；可共用 Skill/规则积木，路由必须分开。**

| 维度 | 全量审码车道 | 提交批审（commit_batch） |
|------|--------------|---------------------------|
| **触发** | 「审核这个工程/仓库」 | 「提交今天的代码 / 提交这批改动」 |
| **前端路由** | `workbuddy_lane=code_review` → Deep Agents SSE | `looksLikeLocalCommitBatch` → **API 直调**（不进 Agent） |
| **后端** | `create_deep_agent` + Skill（`ide-code-review` / `git-code-review` + `code-review`） | `POST /local-dev/commit-batch` → `commit_gate` → `confirm-commit` → git |
| **范围** | 全仓 list → read_batch（分批） | **仅本批**：同步池 ∩ Git 待提交 |
| **输出** | `## 🔍 代码审核报告`（LLM 终稿，四段式） | 确认卡 + 过程步骤（规则结论，无 LLM 报告） |
| **共用** | 可读 `ide_review` 工具链、gate-90 方法论 | **commit-batch-review Skill**（API 直调 LLM+JSON；`disable-model-invocation` 防对话误选） |

**禁止**：

- 提交批审退化成 `request_git_list_source_files` 全仓审
- 全量审码车道里弹「提交确认卡」或直执 git
- 两条路共用一个 `workbuddy_lane` 或同一套 SSE 状态机

```text
用户说「审核工程」  →  code_review 车道  →  Deep Agents + 审码 Skill  →  全量报告
用户说「提交代码」  →  commit_batch 意图  →  local-dev API  →  本批门禁  →  确认卡  →  git
```

## 2. 审码走哪条路？（提交批 vs 全量审码）

**本机目录写码场景：既不是「GitHub 全仓审」，也不是「IDE Bridge 全仓审」的主路径。**

| 路径 | 适用 | 本批提交门禁是否用 |
|------|------|-------------------|
| **本机路径批审**（`local_path` + `paths=[本批文件]`，与 `git_review` 同机读盘规则同源） | 目标目录在 API 同机，文件已同步落盘 | **✅ 默认主路径** |
| **IDE Bridge 审码** | VS Code 已配对、要审「当前 IDE 打开的工程」全仓/分批 | ❌ 不作为提交门禁默认；可另开「审码」车道 |
| **GitHub / 公开仓审码** | 用户确认 HTTPS 仓 URL，浅克隆分批全仓审 | ❌ 不用于本机提交门禁（仓未必已 push） |
| **对话全仓 `code_review` 车道** | 用户明确要「审核这个工程/仓库」 | ❌ 与「提交本批」分开 |

一句话：

- **提交前审码** = `commit-batch-review` **专用 Skill**（API 直调，JSON 过程+结论，无报告终稿）  
- **正式全仓审码** = `code_review` 车道 + `ide-code-review` / `git-code-review` / `code-review` Skill

## 3. 「本批」文件从哪来

优先级（实现时按序）：

1. **用户显式指定**（确认卡勾选 / 消息里点名路径）  
2. **本会话已成功的 local_dev job** 的 `synced_files` 并集（「今天的代码」可再按 `created_at` 滤当天）  
3. **git status**（工作区未提交变更）——仅当 1、2 为空且目录是 git 仓时兜底  

**再过滤（2026-08-24）**：同步池与 Git 交集之后，**只保留业务/功能源码**（与 `ide_review.is_functional_source_rel` 同源）——自动排除 `package.json`、锁文件、`vite.config.*`、`.css/.scss`、文档、静态资源等；确认卡展示「已排除非业务 N 个」。

**禁止**：无范围时退化成全仓 `request_git_list_source_files` 当提交门禁。

## 4. 人如何触发（P1-1b，下一步实现）

| 方式 | 说明 |
|------|------|
| 自然语言 | 「提交今天的代码」「提交这批改动」「帮我 commit」等 → 前端/车道识别为 `commit_batch` 意图（**不是** `code_dev` 再写一轮） |
| API | `POST /api/local-dev/commit-batch`：`workspace` + 可选 `paths` / `since`；服务端跑门禁 → 返回/推送确认卡 → 原 `confirm-commit` |
| 调试 | `LOCAL_DEV_COMMIT_GATE=1` 恢复「写码收尾自动弹卡」（不推荐生产） |

状态机（人触发后）：

```text
idle → reviewing_batch → awaiting_commit
  ├─ commit → git 工作分支 → done
  └─ skip → done（无 commit）
```

## 5. Git 提交策略（P1-1c）

| 项 | 约定 |
|----|------|
| 分支 | `LOCAL_DEV_WORK_BRANCH` / `CURSOR_DEV_WORK_BRANCH` / `dev/wb/<user>` |
| 禁止 | 直接提交 / 推送 `main` / `master` |
| 暂存 | **仅本批**相对路径（自动跳过 `.gitignore`） |
| 确认卡主按钮 | **提交并推送远程**（可填仓库 URL，与 Git 审码类似） |
| 次按钮 | **仅本地提交** / **跳过** |
| **提交说明** | **必填中文**：确认卡填写，概括本次修改；无中文 / 空说明拒绝 commit（禁止 `wb-local-dev` 英文占位） |
| 无 remote | 在确认卡填写 HTTPS/SSH 地址即可推；可选「记住为 origin」 |
| push | 人触发 `commit_batch` 默认 push；`LOCAL_DEV_COMMIT_PUSH=0` 可关掉默认 |
| 执行 | 确认后 **API 直执**，禁止模型 shell |

## 6. 配置

| 变量 | 默认 | 含义 |
|------|------|------|
| `LOCAL_DEV_COMMIT_GATE` | **`0`** | `1`=写码收尾自动弹卡（调试）；生产保持 `0` |
| `LOCAL_DEV_COMMIT_ALLOW_BLOCKED` | `0` | 有阻断是否允许强制提交 |
| `LOCAL_DEV_COMMIT_PUSH` | 未设 | **未设时**人触发提交默认 push；显式 `0` 则默认不推（仍可在确认卡点推送） |
| `LOCAL_DEV_GIT_REMOTE` | `origin` | push 使用的 remote 名 |
| `LOCAL_DEV_WORK_BRANCH` | 空 | 工作分支名 |
| `LOCAL_DEV_COMMIT_GATE_TIMEOUT_SEC` | `600` | 确认卡超时（超时=skip） |
