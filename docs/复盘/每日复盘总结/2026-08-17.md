### 2.2 中午：数据从哪来（边界拍板）

- 探测现场 SQL Server 公网 `:1433`：**端口拒绝连接**。常见原因是未监听公网、防火墙/安全组、需 VPN。账号密码此时验证不到。
- 产品结论（写进方案，避免误用）：
  - **表结构文档** → 只回答「系统大概能管什么」
  - **查工单/计划等** → MES HTTP（OpenAPI 生成的可查对象）
  - **不**把直连生产库当默认查数路径

### 2.3 方案与文档基建

- 用户目标对齐为四块：**很懂这个 MES / 数据分析 / 协助运维 / 加界面加功能**。

### 2.4 MES 资料包接入（P0 产品化）

现场通常只有 **表结构 + 接口文档**，不能把客户数据写死进仓库。

| 你手里有的 | 系统里干什么 |
|------------|----------------|
| 数据库表结构 `.md` | 「读懂 MES」（摸底） |
| 接口文档（`/docs` 或 `openapi.json`） | 自动生成可查对象，不必手写 `entities.json` |
| 平台名称 | 本机资料目录名（`data/mes_profiles/{名称}/`），不是登录账号 |

界面迭代（设置页，按标注改）：

- 文案「资料包 ID」→ **系统名称**（支持中文，如「江西中软MES系统」）
- 顺序：① 平台名称 ② 平台访问地址 ③ 上传表结构及 API 接口
- 支持 `http://127.0.0.1:8009/docs` **从地址导入**（自动找 `/openapi.json`）
- 「一键清除配置」；去掉内置复制 / 高级上传实体入口
- 上传后原生文件框会空：补「已上传 / 已导入」回显
- 「选择文件」无反应：隐藏 `input` 点击不可靠 → 改用 `label` 触发

当前联调资料包：**江西中软MES系统**（表结构 + 8009 OpenAPI）。

## 3. 自检：发现问题与仍存风险

### 3.1 已暴露并已修

- 设置页上传「看起来没成功」——其实已落盘，缺回显。
- 选择文件点了没对话框。
- 去掉内置后能力地图路径残留。
- 表结构格式不匹配导致摸底全空。
- 双 API 进程导致像卡住。

### 3.2 已知边界（不是当天修完的 bug）

1. **查数主机 vs 网页端口**：平台访问地址若填 Vite `:5175`，而 OpenAPI 来自 `:8009`，查数必须打 API 根，不能打网页。当日已口头提醒，次日需把「查数根地址」绑到接口文档 `servers` / `source_url`。
2. **WorkBuddy 登录 ≠ MES 接口鉴权**：登录页是产品登录；上传的 OpenAPI 只生成可查对象。当日方案已写，但查数若误带 WorkBuddy token 打 MES 会 401——次日需拆 MES 接口账号。
3. **路径不能写死 `/api/v1`**：客户文档既有 `/api/work-orders` 也有嵌套 `/api/inspection/plans`，实体 path 须随 OpenAPI 变。
4. **直连 CIMOM 库**：网络未通；即便通了，当前产品也不把生产库当默认查数通道。
5. **桌面包未签名**；Win 包须 Windows 主机全量重打。
6. **当日改动尚未入库**：资料包、解析器、文档分类与方案均在工作区，勿把 `data/settings.json`、`.env`、密钥一起提交。

### 3.3 流程自检

- 先问「表结构能不能当查数」再写方案，避免把字典摸底和 HTTP 查数混成一件事。
- 配置入口放在系统配置而不是只靠对话框记忆——换系统可复现。
- 界面名词按实施同学能懂的改（系统名称），内部仍用 profile id。
- 解析失败先对文档真实标题，再扩解析器，而不是让用户改文档迁就旧格式。
