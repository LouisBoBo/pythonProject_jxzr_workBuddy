# 会话上下文管理说明

> 目标：让同一 `thread_id` 下的多轮对话真正「记得」上文，避免短确认（如「来吧」）丢失任务上下文。

## 1. 之前的问题

对话请求虽然带了 `thread_id`，但 Agent 创建时 **未挂 LangGraph checkpointer**（`checkpointer=None`）。

每轮实际送给模型的只有**当前这一句**用户消息：

```text
invoke({ messages: [ 本轮 user ] }, config.thread_id)
```

因此：

| 现象 | 原因 |
|------|------|
| 上一轮分析完代码并问「要不要贴完整修好版」，用户回「来吧」却变成自我介绍 | 模型看不到上一轮分析与承诺 |
| 重启 API 后同一会话续聊像新开 | 无持久化 Agent 状态；UI 历史只用于展示，未灌回模型 |
| 打开左侧历史继续聊，偶发接不上 | UI SQLite 有消息，Agent 侧无对应 checkpoint |

前端历史库（`data/history/conversations.db`）与 Agent 运行态是**两套存储**，此前没有打通。

## 2. 怎么做的

分三层，互为补充。

### 2.1 持久化 checkpointer（主路径）

- 模块：`apps/agent/checkpoint_store.py` → `get_acheckpointer()`
- 实现：LangGraph **`AsyncSqliteSaver`**（`aiosqlite`），库文件默认 `DATA_DIR/agent_checkpoints.sqlite`
- 接入：API 侧 `create_agent(..., checkpointer=await get_acheckpointer())`；流式用 `astream_events`，同步接口用 `ainvoke`
- **注意**：不可用同步 `SqliteSaver` + `astream_events`，会报 `SqliteSaver does not support async methods`
- 效果：同 `thread_id` 的多轮对话自动累加 `messages`，模型能看到完整对话链

```text
第 1 轮：user(贴码) → assistant(分析 + 询问是否要完整版)
第 2 轮：checkpoint 已有上文 + user(来吧) → assistant(交付完整代码)
```

### 2.2 UI 历史同步（每轮）

- 入口：每次对话前 `await ensure_thread_messages()`（`chat` / `stream_chat`）
- **以 UI 历史为真相源**：把 `conversations.db` 中的 user/assistant 正文同步进 checkpoint（去掉末尾本轮 user，避免与 `ainvoke` 重复）
- 解决：用户点「停止」后前端已落库半截回复，但中断流式时 Agent checkpoint 可能未带上该半截；下一轮「继续」必须能看见断点
- `aget_state` 失败会短重试一次；若 checkpoint 夹杂 tool 等非对话消息，也会整表替换为 UI 对话窗（`RemoveMessage(REMOVE_ALL)` + `as_node=model`）
- 过长则按 `CONTEXT_MAX_MESSAGES` 裁剪

### 2.2b 客户端停止 / SSE 断开

- 前端「停止」→ `AbortController` 断开 SSE
- `chat_stream` 感知 `request.is_disconnected()` / `CancelledError` 后 `cancel_event.set()`
- `stream_chat` 周期性检查 `cancel_event`，并在 `finally` 里 `aclose` 底层 `astream_events`，避免停止后 LLM 仍跑完

### 2.3 窗口裁剪（防爆上下文）

- 回填时：只取最近 `CONTEXT_MAX_MESSAGES` 条
- 已有 checkpoint 且条数超限：用 `RemoveMessage` 丢掉最旧消息，保留窗口尾部
- 单条过长：回填时按 `CONTEXT_MAX_CHARS_PER_MSG` 截断并标注「已截断」

### 2.4 提示词接续（辅助，非存储）

- Skill `paste-code-analyze` + system prompt：短确认（来吧/好的/继续）必须兑现上一轮承诺，禁止中途自我介绍
- 这是**行为约束**；真正记得上文仍依赖 2.1 / 2.2

## 3. 有什么效果

| 能力 | 效果 |
|------|------|
| 同会话多轮 | 「分析 → 来吧」「查工单 → 再筛一下」等短句能接上任务 |
| 停止后再说「继续」 | 停止气泡原样保留；「继续」后新开一条完整/续写答复，时间序正确 |
| 重启 API | 同 `thread_id` 可续；每轮仍与 UI 历史对齐 |
| 打开历史会话 | 每轮按 UI 历史对齐 checkpoint 后再答 |
| Token 控制 | 超长会话不会无限堆积（条数/单条字符上限） |

**仍做不到的（刻意未做）：**

- 智能摘要压缩（把旧轮压成一段 summary）
- 跨 `thread_id` 的长期记忆 / 用户画像
- 多 API 实例共享同一 checkpointer 文件时的强一致（需共享盘 + 注意 SQLite 锁；大规模应换 Postgres checkpointer）

## 4. 配置

环境变量（见 `apps/agent/config.py`）：

| 变量 | 默认 | 含义 |
|------|------|------|
| `DATA_DIR` | 仓库 `data/` | 数据根目录 |
| `AGENT_CHECKPOINT_PATH` | 空 → `$DATA_DIR/agent_checkpoints.sqlite` | checkpoint 库路径 |
| `CONTEXT_MAX_MESSAGES` | `40` | 进入模型的消息条数上限；`0` = 不裁剪 |
| `CONTEXT_MAX_CHARS_PER_MSG` | `12000` | 回填时单条最大字符；`0` = 不截断 |

`.gitignore` 已忽略 `data/agent_checkpoints.sqlite*`，勿提交会话状态。

## 5. 关键文件

| 路径 | 职责 |
|------|------|
| `apps/agent/checkpoint_store.py` | `AsyncSqliteSaver` 单例、历史回填、裁剪 |
| `apps/agent/agents/agent.py` | `create_agent(checkpointer=…)`；CLI 默认内存 saver |
| `apps/api/agent_wrapper.py` | `_ensure_agent` 挂异步 saver；每轮前 `ensure_thread_messages` |
| `apps/api/routes/history.py` | UI 会话历史（展示 + 回填数据源） |
| `scripts/smoke_checkpoint_context.py` | 无 LLM 冒烟（含异步 checkpoint） |

冒烟：

```bash
make smoke-checkpoint-context
```

## 6. 验收建议

1. 新会话贴一段代码 → 助手分析并问要不要完整版 → 回复「来吧」→ 应直接给改好代码，而不是能力开场白。  
2. 完成一轮后重启 API → 同一 `thread_id` 再发「把刚才那版再贴一次」→ 应仍知上文（checkpoint 或历史回填）。  
3. 从左侧打开旧会话续聊 → 首句短确认仍应接得上（依赖 UI 历史回填）。  
4. 超长会话（远超 40 轮）→ 仍可答最近话题；极早细节可能已被裁掉（预期行为）。  
5. 生成中点停止 → 保留「（已停止生成）」气泡 → 说「继续」或「来吧」→ 其后新开一条答复（不合并进停止气泡）；再连点两次「继续」仍应绑原贴码任务。  
6. 停止后看 API 日志：流应尽快结束，不应长时间继续吐 token。

## 7. 后续可演进

1. **摘要压缩**：窗口外旧消息压成一条 system/summary，兼顾长度与远期事实。  
2. **Postgres / Redis checkpointer**：多实例 HA 时替代单机 SQLite。  
3. **任务态显式化**：对「待交付完整代码」等承诺写入结构化 pending，短确认优先读任务态再调模型（进一步降低跑偏概率）。
