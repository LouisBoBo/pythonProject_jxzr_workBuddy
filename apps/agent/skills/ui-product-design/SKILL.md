# 前端产品设计（UI Product Design）

> **定位**：让 WorkBuddy 写出来的界面**像产品**，不像「再贴一张 Element 后台模板」。  
> **配合**：讨论阶段由 `cursor-dev-chat` 引入本 Skill；实现阶段由 Cloud Prompt 注入同款硬约束。

## 何时启用

- 用户要做/改/重写：**页面、界面、首页、概览、看板、仪表盘、表单页、列表页**
- 用户抱怨：**丑、没设计感、和别的页一样、照抄首页、模板感**
- 截图复刻：以截图为规格；本 Skill 负责「还原仍须有层级与质感」，禁止偷换成白卡片

## 设计原则（必须遵守）

1. **一页一身份**  
   每个业务页必须有**可辨认的视觉签名**（主色/主图元/首屏构图至少一项与其它页明显不同）。  
   **禁止**把首页布局原样复制到「生产概览 / 质量分析 / 其它业务页」。

2. **信息层级先于装饰**  
   首屏只突出 1 个主指标或 1 组主关系；次要数据降对比度或收入次级区。  
   禁止所有数字同字号、同亮度「平铺喊话」。

3. **构图要有呼吸**  
   明确主区 / 辅区 / 详情区；网格对齐但避免平均切四块。  
   卡片间距、圆角、描边统一成一套 token（CSS 变量），不要每卡一套临时色。

4. **图表是叙事不是贴图**  
   仪表盘/柱状/折线须服务本页问题（达成？对比？趋势？）。  
   同页两个半圆仪表若含义不同，刻度/文案/辅色须可区分；禁止复制粘贴两个一模一样的 gauge。

5. **深色工业风要克制**  
   可用深色底 + 少量高亮强调色；**禁止**堆满霓虹描边、紫色辉光、圆角胶囊标签墙、多层阴影（AI 默认丑感）。  
   强调色建议 ≤2 种；大面积用中性色阶。

6. **表格与图表分区**  
   明细表可以全宽，但须有清晰表头层级与行悬停；不要让表与图抢同一视觉焦点。

7. **沿用技术栈，不沿用烂布局**  
   可继续用 Vue / Element Plus / ECharts，但**样式必须自定义**到本页规格。  
   「与现有风格一致」≠「复制 Home.vue 改个标题」。

## 写码时的落地要求

- 新建页面：**独立路由 + 独立视图组件**；不要 `import Home` 或复用首页 SFC 当业务页。  
- 抽公共的只有：布局壳、侧栏、主题 token；**业务卡片构图按页设计**。  
- `requirement` / 实现摘要须写清：  
  - 本页视觉身份（与首页差异点）  
  - 首屏模块与层级  
  - 主色/强调色（可用 token 名）  
  - 图表类型与用途  
  - 验收：打开本页与首页并排，**布局不可雷同**

## 明确禁止（不合格）

- 照抄已有页面 DOM/布局骨架，只改文案与路由  
- 默认 Element `el-card` 白底 KPI 三件套交差  
- 双 gauge 完全同款同色同指针文案  
- 无信息层级的「卡片墙」  
- 为炫技加无关模块、假数据装饰块（用户没要的）  
- 截图复刻任务里擅自改成另一套通用模板

## 与截图复刻的关系

| 场景 | 优先级 |
|------|--------|
| 用户明文 **1:1 / 复刻 / 改成这种** | **截图规格最高**；本 Skill 保证还原质感，不偷换成模板 |
| 用户说 **重做 / 重新设计 / 设计感 / 不要照抄** | **本 Skill 最高**；旧截图与旧「按截图位置」五卡骨架只作字段参考，**禁止**再当布局合同 |
| 正文同时出现「按截图位置」+「重做/设计感」 | **重做优先**（「按截图位置」多半是旧 propose 残留） |
| 用户只要修滚动/溢出 | 不启用本 Skill 的「重设计」条款，只做布局壳修复 |

**重做时 requirement 禁止写**：`视觉布局（按截图位置）`、`五卡布局与截图一致`。应写「新构图」。

## 自检

- [ ] 本页与首页（或其它已有业务页）构图明显不同  
- [ ] 有主次层级，不是同权卡片墙  
- [ ] 图表类型服务业务语义，无复制粘贴仪表  
- [ ] 使用主题 token / 自定义样式，而非裸 el-card 模板  
- [ ] 未引入用户未要求的模块
