# 08 · 写码改功能（本机 Cursor / GitHub Cloud）

> **一句话**：你在聊天里把「要改什么」说清楚 → 点确认卡 → Cursor **真改**本机沙箱工程（默认）或白名单 GitHub 仓；改完你自己决定要不要提交、要不要部署。  
> **不是**：Deep Agents 直接写宿主机磁盘；也不是写码 Job 一成功就自动 `commit` / 自动发版（那些是功能 09、10，人再喊一声才动）。

---

## 1. 实现原理

### 1.1 我们到底实现了什么？

工厂 / 客户现场常有：「帮我加个页面」「把这个按钮改一下」。若让大模型一边聊一边直接改电脑上的仓，没法审计、没法回滚，也和「确认卡」产品形态矛盾。  
所以做了 **写码两段式**：先讨论出方案与围栏，人确认后再由 Cursor 执行落地。

| 人做的 | 系统干的 | 达到的效果 |
|--------|----------|------------|
| 说清需求（可带截图） | 讨论段 Deep Agents + Skill 澄清、出选项/方案围栏 | 聊清楚再动手 |
| 点「开始执行」等确认卡 | 执行段 Cursor SDK 在本机沙箱或 Cloud 仓真改 | 磁盘上有可看的 diff |
| 本机选工程目录 / Cloud 选仓 | 沙箱同步回工作区，或 Cloud 推到固定工作分支 | 改动落在你指定的地方 |
| 改完后另说「提交 / 部署」 | **不**自动 commit、**不**自动发版 | 人控节奏，避免改一行就上线 |

**技术落点（整包）：**

| 层次 | 路径 |
|------|------|
| 本机写码包 | `apps/local_dev/`（`service.py`、`cursor_local_agent.py`、`sandbox.py`、`fs_snapshot.py`） |
| Cloud 写码包 | `apps/cursor_dev/`（`service.py`、`jobs.py`） |
| HTTP | `apps/api/routes/local_dev.py`、`apps/api/routes/cursor_dev.py` |
| 意图 / 围栏 | `apps/web/src/chatIntent.js`、`chatCursorDevParse.js` |
| 确认卡 | `CursorDevOptionsCard`、`CodingPlanCard`、`CursorDevRepoPickCard`、`CursorDevMergeGuideCard`、`ScreenshotIntentCard` |
| Skills | `cursor-dev-chat`、`ui-product-design`；车道 `workbuddy_lane=code_dev` |

### 1.2 和「对话查数」「审码」「提交 / 部署」差在哪？

| | 普通对话 / 查数 | **写码（本篇）** | 提交（09）/ 部署（10） |
|--|-----------------|------------------|------------------------|
| 谁发起 | 你打字 | 你打字（写码意图） | 你另说「提交今天的代码」「部署到预发」 |
| 谁干活 | Deep Agents + Tools | **讨论**：Deep Agents；**执行**：Cursor SDK | **程序**调 git / SSH / Actions，模型不碰 |
| 会不会改磁盘 | 一般不改本机工程 | 确认后 **会**（沙箱→工作区或 Cloud 分支） | 提交改 git；部署改预发机 |
| 结果去哪 | 聊天气泡 | 本机 IDE diff / Cloud 工作分支 | commit 卡 / 部署卡过程日志 |

**技术上怎么隔开：**

| 点 | 实现 |
|----|------|
| 写码意图 | `looksLikeCodeDevIntent`；与部署、提交批、审码、贴码互斥 |
| 截图意图 | `looksLikeScreenshotUiRedesign` / `classifyScreenshotIntent` → 可出 `ScreenshotIntentCard` |
| 车道 | 前端显式 `page_context.workbuddy_lane=code_dev` |
| 禁审码工具 | `agent.py` code_dev 块禁止 `request_git_*` / `request_ide_*` |
| 不自动提交 | 默认 `LOCAL_DEV_COMMIT_GATE=0`；提交走功能 09 |
| 不自动部署 | 部署走功能 10 的 `looksLikeDeploy` + confirm |

### 1.3 为什么要「讨论段围栏 + 执行段 Job」？

**人话：**  
- 讨论段只出方案标记块 → 前端画成可点的卡，你还能改选项、选仓。  
- 执行段才调 Cursor → 磁盘改动只发生在你点确认之后，过程可取消、可看 SSE 步骤。

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 围栏解析 | `chatCursorDevParse.js` | 解析 `:::cursor_dev_options` / `:::cursor_dev_propose` 等 |
| 本机 Job | `POST /api/local-dev/jobs` + `streamLocalDevJob` SSE | `service.py` 后台线程；前端 SSE 看步骤 |
| Cloud Job | `POST /api/cursor-dev/jobs` | allowlist 仓 + `CURSOR_API_KEY`；**不**自动合 main |
| 沙箱 | `sandbox.prepare_sandbox` + `fs_snapshot` / `tools_fs` | 隔离目录改完再同步；记 `synced_files` 供 09 汇批 |

### 1.4 本机 vs Cloud，工作区从哪来？

| 模式 | 改哪里 | 典型配置 |
|------|--------|----------|
| **本机（默认）** | 设置里配的本机工程目录 | `LOCAL_DEV_ENABLED`、`LOCAL_DEV_AGENT=cursor_sdk` |
| **Cloud** | 白名单 GitHub 仓固定工作分支 | `CURSOR_DEV_ENABLED`、`CURSOR_API_KEY`、`CURSOR_DEV_REPO_ALLOWLIST` |

**工作区路径（重要）：** 本机工程目录走 **`GET/PUT /api/settings/local-workspace`** 用户偏好，**不是**环境变量 `LOCAL_DEV_WORKSPACE`。设置页保存后前端 `fetchLocalWorkspacePref` / `saveLocalWorkspacePref` 读写。

### 1.5 安全上钉死了什么？

| 约束 | 技术实现 |
|------|----------|
| 主环不写宿主机工程 | 执行只走 Cursor Job；Deep Agents 出围栏不直写 |
| Cloud 不能乱改任意仓 | `CURSOR_DEV_REPO_ALLOWLIST` |
| 沙箱降低误删整盘风险 | `sandbox.py` 隔离 + 同步失败 job 标 failed |
| LLM 应急回退默认关 | `LOCAL_DEV_AGENT=llm` 且须 `LOCAL_DEV_ALLOW_LLM_FALLBACK=1` |
| 写码成功不自动 push main / 生产部署 | `LOCAL_DEV_COMMIT_GATE` 默认关；部署另篇 |
| UI 不照抄 WorkBuddy 首页 | `ui-product-design` Skill |

## 2. 实现流程（人话 + 技术点怎么落地）

> 每节先讲「人看到什么 / 为什么这样」，再给 **技术点表** 和调用链。

### 2.1 人怎么走进写码？

**人话：** 你说「帮我加个登录页」或贴截图说「做成这样」→ 发送前意图识别成写码（或截图澄清卡）→ 对话带 `lane=code_dev` → 模型澄清需求，必要时出选项卡 / 方案卡 / 选仓卡。确认前工作区应仍干净。

```text
ChatView.vue send()
  → looksLikeDeploy / looksLikeLocalCommitBatch 先互斥掉
  → looksLikeCodeDevIntent(text, files)
       或 looksLikeScreenshotUiRedesign / classifyScreenshotIntent
         → ScreenshotIntentCard（意图不清时）
  → POST /api/chat/stream  + page_context.workbuddy_lane=code_dev
  → Skills：cursor-dev-chat（+ ui-product-design 若界面类）
  → 模型输出 :::cursor_dev_* 围栏
  → chatCursorDevParse.js
       → CursorDevOptionsCard / CodingPlanCard
       → CursorDevRepoPickCard（本机目录 / GitHub 仓）
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 意图入口 | `chatIntent.js`：`looksLikeCodeDevIntent`；截图 `looksLikeScreenshotUiRedesign` / `buildScreenshotIntentClarifyCard` |
| 围栏 | `:::cursor_dev_options`、`:::cursor_dev_propose` 等，由 `chatCursorDevParse.js` 解析 |
| 禁审码工具 | code_dev 车道系统提示禁止 `request_git_*` |
| 此阶段 | 无 Job 时 `git status` 应仍干净 |

---

### 2.2 本机执行：确认后 Cursor 怎么改盘？

**人话：** 点「开始执行」→ 后端起本机 Job → 默认走 Cursor Local SDK，在沙箱里改，再同步回你选的工作区 → 聊天里 SSE 看步骤，可取消。成功后本机 IDE 能看到 diff；`synced_files` 记下来给以后「提交今天的代码」用。

```text
用户点确认
  → POST /api/local-dev/jobs（routes/local_dev.py）
       body: workspace, prompt, session_id, …
  → service.py 后台线程：
       LOCAL_DEV_AGENT=cursor_sdk（默认）
         → cursor_local_agent.py 调 Cursor Local SDK
       LOCAL_DEV_AGENT=llm 且 LOCAL_DEV_ALLOW_LLM_FALLBACK=1
         → 应急 LLM 工具环（非默认）
  → sandbox.prepare_sandbox()
       → 隔离目录内改文件
       → fs_snapshot / tools_fs 同步回用户 workspace
       → 记录 synced_files 到 job JSON
  → ChatView：streamLocalDevJob(jobId) SSE
       → 步骤日志；可 cancelLocalDevJob
       status=succeeded → 本机可见 diff
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 开关 | `LOCAL_DEV_ENABLED` | 关则拒建 Job |
| 工作区 | `/api/settings/local-workspace` | 用户偏好路径；建 Job 时做路径校验 |
| Agent | `LOCAL_DEV_AGENT` 默认 `cursor_sdk` | llm 回退须显式允许 |
| 沙箱 | `sandbox.py`、`fs_snapshot.py` | 同步失败 → job failed |
| 前端流 | `api.streamLocalDevJob` | SSE，不是只靠轮询 |

---

### 2.3 Cloud 执行：白名单仓怎么改？

**人话：** 选白名单里的 GitHub 仓 → 确认 → Cloud Agent 在固定工作分支上改并推送；前端看 Cloud Job。**不会**自动合进 main——合 main 靠人，卡上可有合并引导（`CursorDevMergeGuideCard`）。

```text
POST /api/cursor-dev/jobs（routes/cursor_dev.py）
  → 仓须在 CURSOR_DEV_REPO_ALLOWLIST
  → cursor_dev/service.py → Cursor Cloud Agent API
  → 固定工作分支（如 hebo）commit/push
  → 前端 streamCursorDevJob / 轮询；不自动合 main
  → 需要时 CursorDevMergeGuideCard 提示人工合 main
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| Key | `CURSOR_API_KEY`（只服务端） |
| 开关 | `CURSOR_DEV_ENABLED` |
| 白名单 | `CURSOR_DEV_REPO_ALLOWLIST` 防任意仓 |

---

### 2.4 和提交 / 部署怎么衔接（刻意不自动）？

**人话：** 写码成功只表示「文件改好了」。要进远程分支说「提交今天的代码」（功能 09）；要上预发说「部署到预发」（功能 10）。两步都是人触发、另开确认卡。

```text
写码 Job succeeded（synced_files 已记）
  → 不自动 commit（LOCAL_DEV_COMMIT_GATE 默认 0）
  → 用户：「提交今天的代码」→ 功能 09
  → push 成功后
  → 用户：「部署到预发」→ 功能 10
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 写码收尾 | `service.py` 仅在 `commit_gate_enabled` 时才可能弹提交；默认关 |
| 提交入口 | `looksLikeLocalCommitBatch` → commit-batch API |
| 部署入口 | `looksLikeDeploy` → deploy/prepare |

---

### 2.5 页面 / API 对照

| 你在界面上做的 | 前端 | 后端 | 核心 |
|----------------|------|------|------|
| 写码对话 | `ChatView` + lane | `POST /api/chat/stream` | Deep Agents + Skills |
| 本机工作区偏好 | `fetch/saveLocalWorkspacePref` | `GET/PUT /api/settings/local-workspace` | 用户偏好，非 env |
| 起本机 Job | `createLocalDevJob` | `POST /api/local-dev/jobs` | `service.py` |
| 看本机过程 | `streamLocalDevJob` | Job SSE | 步骤 / cancel |
| 起 Cloud Job | `createCursorDevJob` | `POST /api/cursor-dev/jobs` | `cursor_dev/service.py` |

均需登录；OpenAPI 中文 summary（本机写码 / Cursor 云端等 tags）。

---

### 2.6 从头到尾一眼版

```text
【意图】looksLikeCodeDevIntent / 截图澄清卡
        ↓
【讨论】SSE + lane=code_dev + cursor-dev-chat 围栏
        ↓
【确认】Options / Plan / RepoPick 卡
        ↓
【执行】local-dev Job（沙箱+Cursor）或 cursor-dev Job（Cloud）
        ↓
【结果】本机 diff / Cloud 工作分支；synced_files 落盘
        ↓
【下一步】人触发 09 提交 → 人触发 10 部署（不自动）
```

---

### 2.7 出问题时先查哪？

| 现象 | 人话原因 | 技术上先看 |
|------|----------|------------|
| 无确认卡 | 模型没出围栏 / Skill 未加载 | 回复是否含 `:::cursor_dev_*`；`chatCursorDevParse` |
| Job 一直 running | Cursor Key、网络、仓权限 | `CURSOR_API_KEY`；本机 Cursor 是否可用 |
| 目录无变化 | 沙箱没同步 / 工作区路径不对 | job 日志；`/settings/local-workspace` 是否配对 |
| 弹出审码报告 | 走错车道 | `workbuddy_lane` 是否误为 `code_review` |
| LLM 回退误开 | 应急开关开了 | `LOCAL_DEV_ALLOW_LLM_FALLBACK` 应为 0 |
| 以为会自动提交 | 概念混了 | 提交走功能 09；`LOCAL_DEV_COMMIT_GATE` 默认 0 |

## 3. 技术及用法（速查）

| 模块 | 关键函数 / 组件 | 干什么 |
|------|-----------------|--------|
| `chatIntent.js` | `looksLikeCodeDevIntent`、截图相关 | 发送前分流 |
| `chatCursorDevParse.js` | 解析 `:::cursor_dev_*` | 围栏 → 卡数据 |
| 确认卡 | `CursorDevOptionsCard`、`CodingPlanCard`、`CursorDevRepoPickCard`、`CursorDevMergeGuideCard`、`ScreenshotIntentCard` | 人确认 / 选仓 / 合分支引导 |
| `local_dev/service.py`、`cursor_local_agent.py` | 本机 Job 编排 + Cursor SDK | 真改本机 |
| `sandbox.py`、`fs_snapshot.py`、`tools_fs.py` | 沙箱与同步 | 记 `synced_files` |
| `cursor_dev/service.py`、`jobs.py` | Cloud Job | 白名单仓改动 |
| Skills | `cursor-dev-chat`、`ui-product-design` | 讨论与 UI 约束 |
| 前端 API | `createLocalDevJob`、`streamLocalDevJob`、`createCursorDevJob` | Job 生命周期 |

**配置：**

| 变量 / 接口 | 含义 |
|-------------|------|
| `LOCAL_DEV_ENABLED` | 本机写码总开关 |
| `LOCAL_DEV_AGENT` | 默认 `cursor_sdk`；`llm` 须配合 `LOCAL_DEV_ALLOW_LLM_FALLBACK=1` |
| `LOCAL_DEV_COMMIT_GATE` | 写码结束是否自动走提交门禁（默认 **0**） |
| `/api/settings/local-workspace` | **本机工作区路径偏好**（不要靠 env `LOCAL_DEV_WORKSPACE`） |
| `CURSOR_DEV_ENABLED` / `CURSOR_API_KEY` / `CURSOR_DEV_*` | Cloud 写码 |

截图：对话上传图片 → 视觉相关提示辅助澄清（非必须）。操作与车道约定见写码相关手册；**实现以本篇为准**。

## 4. 后续可以怎么做、不要做什么

**可以做：**

1. 写码成功后更明显引导「下一步：提交 / 部署」（仍分别走人触发 API）  
2. P2 显式点名才开：评估 DeepSeek Harness **仅**替换本机写码执行器，不动主对话  
3. Cloud 合并引导卡文案按仓规范细化（仍人工合 main）  

**不要做：**

1. 把 Deep Agents 主环改成直接写宿主机工程目录  
2. 写码成功就自动 `push` main / 自动生产部署  
3. 扩大 Cloud 白名单到不可信第三方仓  

---

## 自测路径（验收）

1. 配置本机工作区（设置页 / `local-workspace`）→ 小需求 → 确认卡 → SSE 过程可停 → 目录出现改动。  
2. Cloud：白名单仓 + Key → 工作分支有 commit（依环境）；不自动合 main。  
3. 确认前工作区不应被改。  
4. 写码成功后**不**自动出现提交/部署完成——须另说「提交今天的代码」「部署到预发」。
