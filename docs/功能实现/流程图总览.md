## 1. 普通聊天：一句话怎么变成屏幕上的回答？

```mermaid
flowchart TD
  A[① 你打字或传文件] --> B[② 页面把话发出去<br/>一边收一边显示]
  B --> D[③ 后端接到这句聊天]
  D --> E[④ 看看大模型这会儿闲不闲<br/>忙着就先别插队]
  E --> F[⑤ 分清这轮是闲聊<br/>还是审码/写码/贴码]
  F --> G[⑥ 参谋班子开工<br/>准备边想边往回推字]
  G --> H[⑦ 先念一遍规矩：<br/>能干什么、不能瞎编]
  H --> I[⑧ 带上各种工具本领<br/>查数、摸底、探活…]

  M --> C[⑫ 页面弹出确认卡<br/>等你点头或取消]
  J -->|普通说话| C2[⑫ 气泡里一个字一个字冒出来]
  G --> C2
```

## 3. 导入 Excel：没点确认，库里一行都不会进

```mermaid
flowchart TD
  U[① 你上传表格，并说要导入某某] --> UP[② 文件先存到服务器临时区]
  UP --> SSE[③ 聊天里参谋说：我想帮你导入]
  SSE --> TC[④ 参谋伸手去「写入」]
  TC --> MW[⑤ 保安一把拦住：不行，先填确认单]
  MW --> PV[⑥ 先抽出几行样例给你瞄一眼]
  PV --> PD[⑦ 开一张待确认的导入单存着]
  PD --> CARD[⑧ 页面弹出确认卡：<br/>导到哪、大约多少行、长啥样]

  CARD -->|你点取消| CAN[⑨a 撕掉单据，库纹丝不动]
  CARD -->|你点确认| CF[⑨b 后台认领这张单]
  CF --> EXEC[⑩ 后台自己执行导入<br/>这回是真写入 MES]
  EXEC --> AUD[⑪ 记一笔账：谁、何时、导了什么]
```

### 节点说明（§3）

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| ①～② | 你交表，系统先收着 | `POST /api/upload` |
| ③～④ | AI 只能「申请导入」 | Skill + `import_file_to_platform` |
| ⑤～⑦ | 申请变确认单，还没入库 | `WriteConfirmMiddleware` / pending |
| ⑧ | 你签字的地方 | `WriteConfirmCard` |
| ⑨a | 不签字就作废 | cancel |

## 4. 摸底 vs 看接口健不健康（别当成一回事）

```mermaid
flowchart TD
  subgraph 摸底_问系统能管啥
    S1[① 设置页上传厂里的表结构说明] --> S2[② 你问：MES 到底能干什么?]
    S2 --> S3[③ 按摸底剧本翻文档]
    S3 --> S4[④ 整理成：有哪些能力、场景串哪些表]
    S4 --> S5[⑤ 只根据文档回答<br/>不去查今天真实有多少单]
  end

  subgraph 探活_问接口通不通
    A1[① 你给接口说明书，或上传网关日志] --> A2{② 你想干哪档事?}
    A2 -->|对着文档挨个试打| A3[③A 先列出有哪些接口]
    A3 --> A4[④A 往「沙箱假伺服」上试着敲门<br/>默认不打真生产]
    A4 --> A5[⑤A 排出问题接口，写出中文体检报告]
    A2 -->|对着日志找错| A6[③B 读你上传的日志]
    A6 --> A7[④B 按地址、错误码归拢]
    A7 --> A8[⑤B 报告写明「这是日志里的问题」<br/>别跟沙箱体检数字混在一起说]
  end
```

### 节点说明（§4）

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| 摸底①～⑤ | 读说明书，讲「能管啥」，**不当今日产量** | `analyze-mes-schema` 等 |
| 探活 A | 对着文档，在沙箱里「敲敲门看谁应」 | `build_api_catalog` / `probe_api_catalog` |
| 探活 B | 对着旧日志找常挂的接口 | `import_external_api_logs` 等 |
| 别混 | 沙箱不通 ≠ 生产挂了；日志错误率 ≠ 沙箱失败数 | Skill 硬约束 |

## 5. 贴码 / 审仓 / 改功能：三条道别走串

```mermaid
flowchart TD
  MSG[① 你发来一句话] --> Q1{② 是贴了一段代码<br/>想问问有啥毛病?}
  Q1 -->|是| L6[③ 走「评这段码」]
  L6 --> P6[④ 只盯着你贴的那几行评<br/>不拉仓库、不改你电脑文件]

  Q1 -->|否| Q2{⑤ 是要审整个仓库或本机工程?}
  Q2 -->|是| L7[⑥ 走「审代码」]
  L7 --> PICK[⑦ 你选：审网上的公开仓<br/>还是审本机 VS Code 打开的工程]
  PICK --> BAT[⑧ 像翻书一样一章章只读代码]
  BAT --> REP[⑨ 给你一份中文报告：<br/>严重/一般/建议 分等级]

  Q2 -->|否| Q3{⑩ 是要加功能或改页面?}
  Q3 -->|是| L8[⑪ 走「改代码」]
  L8 --> DIS[⑫ 先跟你把需求聊清楚<br/>再弹出确认卡]
  DIS --> JOB{⑬ 你点了「开干」没有?}
  JOB -->|改本机工程| LOC[⑭ 让 Cursor 在隔离沙箱里改<br/>改完再同步回你的工程目录]
  JOB -->|改云端白名单仓| CLD[⑮ 在允许的 GitHub 仓里<br/>往工作分支改，不合主分支]
  LOC --> DONE[⑯ 记下这次动过哪些文件<br/>但不会自动帮你 git 提交]
  CLD --> DONE
```

### 节点说明（§5）

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| ②～④ | 贴码点评：当面批作业，不动档案柜 | `paste_code` |
| ⑤～⑨ | 审代码：只读开卷考试，出报告 | `code_review` + git/ide 工具 |

| ⑯ | 改完先记「本批文件」；要入库再说「提交今天的代码」 | `synced_files` → 功能 09 |

## 6. 提交入库：先凑名单，再安检，你点头才 commit

```mermaid
flowchart TD
  U[① 你说：提交今天的代码] --> I[② 系统认出：这是要入库<br/>不是要发版]
  I --> P1[③ 第一步：先数数有哪些文件要交<br/>这一步还不安检]
  P1 --> COL[④ 凑「本批」：今天同步过的 ∩ 现在 git 里脏的]
  COL --> P2[⑤ 第二步：开始安检]
  P2 --> GATE[⑥ 按规矩扫一遍<br/>有没有硬伤拦着不让交]
  GATE --> CARD[⑦ 弹出确认卡：文件清单 + 中文说明草稿]

  CARD -->|你取消| X[⑧a 什么都不提交]
  CARD -->|你确认| CF[⑧b 你点头了]
  CF --> MSG[⑨ 检查提交说明：得有中文、别太离谱]
  MSG --> GIT[⑩ 在工作分支上真正 git 提交<br/>是程序敲命令，不是 AI 敲]
  GIT --> PUSH{⑪ 要不要顺便推到远程?}
  PUSH -->|要| PH[⑫ 往远程工作分支推一把]
  PH -->|推失败| RT[⑬ 本地提交还在<br/>你可以稍后只重试「推送」]
  PH -->|推成功| OK[⑭ 搞定]
  PUSH -->|先不推| OK
```

### 节点说明（§6）

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| ③ | **只点名**，像先列清单 | `.../commit-batch/prepare` |
| ⑤～⑥ | **才安检**，别以为 ③ 完事了就过关 | `.../commit-batch` + `run_commit_review_gate` |
| ⑦ | 给你签字 | 提交确认卡 |
| ⑩ | 真入库到工作分支 | `git_commit` |
| ⑫～⑬ | 推远程失败也不撤本地提交 | `push_retry` |

## 7. 部署到预发：先体检开单，你点头才真发

```mermaid
flowchart TD
  U[① 你说：部署到预发] --> I[② 系统认出：这是要发版]
  I --> PRE[③ 先做体检：开关开了没、钥匙配了没<br/>这步绝不真发]
  PRE --> CHK[④ 列出检查项给你看：过没过]
  CHK --> CARD[⑤ 弹出部署确认卡]

  CARD -->|你取消| X[⑥a 不发，现场不动]
  CARD -->|你确认| CF[⑥b 再检一遍，并防止你连点两次]
  CF --> PROV{⑦ 咱们怎么发?}

  PROV -->|本机拿钥匙发| SSH[⑧ 后台开工：给这轮发版起个号]
  SSH --> WT[⑨ 临时检出「已经提交好的那个版本」<br/>不是你电脑上没保存的半成品]
  WT --> BD[⑩ 按规定步骤打包前端/后端]
  BD --> RS[⑪ 把包同步拷到预发服务器目录]
  RS --> RST[⑫ 需要的话：远程喊一声「服务重启」]
  RST --> HL[⑬ 用浏览器那种方式敲一下预发地址<br/>看页面还活着不]
  HL --> MEM[⑭ 把进度记在小本本上<br/>好随时来问「发到哪了」]

  PROV -->|走 GitHub 流水线| GH[⑧b 按一下云端流水线的「开始」按钮]
  GH --> RID[⑨b 拿到这趟流水线的单号<br/>好跟踪跑没跑完]

  MEM --> POL[⑮ 确认卡隔几秒问一声：发到哪了?]
  RID --> POL
  POL --> END{⑯ 成了还是黄了?}
  END -->|成了| VIS[⑰ 把预发网址亮给你]
  END -->|黄了| LOG[⑰b 把失败日志亮给你]
  END -->|已经有结果| STOP[⑱ 别再一遍遍问了，停]
```

### 节点说明（§7）——对应你截图里那几格

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| ③～④ | 开单体检，**不发货** | `prepare_deploy` |
| ⑤～⑥b | 你签字；防手抖连点 | 确认卡 / `confirm_deploy` |
| ⑦ | 本机钥匙发，或云端流水线发 | `DEPLOY_CI_PROVIDER` |
| ⑧～⑪ | 取出已提交版本→打包→拷到预发机 | `deploy_local_ssh` |
| ⑫ | 可选：让预发机上的服务重启一下 | `DEPLOY_SSH_RESTART_CMD` |
| ⑬ | 敲一下预发网址，看还回不回得来 | `probe_deploy_health`（探活） |
| ⑭ | 进度记在内存小本本，刷新状态用 | 内存 `_JOBS` |
| ⑧b | 不是本机拷文件，而是去 GitHub 点「跑流水线」 | `workflow_dispatch` |
| ⑨b | 拿到流水线单号，好查跑到哪 | `run_id` |
| ⑮ | 确认卡像小孩问「好了没」——隔几秒问进度 | `POST /deploy/poll` |
| ⑰～⑱ | 成功给链接；完事就别无限问 | 停轮询 |

## 8. 自动化任务：设好闹钟，到点自己干活（但不许自动发版）

```mermaid
flowchart TD
  UI[① 你在侧栏设好：几点、干什么、推不推群] --> ST[② 记到本子上<br/>并算出「下次该几点响」]
  BOOT[③ 后端服务开着] --> SCH[④ 闹钟程序挂上]
  SCH --> TICK[⑤ 大约半分钟瞄一眼：有没有到点的]
  ST --> TICK
  TICK --> DUE{⑥ 有到期且没暂停的任务吗?}
  DUE -->|没有| TICK
  DUE -->|有| EX[⑦ 开始跑这一轮]
  UI -->|你点「立即执行」| EX

  EX --> MU[⑧ 插个「正在跑」牌子<br/>同一任务别叠着跑两遍]
  MU --> LK{⑨ 这会儿有人正在跟 AI 聊天吗?}
  LK -->|有人在聊| SKIP[⑩ 先让路：这轮跳过<br/>过会儿闹钟再叫，绝不掐你的对话]
  SKIP --> TICK
  LK -->|没人占着| AG[⑪ 单独开一间小屋子<br/>按你写的指令让 AI 去查/搜/整理]
  AG --> RUN[⑫ 把结果写进「运行记录」]
  RUN --> DEL[⑬ 需要的话：发企微群 和/或 写入飞书表格]
  DEL --> NEXT[⑭ 算好下次几点再跑<br/>若是「只跑一次」就停掉]
```

### 节点说明（§8）

| 节点 | 大白话 | 对应代码（可选看） |
|------|--------|-------------------|
| ①～② | 你设闹钟 | 自动化任务页 / `automations.json` |
| ⑤～⑥ | 闹钟到点 | `scheduler` / `should_run_now` |
| ⑨～⑩ | **人聊优先**，任务让路 | `stream_lock`，`wait_sec=0` |
| ⑪ | 独立会话跑指令 | `execute_automation` |
| ⑬ | 推群、写表；**不会**自动提交/部署 | 企微 / 飞书投递 |

对应：[11-自动化任务](./11-自动化任务.md)
