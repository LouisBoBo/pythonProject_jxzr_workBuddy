# 11 · 自动化任务（定时调度 + Agent 执行）

> **一句话**：你在「自动化任务」页配好「做什么、几点做」→ 到点由后台叫醒大模型按指令干活（查数、搜新闻、整理）→ 结果进运行记录，需要的话再推企微或写入飞书表。  
> **不是**：AI 自己决定改代码、自动提交、自动发版（那些仍是功能 08～10，人点确认卡才动）。  
> **看图**：[流程图总览 §8](./流程图总览.md#8-功能-11自动化任务闹钟--发版)

---

## 1. 实现原理

### 1.1 我们到底实现了什么？

工厂里常有这类需求：每天早报进企微、昨日生产写入飞书表、周五整理周报。若每次靠人打开对话框说一遍，容易忘、也没法准时。  
所以做了 **自动化任务**：人只配一次，**闹钟到了系统自己跑**。

| 人配的 | 系统干的 | 达到的效果 |
|--------|----------|------------|
| 任务名称 + 执行指令 | 到点唤醒 Deep Agents 按指令查/搜/写摘要 | 不用每天手动开口 |
| 每天/每周几点 | 调度器约每 30 秒看一眼谁到期 | 准点触发（用户正在对话时会让一让） |
| 是否推企微 | 跑完调企微群机器人 | 群里直接看到结果 |
| 是否写飞书表 | 跑完解析表格 JSON，往多维表格追加行 | 领导打开飞书就能看数 |
| 「立即执行」 | 不等闹钟，马上跑一轮 | 配完立刻能验收 |

**技术落点（整包）：**

| 层次 | 路径 |
|------|------|
| 业务包 | `apps/automations/` |
| HTTP | `apps/api/routes/automations.py`（前缀 `/api/automations`） |
| 启动挂载 | `apps/api/main.py` → `schedule_automation_scheduler(DATA_DIR)` |
| 前端页 | `AutomationsView.vue`、`AutomationEditDialog.vue`、`AutomationRunDetail.vue` |
| 落盘 | `data/automations/{automations,runs,runtime}.json` |

### 1.2 和「聊天」「部署」差在哪？

很多人一听「自动化」就想到部署。这里要掰开：

| | 对话里随口问 | **自动化任务（本篇）** | 自动化部署（功能 10） |
|--|--------------|------------------------|----------------------|
| 谁发起 | 你打字 | **时钟**或「立即执行」 | 你说「部署到预发」 |
| 谁干活 | 大模型 + 工具 | 还是大模型 + 工具 | **程序** SSH/rsync，模型不碰 |
| 会不会改代码/发版 | 可能走到确认卡 | **明确禁止** | 人确认后真发版 |
| 结果去哪 | 聊天气泡 | **运行记录** + 可选企微/飞书 | 部署确认卡过程日志 |

设置页也是两套：企微/飞书给「任务」用；`DEPLOY_*` 给「发版」用。

**技术上怎么隔开：**

| 点 | 实现 |
|----|------|
| 不进对话意图旁路 | 自动化**没有** `chatIntent.js` 关键词；入口是侧栏页 + REST，不是 ChatView 发送前拦截 |
| 不进写码/审码车道 | `page_context.automation_run=true` → `apps/api/agent_lane_message.py` 跳过 `workbuddy_lane` 强制注入 |
| 执行前缀禁高风险 | `executor.execute_automation` 拼安全前缀，明示禁止写码/提交/部署 |
| 配置分组 | `settings_store`：`WECOM_*` / `FEISHU_*` 与 `DEPLOY_*` 分属不同设置分组 |

### 1.3 为什么要单独会话、还要和对话抢一把锁？

**人话：**  
- 单独会话 → 自动化不搅你正在看的聊天，也不「接着你上一句瞎答」。  
- 共用一把锁 → 你正在流式聊天时，到期任务**本轮先跳过**，绝不掐断对话去插队。人聊优先；任务晚几十秒可以接受。

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 独立会话号 | `executor.execute_automation` | `thread_id = f"automation-{id}-{run_id}"`，与用户 thread 隔离 LangGraph checkpoint |
| 上下文标记 | `set_request_agent_context(...)` | `user_id/username="automation"`，`page_context` 带 `automation_run`、`source=scheduler` |
| 对话锁 | `try_acquire_stream_lock(lock, wait_sec=0.0)`（`stream_concurrency.py`） | 与用户 SSE **同一把锁**；自动化 **不等待**（`wait_sec=0`），拿不到就 `skipped=stream_busy` |
| 同任务互斥 | `runtime.mark_running` / `clear_running` | 写 `runtime.json`，同一 `automation_id` 不能并行两跑 |

### 1.4 跑完之后两条「投递」，互不拖累

```text
大模型跑成功（executor 内）
  ├─ deliver_automation_run(...)           → 企微
  └─ sync_automation_run_to_bitable(...)   → 飞书
```

企微挂了，飞书照写；飞书写砸了，企微该发还发。状态分别写在 `runs.json` 的 `delivery_*` / `bitable_*`。

### 1.5 安全上钉死了什么？

| 约束 | 技术实现 |
|------|----------|
| 不进写码/审码/贴码车道 | `automation_run` + `agent_lane_message` |
| 禁止任务里「自动提交/部署」 | 执行前缀 + 改写 API 的系统提示同样禁止 |
| `cwds` 不越界 | `store._sanitize_cwds`：`resolve` + 相对仓库根校验 |
| 外发 HTTP 安全 | 企微/飞书均走 `safe_http` / URL 校验 |
| 密钥不进 prompt | `settings_store.resolve_setting`；webhook / APP_SECRET 只在投递模块读 |
| 可整关 / 可单停 | `AUTOMATIONS_SCHEDULER_ENABLED`；任务 `status=paused` |

## 2. 实现流程（人话 + 技术点怎么落地）

> 每节先讲「人看到什么 / 为什么这样」，再给 **技术点表** 和调用链。

### 2.1 人怎么配一条任务？

**人话：** 侧栏打开「自动化任务」→ 用模板或自定义 → 填名称、指令、几点跑、要不要企微/飞书 → 自定义可点「AI 改写」把草稿扩成带【目标】【步骤】【输出】【禁止】的完整指令（不改你本意，也不替你改几点跑）。配完列表里能看到「下次执行时间」；「立即执行」不用等到明天。

```text
AutomationsView.vue
  ├─ 模板 → automationTemplates.js（三套预设）
  ├─ 新建/编辑 → AutomationEditDialog.vue
  │     ├─ 日程 → automationSchedulePresets.js → rrule / scheduled_at
  │     └─ AI 改写 → api.rewriteAutomationPrompt
  │           → POST /api/automations/rewrite-prompt
  │           → prompt_rewrite.rewrite_automation_prompt
  └─ 保存 → createAutomation / updateAutomation
        → store.create_automation / update_automation
        → schedule.enrich_automation_schedule（写入 next_run_at）
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 模板 | `automationTemplates.js`：`daily-ai-news`、`weekly-work-report`、`mes-daily-production-report` |
| 持久化 | `store.create_automation` / `update_automation`；原子写 `_write_json_atomic`（`.tmp` + `replace`） |
| 算下次时间 | `schedule.compute_next_run_at` + `enrich_automation_schedule`（DAILY/WEEKLY RRULE 或 once） |
| AI 改写 | `rewrite_automation_prompt(draft, task_name=)`：走现有 `LLM_*` 客户端；系统提示强制骨架，禁止写调度/企微/飞书/写码部署 |
| 前端何时显示改写 | `AutomationEditDialog`：`_source !== 'template'` 才显示「AI 改写」按钮 |

### 2.2 闹钟是谁在敲？

**人话：** API 一启动，后台约每 30 秒扫一遍任务；谁启用且「下次执行时间」已到，就跑一轮。若用户正在对话，本轮跳过、下个周期再试。单次任务跑完自动暂停。

```text
main.py 启动
  → schedule_automation_scheduler(DATA_DIR)          # scheduler.py
    → scheduler_enabled() 读 AUTOMATIONS_SCHEDULER_ENABLED
    → asyncio.create_task(_loop)
         先 sleep 2s，再每 _tick_seconds()（默认 30，环境变量 AUTOMATIONS_TICK_SEC）
         → _tick_once：
              store.list_automations
              缺 next_run_at 则 enrich 补齐
              schedule.should_run_now(item) 为真
                → await execute_automation(...)
              若返回 skipped=stream_busy → 不推进日程，下 tick 再试
```

**技术点：**

| 点 | 函数 | 怎么做的 |
|----|------|----------|
| 是否到期 | `should_run_now` | `active` + `next_run_at<=now` + `last_run_at` 未盖住本轮 + `valid_from/until` 窗口 |
| 下次时间 | `compute_next_run_at` | 解析 RRULE（`_parse_rrule` / `_daily_next` / `_weekly_next`）或 once 的 `scheduled_at` |
| 单次任务 | `execute_automation` 收尾 | `status=paused`，`next_run_at=null` |
| 关调度 | `scheduler_enabled` | `AUTOMATIONS_SCHEDULER_ENABLED=0` 则不建 `_loop` |

---

### 2.3 到点之后，大模型怎么被叫醒？

**人话：** 先占坑（同任务不并行）→ 写一条「进行中」运行记录 → 抢对话锁 → 拼安全前缀和任务指令 → 非流式跑完 Deep Agents → 写摘要 → 成功再投递 → 算下次时间。运行记录里能看到成败、摘要、企微/飞书状态。

```text
POST /api/automations/{id}/run     # run_automation_now_api
  或  _tick_once 到期
       ↓
execute_automation(data_dir, automation)          # executor.py
  ├─ runtime.mark_running(...)
  ├─ store.append_run(status=running, thread_id=…)
  ├─ AgentRunner() + try_acquire_stream_lock(wait_sec=0)
  │     失败 → update_run(failed/说明忙)；clear_running；return skipped
  ├─ set_request_agent_context(automation_run=true, …)
  ├─ 拼前缀：
  │     安全禁令
  │     + 周报？ → _weekly_report_prefix → repo_digest.build_weekly_repo_digest
  │     + 生产日报？ → _daily_production_report_prefix
  │     + 开了飞书？ → 注入 BITABLE_JSON 输出说明
  │     + cwds 说明
  ├─ await runner.chat(prefix + prompt, thread_id=…)   # 非 SSE
  ├─ finally：reset context；lock.release；clear_running
  ├─ store.update_run(succeeded|failed,
  │     summary=truncate_summary_keep_bitable(...))     # 落盘截断，保留围栏
  ├─ 成功：
  │     deliver_automation_run(...)
  │     sync_automation_run_to_bitable(...)             # 互不影响
  └─ 更新 last_run_at + next_run_at（once 则 pause）
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 总编排 | `execute_automation` | 上表整条链 |
| 周报材料 | `build_weekly_repo_digest` | **只读** git log/stat，不 commit |
| 生产日报日期 | `_daily_production_report_prefix` | 写死「昨日」ISO，禁模型臆造日期 |
| 摘要落盘 | `truncate_summary_keep_bitable`（`bitable_writer.py`） | 上限约 16KB，优先保住 `bitable_json` 围栏 |
| Agent 主环 | `AgentRunner.chat` → Deep Agents | 与对话同一套 Tools/Skills；靠车道与前缀限制危险旁路 |

---

### 2.4 企微消息怎么出去的？

**人话：** 任务勾了推送 + 系统配置打开企微 + 填了群机器人 webhook，跑成功后群里直接出现整理好的早报/日报。可开「干跑」只记日志不真发。

```text
deliver_automation_run(automation, run, summary)   # delivery.py
  → automation_push_enabled（任务 push_to_wecom）
  → wecom_bot.push_enabled / webhook_key
  → run_summary_text.format_wecom_push(summary, name, …)
       （新闻/生产日报等会拆段落、控字节）
  → wecom_bot.send_push_with_retry → qyapi webhook（safe_http）
  → push_dry_run 时不 HTTP，只打日志
  → store.update_run(delivery_status=sent|failed|skipped, …)
```

**技术点：**

| 点 | 函数 | 怎么做的 |
|----|------|----------|
| 开关 | `push_enabled` / `automation_push_enabled` | 全局 `WECOM_PUSH_ENABLED` × 任务字段 |
| Key 规范化 | `normalize_webhook_key` / `build_webhook_url` | 支持只填 key 或完整 URL |
| 文案 | `format_wecom_push` / `parse_run_summary` | 从 Agent 摘要抽出可推送结构 |
| 重试 | `send_push_with_retry` | 短暂失败重试，避免偶发网络抖 |

---

### 2.5 飞书多维表格怎么写上的？

**人话：** 大模型按指令查数，在回复里带约定好的表格 JSON；程序抠出 JSON，必要时按工单号补工序/完工时间，再往飞书表追加行。以前摘要截太短会把 JSON 砍断导致写表失败——已改为 **用完整回复做 sync，落盘再截断**。

```text
sync_automation_run_to_bitable(...)          # bitable_sync.py
  → get_bitable_config / sanitize_bitable_sync（任务 bitable_sync）
  → feishu_bitable.bitable_enabled + app_id/secret
  → bitable_writer.extract_bitable_payload(完整 summary)
  → enrich_work_order_rows（可选：fetch_work_order_lookup 按工单号回填）
  → map_rows_to_records / remap_records_to_table_fields
  → feishu_bitable.get_tenant_access_token
  → batch_create_records（P0 仅 append；upsert 未做）
  → dry_run 则跳过真写
  → update_run(bitable_status / bitable_record_ids / bitable_error)
```

**技术点：**

| 点 | 函数 | 怎么做的 |
|----|------|----------|
| 解析围栏 | `extract_bitable_payload` / `_recover_rows_array` | 支持 fence 与 `【BITABLE_JSON】`；损坏时尽力恢复 rows |
| 列名对齐 | `resolve_column_name` / `remap_records_to_table_fields` | 中英别名映射到表头真实列名 |
| 工单回填 | `enrich_work_order_rows` | 防 Agent 漏写工序/完工时间 |
| Token | `get_tenant_access_token` / `normalize_app_token` | 应用身份换 tenant token；兼容 wiki node |
| HTTP | `_http_json` + `safe_http` 断言 | 禁止乱打非飞书域名 |

### 2.7 从头到尾一眼版（业务 + 代码）

```text
【页面】建任务 → store + next_run_at
        ↓
【调度】scheduler._tick_once / 或 POST …/run
        ↓
【执行】runtime 互斥 + stream_lock
        ↓
【Agent】AgentRunner.chat（独立 thread_id，Deep Agents + 现有 Tools）
        ↓
【落盘】runs.json（summary 截断保 bitable 围栏）
        ↓
【投递】delivery（企微）‖ bitable_sync（飞书）
        ↓
【日程】推进 next_run_at 或 once→paused
```

### 2.8 出问题时先查哪？

| 现象 | 人话原因 | 技术上先看 |
|------|----------|------------|
| 到点没动静 | 暂停了 / 时间不对 / API 没开 / 当时在对话 | `status`、`next_run_at`、`AUTOMATIONS_SCHEDULER_ENABLED`、日志里 `stream_busy` |
| 立即执行一直忙 | 同任务还在跑或对话占锁 | `runtime.json`；用户 SSE 是否进行中 |
| 企微没消息 | 开关/key/干跑 | 任务 `push_to_wecom`；`WECOM_*`；`delivery_status` |
| 飞书写表空/失败 | 凭证、JSON 围栏、表 id | `bitable_status`/`bitable_error`；summary 是否含完整 payload |
| 以为会自动发版 | 概念混了 | 发版走功能 10：`looksLikeDeploy` + confirm 卡 |

| 模块 | 关键函数 | 干什么 |

操作手册见 [`../自动化任务/`](../自动化任务/README.md)；**实现以本篇为准**。

## 4. 后续可以怎么做、不要做什么

**可以做：**

1. 飞书按工单号 upsert（先扩 `bitable_sync` / `batch_create_records` 旁的更新 API）  
2. 运行记录按任务筛选、失败重试按钮（仍走 `execute_automation`，不抢用户 SSE）  
3. 更多 RRULE（每月）——先扩 `schedule._parse_rrule` / `compute_next_run_at`，再放开 `automationSchedulePresets.js`  

**不要做：**

1. 自动化任务里自动写码 / commit / 部署  
2. 为「必须准点」掐断用户 SSE（不要把 `wait_sec=0` 改成死等占锁）  
3. 另起一套 Agent 框架只为了跑定时任务

## 自测路径（验收）

1. 建任务 → **立即执行** → `GET /runs` / 页面运行记录有摘要。  
2. 开企微/飞书 → 对一下 `delivery_status` / `bitable_status` 与群、表。  
3. 对话流式进行中再点立即执行 → 应 busy/skip，**对话不断**。  
4. 暂停任务 → 到点不跑；恢复后 `next_run_at` 推进。
