# 表结构 → 业务能力分析（方案 A）

依据本地文档 `docs/中软MES数据库表结构.md`，为实施摸底提供只读分析能力。

---

## 大白话：这是在干什么

这不是「查现在系统里有多少工单」，而是：**翻中软给的那本「表说明书」，推断这个 MES 大概能管哪些业务**。

像看楼盘户型图猜房子功能，不是进房数家具。

| | 表结构 → 平台业务能力 | 查工单 / 排产 / 导入导出 |
|--|--|--|
| 是什么 | 平台能力摸底（字典） | 助手**模拟演示** |
| 数据从哪来 | 本地 Markdown 说明书 | 演示用 ERP/实体目录 |
| 会不会改平台 | 不会 | 不改变「平台能力」定义；导入仍走确认 |

**人话能力地图只谈左列。** 右列不要写进「平台能干什么」的结论。

---

## 什么时候用 / 不用

**该用**

- **人话能力地图**：平台（表结构）能管哪些业务，**不含**模拟查/导
- 摸底：这套 MES 大概有哪些模块
- 对能力：品质 / 仓储 / 设备各自管什么
- **按业务场景串表**：工单下达到入库、采购收料、品质检验等
- **导出摸底报告**（Markdown/Excel）发给客户/中软对齐
- 搞清某张表：`TBL_MO` 是什么、有哪些字段、和谁关联
- 术语：工单 vs 排产、IPQC / OQC 等

**不该用**

- 「查一下今天的工单」→ 用查询 Skill / `query_platform_data`
- 「把这批数据导入」→ 用导入流程（含确认）
- 「谁导入了文件」→ `query_write_audit`

## 你怎么问（由粗到细）

1. **人话总览（推荐先问）**  
   「平台能干什么」「有哪些功能模块」  
   → 只给表结构业务能力地图；可顺带一句「查工单/排产是模拟演示，不计入平台能力」。

2. **缩到一块**  
   「仓储能管哪些事」「品质模块说说」  
   → 业务问题 + 代表表 + 可怎么问（表结构语境）。

3. **按业务场景要表包**  
   「工单从下达到入库涉及哪些表」  
   → 按阶段给出主表路径，并可附带字典关联扩展表。

4. **盯住一张表**  
   「TBL_MO 是什么意思」

5. **术语不清**  
   「工单和排产有什么区别」「IPQC 是什么」

6. **导出摸底报告**  
   「导出一份摸底报告（Markdown 和 Excel）」  
   → 生成到导出目录（默认桌面，或 `EXPORT_DIR`），回复里给路径。

7. **文档更新后**  
   「重建表结构索引」

## 助手内部工作流（对应工具）

```text
你提问
  ↓
Skill（analyze-mes-schema）判断：这是「摸底/看功能」，不是「查实时数据」
  ↓
读本地能力地图 + 表结构文档（或索引缓存）
  ↓
按需要调用：
  人话总览 → list_platform_capabilities
  模块详情 → describe_platform_capability
  术语小抄 → list_platform_glossary
  表结构总览 → analyze_schema_capabilities / list_schema_domains
  找表 / 详表 → list_schema_tables / describe_schema_table
  场景表包 → list_business_scenarios / get_scenario_table_pack
  摸底报告 → export_schema_survey_report
  文档更新 → rebuild_schema_index
  ↓
用中文整理：人话能力 → 代表表 / 场景路径 / 报告路径
  ↓
提醒：表结构平台能力 ≠ 模拟演示查/导
```

Skill 路径：`apps/agent/skills/analyze-mes-schema/SKILL.md`

## 人话能力地图（模块）

配置：`apps/agent/tools/schema_tool/capability_map.json`（`scope: schema_only`）

每块包含：一句话能力、常见业务问题、用户说法、代表表、相关场景、示例问法。

状态含义：
- `schema_backed`：字典中有代表表可佐证
- `schema_partial` / `schema_unverified`：配置不完整

**明确排除：** 查工单、查排产、导入导出 —— 模拟演示，见实体目录 `entities.json`，不进入本地图结论。

## 业务场景表包（预置）

| 场景 id | 标题（示例说法） |
|---------|------------------|
| `mo-to-warehouse` | 工单从下达到入库/仓储 |
| `srm-receiving` | 采购收料到入库 |
| `quality-ipqc` | 品质检验（IPQC/化验/客诉） |
| `oqc-shipment` | 出货报告（OQC） |
| `eam-maintain-repair` | 设备点检保养与维修 |
| `spc-control` | SPC 统计过程控制 |

种子表按阶段排列；可选按字典「关联关系」向外扩 1 跳。缺失表会标在 `missing_in_doc`。

---

## 摸底报告内容

- 能力前缀地图、业务域与代表表
- 预置场景表包摘要
- 当前助手**模拟演示**实体（entities.json，非平台能力背书）
- 代表表字段摘要（可关：`include_fields=false`）

格式：`format=markdown|excel|both`（默认 both）

## 工具一览

| 工具 | 作用 |
|------|------|
| `list_platform_capabilities` | 人话能力地图总览（**仅表结构平台能力**） |
| `describe_platform_capability` | 某模块人话详情（表结构） |
| `list_platform_glossary` | 术语小抄 |

| `list_schema_tables` | 按域/关键字检索表（分页） |

| `list_business_scenarios` | 列出预置业务场景 |
| `get_scenario_table_pack` | 按场景串主表 + 关联扩展 |
| `export_schema_survey_report` | 导出摸底报告 Markdown/Excel |
| `rebuild_schema_index` | 文档更新后重建索引 |

---

## 边界（不影响已有功能）

- **不连** MES/ERP 数据库，不改 `entities.json`，不改写 `WRITE_TOOLS`
- 查/导/导入确认（M0/M2）路径不变；本能力仅读本地 Markdown + 写本地报告文件
- 表结构平台能力 ≠ 助手模拟演示（查工单/排产/导入导出）；演示仍走原工具，但不改平台能力定义

## 环境变量（可选）

- `MES_SCHEMA_DOC`：覆盖默认文档路径
- `EXPORT_DIR` / `EXPORT_TO_DESKTOP`：报告输出目录（与平台数据导出同一套约定）

索引缓存：`data/schema/mes_schema_index.json`（自动生成）
