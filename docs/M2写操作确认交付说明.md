# M2 交付说明：受控写操作（HITL）

> 前提：第一阶段对话 / 流式过程区 / ERP 登录保持可用。  
> 开关默认开启；出问题可一键关闭或按 git 回滚。

---

## 做了什么

### 1. 写工具清单

- 常量：`apps/agent/middleware/write_tools.py`
- 当前须确认的写工具：**`import_file_to_platform`**
- 查询、本地导出、预览、格式转换**不**进确认流

### 2. 人工确认中间件

- `MesWriteConfirmMiddleware`（`apps/agent/middleware/write_confirm.py`）
- 环境变量 **`REQUIRE_WRITE_CONFIRM=true`（默认）** 时挂入 `build_custom_middleware()`
- Agent 调用写工具时：
  1. **不调用**平台 import
  2. 只读预览文件（行数 / 列 / 样例）
  3. 落盘 pending action（`data/writes/pending/{action_id}.json`）
  4. 返回带 `__write_confirm__` 的 ToolMessage，并提示模型勿重试

### 3. 确认 / 取消 API

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/writes/pending` | 当前用户待确认列表 |
| GET | `/api/writes/actions/{id}` | 单条详情 |
| POST | `/api/writes/actions/{id}/confirm` | **确认后直调工具写 ERP** |
| POST | `/api/writes/actions/{id}/cancel` | 取消，无平台副作用 |
| GET | `/api/writes/audit` | 只读审计（可按 thread_id / tool） |

安全约束：

- 需登录（与对话相同 Bearer）
- 操作人绑定 `user_id` / `username`，禁止串用他人 pending
- 一次性状态机：`pending → confirmed | cancelled | failed | expired`
- 默认 30 分钟过期（`WRITE_CONFIRM_TTL_SEC`）

### 4. 前端确认卡

- SSE 新事件：`type: "confirm"`
- 组件：`WriteConfirmCard.vue`，嵌在对话气泡中
- 展示实体、文件、行数、字段、样例；「确认写入 / 取消」

### 5. 审计落盘

- `data/writes/audit.jsonl`：pending / confirmed / cancelled / failed / expired
- 字段含 thread、user、tool、参数摘要、结果摘要

### 6. Skill 提示

- `import-export-data`：收到挂起确认后禁止再次调用导入

## 验收对照（M2 DoD）

| 项 | 状态 |
|----|------|
| 未确认时写工具不会改平台 | 中间件短路 + 仅 confirm API 执行 |
| 确认后可成功导入；取消无副作用 | confirm / cancel 分路径 |
| 审计可按会话查 | `GET /api/writes/audit?thread_id=` |
| 查询等第一阶段能力不受影响 | 写确认默认只拦写工具；可用 `REQUIRE_WRITE_CONFIRM=false` 整段关闭 |

**当前阶段（功能验证，未到上线）：** 上表通过即可收口开发验收。下列三项**暂缓**，不阻塞 M2 功能验证：

1. 其它 ERP「更新类」写接口纳入确认清单（现仅 `import_file_to_platform`）  
2. 多 API 实例共享 `data/writes`（现按单机试点）  
3. 试点实施业务签字「敢用」（上线/试点放量前再做）

## 隐患与限制（务必读）

1. **Agent 仍可能「嘴上说已导入」**  
   模型可能无视 ToolMessage 幻觉成功。以确认卡 + 审计为准，不以助手文案为准。

2. **确认后不再走 Agent 图 resume**  
   采用「API 直执」而非 LangGraph `interrupt_on`，实现简单、可回滚；缺点是确认后不会自动再触发一轮模型总结（前端会补一句结果文案）。

3. **pending / 审计在本地磁盘（上线前再处理）**  
   功能验证单机足够。多实例部署时需共享卷或改库——**暂缓，不上线前不必做**。

4. **文件路径信任边界**  
   确认执行使用挂起时保存的 `file_path`。应确保上传目录可控；勿让 Agent 写入任意系统路径后导入（现有上传落 `data/uploads`）。

5. **Agent 单例与热更**  
   改 middleware / 环境变量后需重启 API（`./scripts/stop.sh && ./scripts/dev.sh`）。

6. **历史会话中的确认卡**  
   过期或已处理的 action 再点会 409/410；属预期。

7. **性能**  
   预览会读文件头；超大文件受 `MAX_IMPORT_ROWS` 与 pandas 读入成本影响，与原先导入一致。
   审计查询默认近 30 天 + 分页，避免全量扫描。

## 回滚方式（由轻到重）

### A. 功能开关（推荐，无需改代码）

在仓库根 `.env`：

```bash
REQUIRE_WRITE_CONFIRM=false
```

重启 API。行为回到「Agent 可直接 import」，第一阶段其它功能不变。

### B. 仅清 pending / 审计数据

```bash
rm -rf data/writes/pending/*
# 可选：备份后清空审计
# mv data/writes/audit.jsonl data/writes/audit.jsonl.bak
```

### C. Git 回滚本里程碑改动

## 手工冒烟建议

1. 登录后查询生产计划 / 工单 → 仍应流式正常，**无确认卡**  
2. 上传 CSV，自然语言要求导入 → 出现确认卡，**ERP 尚无新数据**  
3. 点「取消」→ 审计有 `write_cancelled`，平台无变更  
4. 再导入 → 点「确认写入」→ 成功则审计 `write_confirmed`，平台有数据  
5. `GET /api/writes/audit?thread_id=<当前会话>` 能查到记录
