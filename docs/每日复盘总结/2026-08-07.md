## 3. 自检：发现问题与仍存风险

### 3.1 已暴露并已修

| 问题 | 原因 | 处理 |
|------|------|------|
| 写码界面假死感 | 本地状态与 Cloud 不同步 / 过程无刷新 | 对账收尾 + 进度刷新 |
| 贴图不理解 / 复刻差 | 仅靠弱文字或臆造模块 | 复刻视觉规格 + 禁白卡交差 + **原图进 Cloud** |
| 确认钮无反馈 | 异步准备阶段未切 busy | 提前 `running` + spinner |
| 侧栏每消息闪空白 | 历史强制整表 loading | 静默刷新 |
| 首页高度无限涨 | `autoresize` ↔ 百分比高度互撑 | 固定图表高度（`579656a`） |
| 右下角字乱 / 裁切 | 行高不足 + overflow | 加高行、nowrap/ellipsis（`0be4e58`） |
| **任意路径读图外传 Cloud** | `resolve_image_path` 接受任意可读绝对路径 | **仅 `data/uploads`**（高危） |

### 3.2 安全自检（专项）

| 级别 | 问题 | 状态 |
|------|------|------|
| **高** | 登录用户可通过 `file_paths` 指定任意本机可读图片路径外传 Cloud | **已收紧** uploads-only；**部署后需重启 API** |
| 中 | 上传接口仍回传绝对 `path`，前端原样回传扩大攻击面 | 建议前端只回传 `saved_name` |
| 中 | `/api/download/{filename}` 无登录（有目录校验） | 导出含敏感数据时需加鉴权 |
| 低 | job JSON 存截图路径；vision 发智谱 | 预期；注意第三方可见性 |
| 运维 | `.env` 含 Token；今日曾用 Token clone，临时目录已清 | **勿提交 .env**；若进过日志/聊天建议轮换 |

相对稳妥：`/api/uploads/{filename}` 鉴权 + 路径净化；上传/Cloud 图片有大小与张数限制。

### 3.3 仍存风险 / 未闭环

1. WorkBuddy 今日大量前端/写码改动**未必已全部提交推送**——与昨日同类风险，择机白名单提交。
2. 1:1 复刻仍非像素级：顶栏深浅、小屏滚动、「详细信息」占位等差距需诚实告知用户。
3. Cloud 终稿仍多为「工具过程 → 一次下发」平台特性，前端渐进只能缓解观感。
4. 右下角修后需用户 `git pull` + 刷新 `/home` 目视确认。
5. 意图启发式 + lane：极端短句仍可能歧义，继续靠反问与对立话术回归。

### 3.4 流程自检（有无做错）

- 先列优化项再改代码（用户要求）——遵守；P0 优先方向正确。
- 复刻失败未甩锅「模型不行」，拆成规格不足 vs 写码不足，并上原图直传——对症。
- 修高度环时坚持固定 px、避免再引入 `height:100%` autoresize——与右下修兼容。
- 用 Token clone 后 scrub remote、删临时目录——流程正确；密钥仍勿进文档/复盘正文。
