## 2. 今日做了什么（按主题）

### 2.1 B 查数：真数据 + 可读结果

昨日边界（查数走 HTTP、不直连库）今天在江西中软资料包上跑通。

- 列表走当前目录实体（示例 `work-orders`），回复中文列（状态/优先级/产线/工单号/产品），不把表结构模块清单当业务数据。
- 筛选必须作为 MES API 参数下发，禁止全量拉取后口头说「都是 pending」。
- `summarize_platform_data` 按返回记录里的真实字段分组。
- 导出给出绝对路径与行数。
- 指标口径（在制 / 紧急未完工 / 当日完工）进 `metrics_default.json`，运行时绑定当前目录字段与枚举，不写死某一套 MES。

联调数字见文末「现场记录」。

### 2.2 C 运维：值班话术工具化

- 场景包 `ops_scenes_default.json` + `list_ops_scenes` / `run_ops_scene`。
- 紧急堆积与查数口径对齐（见 3.1）：urgent **或** high，且未完工。
- 探活 / 401 / 谁导入了 不依赖可查对象目录是否生成完毕。

### 2.3 A 懂平台：对照 + 换平台自检

- `compare_schema_vs_catalog`：表结构（L0）对 OpenAPI 可查对象（L1），默认不抽检现场。
- 无 `capability_map.json` 时按当前表结构域推断人话能力地图与术语。
- 场景表包按文档表名/中文关键字匹配，不写死 `TBL_*`。
- `inspect_mes_profile`：清缓存后重读当前资料包；返回 known / missing / next_tool；凭据只报是否已填，不回账号密码。
- 对话注入当前 MES 配置（写码 / 审核 / 贴码车道除外），避免用上一套系统的记忆作答。

### 2.4 D 写码：加列必须落到库和历史数据

现场问题：工单列表加「实际开始/结束时间」后，页面有了、库也 ALTER 了，**历史行仍是空**。提示词约束不够。

处理：

- 提示词增加数据栈规则（UI + 模型 + 迁移 + 回填）。
- **确定性闸门** `stack_chain_gate`：同步到目标目录后扫描工程内 SQLite，只动白名单时间列、只填 NULL。
- 演示库约定：开始用计划日 08:00，结束用计划日 18:00；pending 结束时间为空是正确行为。

### 2.5 产品硬约束（全天守住）

- 可查对象与 path 来自当前资料包，不把 `work-orders` / `/api/v1` 写成产品默认。
- WorkBuddy 登录 ≠ MES 查数鉴权。
- A 摸底（表结构）与 B 查数（HTTP）不混用。
- 未知就列缺失项请用户到「系统配置 → MES 接入」补齐，禁止编造。

## 3. 自检：发现问题与仍存风险

### 3.1 已暴露并已修

| 现象 | 原因 | 处理 |
|------|------|------|
| 「紧急工单」只出 1 条 | 只筛 `priority=urgent` | 口径改为 urgent **或** high ∩ 未完工；现场 3 条（WO-AN-005 / 003 / 001） |
| 加实际开始/结束时间后列表仍空 | 只改 UI + ALTER，未回填历史 NULL | 同步后闸门补列并按状态回填 |
| 问「MES 401 / 接口通不通」被挡住 | `inspect_mes_profile` 把 ops 与查数一样要求必须有目录 | 运维不依赖空目录；未配置平台名称才拦 |
| 闸门可能拼 SQL / 写到仓外 | 表名列名直接插值；`rglob` 跟随符号链接 | 标识符白名单 + 引号；解析路径必须仍在工程根下；跳过 `.vite` / `.dev-logs` |
| 工具报错带出本机路径 | `str(e)` / 期望路径直接回给模型 | 只报异常类型 + 中文提示 |
| 查数表格可能露出 token/密码列 | 展示列未过滤密钥字段 | 跳过 password / token / api_key 等列名 |

### 3.2 已知边界（不是当天修完的 bug）

1. **当日完工**：该 MES 列表接口没有日期查询参数，只能诚实降级；不要对用户说「今天完工了 N 条」除非筛参真的下发成功。
2. **只读 SQL、字段级权限、固定产线异常日报套版**：方案里仍是后置，本轮未做。
3. **桌面包未签名**；Win 包须在 Windows 主机打（昨日结论仍有效）。
4. **当日改动尚未入库**：查数/运维/闸门/自检均在工作区。提交时排除 `.env`、`data/settings.json`、客户资料包密钥、本机沙箱 `data/local_dev/`。

### 3.3 流程自检

- 口径先对现场真实枚举（urgent vs high），再写默认 filter，避免「工具调通了但条数不对」。
- 写码加数据列：提示词只能减漏，闸门才能保证历史空值被填。
- 换平台验收标准是「缺什么说什么、已知做下一步」，不是「换一套也能猜」。
- 自检安全时，高熵中文字符串扫描是误报，不要当成密钥。
