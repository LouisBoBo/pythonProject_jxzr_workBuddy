# 03 · 文件导入与受控写入

> 上传 CSV/Excel 想写入 MES：**先预览，人点确认卡，后端再真正导入**；可查「谁导了什么」。

---

## 1. 实现原理

### 1.1 为什么导入要特别「慢半拍」？

往 MES 写数据 = **生产数据变更**。如果模型说完「已导入」就真写进去了，风险是：

- 用户没看清目标实体、行数、样例行  
- 模型幻觉多导了几千行  
- 事后说不清是谁干的

所以采用 **HITL（Human In The Loop）**：人机协同，**提议和执行分开**。

### 1.2 三段式：提议 → 挂单 → API 真执行

| 阶段 | 谁干 | 发生什么 |
|------|------|----------|
| 提议 | 大模型 | 决定调用 `import_file_to_platform`，带上文件路径、目标实体 |
| 拦截 | WriteConfirmMiddleware | 不真写 MES，生成 `pending` 记录 + 预览信息 |
| 执行 | FastAPI `writes.py` | 用户点确认后，**同一段 Python 函数**再跑一遍 import |

注意：**确认后不再问模型**「请确认是否导入」。否则模型可能第二次回答不一致。执行权在 API。

### 1.3 Middleware 怎么拦住写工具？

`apps/agent/middleware/write_confirm.py` 在 Agent 工具调用链上挂了一层：

- `WRITE_TOOLS` 集合里目前主要是 `import_file_to_platform`（`write_tools.py` 声明）  
- 模型发起 tool call → Middleware 改成「生成确认单」→ SSE 推 `confirm` 事件  
- 前端 `WriteConfirmCard.vue` 展示预览

开关 `REQUIRE_WRITE_CONFIRM` 默认 `true`；关掉后适合本地调试，**不建议生产关**。

### 1.4 审计与限流

- 每次确认/取消写入 `write_store` + 审计查询接口  
- `MAX_IMPORT_ROWS` 限制单次行数，防一次灌爆  
- 上传路径经 `upload_paths.py` 校验，防 `../` 穿越

## 2. 实现流程（技术点怎么落地）

> 核心：**模型只提议，Middleware 挂单，用户确认后 API 直执**。执行函数与预览用的是同一个 `import_file_to_platform`。

### 2.1 上传文件（对话附件）

```text
POST /api/upload（chat.py）
  → 存 DATA_DIR/uploads/{user}/{uuid}_{filename}
  → upload_paths.py 校验路径在 DATA_DIR 内
  → 返回相对路径给 messages.attachments
```

### 2.2 Agent 提议：Middleware 截获写工具

```text
用户：「把这份 Excel 导入物料主数据」
  → SSE + Skill import-export-data
  → 模型 tool_call: import_file_to_platform(file_path, entity, ...)

WriteConfirmMiddleware.wrap_tool_call()（write_confirm.py）
  IF tool.name in WRITE_TOOLS:  # 目前仅 import_file_to_platform
    1. 剥离模型伪造的 _write_confirmed / _action_id
    2. _preview_import() → preview_file() 只读前几行，不调 MES 写接口
    3. create_pending_action() → data/writes/pending/{action_id}.json
    4. 返回 ToolMessage 含 __write_confirm__ + action_id
    不调用真实 handler
```

| 技术点 | 实现 |
|--------|------|
| 开关 | `REQUIRE_WRITE_CONFIRM` 默认 true；关则中间件不拦（仅调试用） |
| TTL | `WRITE_CONFIRM_TTL_SEC` 默认 1800s，过期 pending 失效 |
| 预览上限 | `preview_file()` + `MAX_IMPORT_ROWS` 防超大文件 |

### 2.3 SSE 推确认事件 → 前端卡片

```text
agent_wrapper._extract_write_confirm() / agent_tool_ui
  → SSE { type: "confirm", action_id, preview, entity, ... }
  → WriteConfirmCard.vue 展示行数样例、目标实体
```

用户未点确认前：**MES 侧无任何写入**。

### 2.4 用户确认：API 直执（不经模型）

```text
POST /api/writes/actions/{action_id}/confirm（writes.py）
  1. _assert_owner(user_id) — 只能确认自己的 pending
  2. claim_action() — pending → executing 原子认领，防双击
  3. _execute_write() → import_file_to_platform() 真调 MES HTTP
  4. mark_action(confirmed | failed)
  5. 写审计 GET /api/writes/audit 可查

取消：POST .../cancel → pending 标记 cancelled，不执行
```

| 技术点 | 实现 |
|--------|------|
| 防假确认 | 确认 API **不再**让模型二次 tool_call |
| 失败回滚 | 执行失败 → action 回 pending 或 failed，审计有记录 |
| 行数 | `import_file_to_platform` 内校验 `MAX_IMPORT_ROWS` |

### 2.5 与读操作对比

| Tool | 改 MES | 确认卡 |
|------|--------|--------|
| `query_platform_data` | 否 | 无 |
| `import_file_to_platform`（提议） | 否 | 弹出 |
| `import_file_to_platform`（confirm 后） | **是** | 已确认 |

### 2.6 常见排查

| 现象 | 查什么 |
|------|--------|
| 没弹确认卡 | `REQUIRE_WRITE_CONFIRM`；Middleware 是否加载 |
| 确认后仍无数据 | MES 写接口 4xx；看 audit |
| 403 owner | 换用户登录；action 绑定 user_id |

## 3. 技术及用法

| 技术 / 模块 | 怎么用 |
|-------------|--------|
| `middleware/write_confirm.py` | 拦截写工具集合 `WRITE_TOOLS` |
| `middleware/write_tools.py` | 声明哪些工具算「写」 |
| `tools/file_ops.py` | `import_file_to_platform` 实现 |
| `write_store.py` | pending / 审计落盘 |
| `apps/api/routes/writes.py` | confirm / cancel / pending / audit |
| `WriteConfirmCard.vue` + `api.js` 的 `confirmWrite` | 人机确认 UI |
| Skill `import-export-data` | 教模型何时导入、如何描述预览 |

上传路径安全：`upload_paths.py` 等，防路径穿越。

---

## 4. 后续扩展与优化建议

1. **可做**：更多写工具纳入同一 HITL 集合（统一确认卡体验）。  
2. **可做**：导入失败按行号回显、支持部分成功策略（需业务定规则）。  
3. **慎做**：关闭 `REQUIRE_WRITE_CONFIRM` 上生产。  
4. **不要做**：让模型在确认后再「自己决定」调一次写工具当执行。

---

## 自测路径

1. 上传小 CSV → 说导入某实体。  
2. 必须出现确认卡；未点确认 MES 无新数据。  
3. 确认后有成功反馈；审计能查到本次操作。
