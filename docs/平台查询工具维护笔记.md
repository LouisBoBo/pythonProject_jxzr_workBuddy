# 平台查询工具维护笔记

本文说明如何维护 Agent 的平台查询能力：能查哪些实体、中文如何映射到 API、加新接口时改哪里。

> Monorepo 路径前缀：`apps/agent/`

## 架构一览

```
用户说「查工单 / 查生产计划」
        ↓
Web (apps/web:5180) → API (apps/api:8765) → Agent
        ↓
apps/agent/tools/query_tool/platform_query.py
        ↓
apps/agent/tools/platform_api.py
        ↓
apps/agent/tools/query_tool/entity_catalog.py  ← 读 entities.json
        ↓
GET/POST /api/v1/{path}/
```

实施高频话术与验收句见 [`docs/实施高频场景清单.md`](../../docs/实施高频场景清单.md)；无 LLM 别名冒烟：`make smoke-entity-phrases`。

| 文件 | 职责 |
|------|------|
| `apps/agent/tools/query_tool/entities.json` | **日常维护入口**：实体白名单、别名、路径、字段说明 |
| `apps/agent/tools/query_tool/entity_catalog.py` | 加载目录、别名解析、生成系统提示词 |
| `apps/agent/tools/query_tool/platform_query.py` | Agent 可调用的查询工具封装 |
| `apps/agent/tools/platform_api.py` | HTTP/Mock 客户端；`ENTITY_MAP` 来自目录 |
| `apps/agent/skills/ops-query-playbook/SKILL.md` | 异常工单 / 按状态筛 / 排产汇总话术 |
| `apps/agent/middleware/entity_guard.py` | 可选：明显选错实体时硬拦截（`ENABLE_ENTITY_GUARD`） |
| `apps/agent/agents/agent.py` | 启动时调用 `build_system_prompt()` |
| `apps/api/` | HTTP 服务与 Agent 包装 |
| `apps/web/` | 前端界面 |

**不是**平台上所有 API 都能查；只有目录里登记过的实体才能走通用查询工具。

## 查询工具有哪些

| 工具 | 用途 |
|------|------|
| `list_platform_entities` | 列出实体 id、中文名、别名、字段与条数 |
| `get_platform_summary` | 平台概要：各实体记录数 |
| `describe_entity` | 某实体字段结构与样例 |
| `query_platform_data` | 按 entity + filters 条件查询 |

导入/导出在 `apps/agent/tools/file_ops.py`，同样用实体目录里的英文 id。

## 自然语言如何映射到 API

1. **提示词**：启动时根据 `entities.json` 生成说明，LLM 据此选择参数。
2. **别名解析**：`resolve_entity_id()` 接受英文 id 或中文别名（含排产/排程等同义说法）。
3. **路径映射**：`id` / `path` → 请求 `/api/v1/{path}/`。

## 如何加一个新实体（标准 CRUD）

只改 `apps/agent/tools/query_tool/entities.json`，然后重启 API（`./scripts/stop.sh && ./scripts/dev.sh`）。

最小配置：

```json
{
  "id": "devices",
  "label": "设备",
  "aliases": ["设备", "机器"],
  "path": "devices",
  "ops": ["query", "import", "export"]
}
```

`fields` 可选，不影响真实查询。

## 启动与端口

```bash
./scripts/dev.sh     # Web 5180 + API 8765
./scripts/stop.sh
```

改实体目录后必须重启 API，否则仍用内存中的旧提示词/映射。
