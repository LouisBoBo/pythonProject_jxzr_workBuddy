# 第二阶段产品方向（实施 / 运维微 WorkBuddy）

> 状态：**已锁定**（2026-07-24）  
> 承接：[`第一阶段开发复盘.md`](./第一阶段开发复盘.md)  
> 执行拆解：[`第二阶段开发计划.md`](./第二阶段开发计划.md)

---

## 一句话锚点

**让实施与运维在公司自有 MES/ERP 上，用自然语言完成日常查询与受控变更，过程可审计、结果可回看。**

---

## 已确认前提

| 项 | 结论 |
|----|------|
| 主用户 | **实施、运维**（不是平台研发） |
| 主战场 | 对接自有平台：查 / 导 / **受控改** |
| 产品形态 | 公司自有「微 WorkBuddy」——对话 + 工具 + 可审计过程 |
| 领导第 3 条 | 「平台新功能：写代码 → 测试 → 部署全自动」= **愿景，本阶段不做** |

---

## 本阶段目标（做）

1. **场景加深**：围绕实施/运维高频话术补实体、别名、Skills  
2. **受控写操作**：导入/更新须确认（HITL / Middleware），禁止默默写生产  
3. **权限与审计**：谁、哪个会话、调了什么工具、改了什么——可查可追责  
4. **嵌入方式**：能从公司平台打开助手并带身份/上下文（独立 5180 保留作开发壳）  
5. **体验小步**：只修阻塞真用的点，不重做「思考流」大叙事  

---

## 本阶段非目标（不做）

- 自动写业务代码、自动测、自动部署流水线  
- 通用企业 Agent / 多租户 SaaS 化  
- 推倒重来架构；另开与 MES 运维无关的产品线  

---

## 对领导第 3 条的话术

> 我们先把实施运维的自然语言助手做到「天天用、敢用、可审计」；全自动研发流水线依赖代码库权限、CI、环境与回滚体系，作为后续阶段**单独立项**，避免和当前业务助手抢资源。

---

## 能力分层

```text
[本阶段] 实施/运维 → 微 WorkBuddy → 平台 Tools/实体 + Skills + 确认与审计
    │
    └── 明确不进入 → [缓做] 写代码 / 测试 / 部署全自动
```

---

## 建议里程碑（方向级）

| 里程碑 | 验收直觉 |
|--------|----------|
| **M0 登录** | 使用前须 ERP 登录；会话带用户信息（见 [`ERP登录对接说明.md`](./ERP登录对接说明.md)） |
| **M1 真场景** | 实施用自然语言完成 3～5 个高频查询/导出，实体选错率可接受 |
| **M2 敢写** | 受控导入/更新有确认与审计，试点环境敢让实施点 |
| **M3 进平台** | 从公司平台能打开助手并带身份/上下文 |
| **M4 稳态** | 权限、日志、配置与部署说明可交给运维接手 |

> 说明：M1 查询场景已有部分验证通过时，可优先做 **M0 登录** 再进 **M2**。

详细任务与文件落点见 [`第二阶段开发计划.md`](./第二阶段开发计划.md)。
