## 2. 今日做了什么（按主题）

### 2.1 本机目录写码主线（P0）

- 默认目标：本机绝对路径 + 上次记忆；可选 GitHub。
- 流程：澄清需求 → 确认卡 → **沙箱改码** → 闸门校验 → **sync 到确认目录** → **确保 FE/BE 并给出预览 URL**。
- 关键模块：`apps/local_dev/`（`sandbox` / `service` / `dev_runtime` / `workspace` / `jobs` 等）、`apps/api/routes/local_dev.py`、写码确认卡与 Chat 流式对接。
- 方案与验收说明已写入 [`本机目录写码与沙箱隔离方案.md`](../../写码与审码/本机目录写码与沙箱隔离方案.md)。

### 2.2 沙箱安全加固

| 问题 | 风险 | 处理 |
|------|------|------|
| 可写并同步 `.git/hooks/*` | 注入 git hook | 拦截路径组件 `.git` / `.ssh` 等 |
| 可写 `authorized_keys` 等 | 凭据落盘 | 扩大敏感文件名单 |
| 可选家目录 / 整盘 Desktop | 同步面过大 | 拒绝 home、Desktop/Documents/Downloads 整根 |
| sync 遇非法路径中途抛错 | 可能半同步 | 先校验再批量拷贝，非法项跳过 |
| 任务无 `user_id` 时归属过宽 | 越权读 SSE | 无归属信息直接 403 |

**结论（本机场景）**：目录沙箱主路径可用；**不是** gVisor/Docker。隔离靠路径闸门。`POST /api/local-dev/pick-folder` 弹窗在 **跑 API 的机器** 上。用户确认过的工程目录内，模型仍可改非敏感业务源码——产品意图，靠确认卡约束。

### 2.3 同步后预览（选项 1 已落地）

- `dev_runtime.ensure_dev_preview()`：探测工程与端口 → HTTP 健康检查 → 健康则复用，不健康则结束进程再拉起。
- Job / SSE `done` 带 `preview_url` / `preview`；前端确认卡展示可点击链接。
- 配置开关与超时：`LOCAL_DEV_PREVIEW_*`（见 `apps/local_dev/config.py`）。

### 2.4 ERP / 样例仓侧修障

- **维修管理「请求失败」**：路由冲突——`/api/equipment/repairs` 被 `/api/equipment/{equipment_id}` 吃掉 → 迁到 `/api/equipment-repairs`，前端 `equipmentRepair.js` 同步。
- **预览后无法登录**：后端坏 import（`DeviceAlarmTrendPoint`）+ 「端口在听但未健康仍当复用」→ 健康必须过 HTTP；不健康杀进程重开；fullstack 需前后端都健康。

### 2.5 UX 与对话体验

- 确认卡需求 Markdown 渲染（与对话一致）。
- 「本轮进度」可折叠、嵌写码确认卡；步骤文案去「schemas/router」等行话。
- 工具循环有 `tool_calls` 时不再把中间叙述灌进气泡（减少闲聊刷屏）。
- 进度卡重复：流式气泡在 `activeCursorDevMsg` 已有确认卡时不再渲染第二份；标题去掉与左侧圆点重复的「1. 2.」前缀。

### 2.6 阻断级前端故障：侧栏切换失效

- **现象**：点击「开启新对话」与历史会话无效果。
- **根因**：会话切换未清写码轮询；HMR 损坏 Vue vnode 后持续 `__vnode` / `parentNode` 报错，路由更新打不进干净重绘。
- **处理**：
  - `App.vue`：`router-view` 按 `thread` 做 `:key` 强制重挂载；
  - `ChatView`：`loadSession` / `startNewChat` / `onUnmounted` 中止流并 `clearActiveCursorDev`；
  - `CodingPlanCard`：去掉对 steps 的 deep watch，减轻无意义更新。

## 3. 自检：发现问题与仍存风险

### 3.1 已暴露并已修

- 维修 API 路由被动态段吞掉。
- 预览「假复用」导致后端未真正可用。
- 新对话 / 历史点击无响应。
- 「本轮进度」双份展示。
- 沙箱路径逃逸与敏感路径若干缺口（见上表）。

### 3.2 仍须知晓（非 bug，是边界）

- 目录沙箱 ≠ 进程级容器隔离；恶意/失控子进程仍是本机进程模型。
- 确认目录内的业务文件覆盖风险由产品确认卡承担。
- 远程部署时勿把「本机选目录弹窗」当成浏览器本机选目录。
- 长时间热更新后若侧栏再次异常，先硬刷新（`Cmd+Shift+R`）再验证。
