# 08 · 写码改功能（本机 Cursor / GitHub Cloud）

> 聊天里把需求说清楚 → **人确认** → Cursor **真改**本机工程或白名单 GitHub 仓。默认本机；Cloud 走固定工作分支，人工合 main。

---

## 1. 实现原理

### 1.1 写码也是「两段式」，和查数、审码不一样

| 阶段 | 谁干 | 产出 |
|------|------|------|
| **讨论段** | Deep Agents + `cursor-dev-chat` Skill | 澄清需求、选项、方案围栏 |
| **执行段** | Cursor SDK（本机或 Cloud） | 磁盘/远程分支上的真实 diff |

大模型在讨论段**不能直接改**你电脑上的项目目录——否则无法审计、无法回滚、也和「确认卡」产品形态矛盾。  
所以模型只输出特殊标记块，例如：

```text
:::cursor_dev_options
...可选方案...
:::

:::cursor_dev_propose
...拟改哪些文件、做什么...
:::
```

前端 `chatCursorDevParse.js` 解析这些块，渲染成可点的确认卡。

### 1.2 本机写码 vs Cloud 写码

| 模式 | 改哪里 | 典型配置 | 执行模块 |
|------|--------|----------|----------|
| **本机（默认）** | 设置里配的本机工程目录 | `LOCAL_DEV_ENABLED`、`LOCAL_DEV_AGENT=cursor_sdk` | `apps/local_dev/` |
| **Cloud** | 白名单里的 GitHub 仓 | `CURSOR_DEV_ENABLED`、`CURSOR_API_KEY`、仓 allowlist | `apps/cursor_dev/` |

本机路径下还有**沙箱**：Cursor 先在隔离目录里改，确认同步后再拷回工作区（`sandbox.py`、`fs_snapshot.py`），降低误删整个盘的风险。

### 1.3 写码之后不会自动提交 / 部署

这是刻意的产品设计：

- 改完 → 人说「提交今天的代码」→ 功能 09  
- 推上远程后 → 人说「部署到预发」→ 功能 10  

避免「改一行就自动上生产」。

### 1.4 和审码、贴码的隔离

- `workbuddy_lane=code_dev`  
- 系统提示禁止 `request_git_*` / `request_ide_*`（那是审码工具）  
- 界面类需求额外走 `ui-product-design` Skill（禁止照抄 WorkBuddy 首页当客户页面）

## 2. 实现流程（技术点怎么落地）

> **两段式**：讨论段 SSE 出围栏；执行段 Job API 调 Cursor。**磁盘改动只发生在 Job 确认之后**。

### 2.1 讨论段：意图 → 围栏 → 确认卡

```text
looksLikeCodeDevIntent(text, files) → lane=code_dev
  → POST /api/chat/stream
  → Skills：cursor-dev-chat（+ ui-product-design 若界面类）

模型输出（正文 + 围栏）：
  :::cursor_dev_options
  :::cursor_dev_propose

chatCursorDevParse.js 解析
  → CursorDevOptionsCard / CodingPlanCard
  → CursorDevRepoPickCard（本机目录 / GitHub 仓）
```

| 技术点 | 实现 |
|--------|------|
| 禁审码工具 | `agent.py` code_dev 块禁止 `request_git_*` |
| 禁照抄首页 | `ui-product-design` Skill 约束客户页面风格 |
| 此阶段 | `git status` 应仍干净（无 Job） |

### 2.2 执行段 · 本机 Cursor

```text
用户点「开始执行」
  → POST /api/local-dev/jobs（routes/local_dev.py）
  body: workspace, prompt, session_id, ...

service.py 起后台线程：
  LOCAL_DEV_AGENT=cursor_sdk（默认）
    → cursor_local_agent.py 调 Cursor Local SDK
  LOCAL_DEV_AGENT=llm 且 LOCAL_DEV_ALLOW_LLM_FALLBACK=1
    → 应急 LLM 工具环（非默认）

sandbox.py::prepare_sandbox()
  → 隔离目录内改文件
  → fs_snapshot / tools_fs 同步回用户 workspace
  → 记录 synced_files 到 job JSON（供功能 09 汇批）

ChatView 轮询 GET /api/local-dev/jobs/{id}
  → 步骤日志；可 cancel
  status=succeeded → 本机 IDE 可见 diff
```

| 技术点 | 实现 |
|--------|------|
| 开关 | `LOCAL_DEV_ENABLED` |
| 工作区 | 设置页 `LOCAL_DEV_WORKSPACE`；路径校验 |
| 沙箱 | 降低误删风险；同步失败 job 标 failed |

### 2.3 执行段 · Cursor Cloud

```text
POST /api/cursor-dev/jobs（routes/cursor_dev.py）
  → 仓须在 CURSOR_DEV_REPO_ALLOWLIST
  → cursor_dev/service.py → Cursor Cloud Agent API
  → 在固定工作分支（如 hebo）commit/push
  → 前端轮询 Cloud job；**不自动合 main**
```

| 技术点 | 实现 |
|--------|------|
| Key | `CURSOR_API_KEY` |
| 开关 | `CURSOR_DEV_ENABLED` |
| 白名单 | `CURSOR_DEV_REPO_ALLOWLIST` 防任意仓 |

### 2.4 与提交 / 部署衔接（刻意不自动）

```text
写码 Job succeeded
  → 不自动 commit（LOCAL_DEV_COMMIT_GATE 默认 0）
  → 用户：「提交今天的代码」→ 功能 09
  → push 后：「部署到预发」→ 功能 10
```

### 2.5 常见排查

| 现象 | 查什么 |
|------|--------|
| 无确认卡 | 模型是否输出 `:::cursor_dev_*`；Skill 是否加载 |
| Job 一直 running | Cursor Key、网络、仓权限 |
| 目录无变化 | 沙箱同步；workspace 路径是否配对 |
| 弹出审码报告 | lane 是否为 `code_review` |
| LLM 回退误开 | `LOCAL_DEV_ALLOW_LLM_FALLBACK` 应为 0 |

## 3. 技术及用法

| 技术 / 模块 | 怎么用 |
|-------------|--------|
| Skill `cursor-dev-chat`、`ui-product-design` | 讨论与 UI 约束（禁照抄首页乱套） |
| `chatCursorDevParse.js` | 解析围栏标记 |
| 确认卡 | `CursorDevRepoPickCard`、`CursorDevOptionsCard`、`CodingPlanCard` 等 |
| `apps/local_dev/service.py`、`cursor_local_agent.py` | 本机 Cursor SDK 执行 |
| `sandbox.py`、`fs_snapshot.py`、`tools_fs.py` | 沙箱隔离与同步 |
| `apps/cursor_dev/service.py`、`jobs.py` | Cloud Job |
| API | `routes/local_dev.py`、`routes/cursor_dev.py` |
| 配置 | `LOCAL_DEV_ENABLED`、`LOCAL_DEV_AGENT`（默认 `cursor_sdk`；`llm` 回退需 `LOCAL_DEV_ALLOW_LLM_FALLBACK=1`）；Cloud：`CURSOR_DEV_ENABLED`、`CURSOR_API_KEY`、`CURSOR_DEV_REPO_ALLOWLIST` |

截图规格：对话上传图片 → 视觉相关工具/提示辅助需求澄清（非必须）。

## 4. 后续扩展与优化建议

1. **可做**：写码成功后更明显引导「下一步：提交 / 部署」。  
2. **可做（P2 显式点名才开）**：评估 DeepSeek Harness **仅**替换本机写码执行器，不动主对话。  
3. **慎做**：扩大 Cloud 白名单仓到不可信第三方。  
4. **不要做**：把 Deep Agents 主环改成直接写宿主机；不要写码成功就自动 push main / 自动生产部署。

---

## 自测路径

1. 本机：配置工作区 → 小需求 → 确认卡 → 过程可停 → 目录出现改动。  
2. Cloud：白名单仓 + Key → 工作分支有 commit（依环境）。  
3. 确认前工作区不应被改。
