# 10 · 人触发预发部署

> **一句话**：你说「部署到预发」→ 看清确认卡 → 点确认 → 后台按配置走 **本机 SSH** 或 **GitHub Actions**，把**已提交的 ref** 发到预发，并可探活打开地址。  
> **不是**：写码/提交成功后自动上生产；也不是大模型自己 SSH、自己拿私钥（模型不参与发版命令）。  
> **看图**：[流程图总览 §7](./流程图总览.md#7-功能-10人触发预发部署)

---

## 1. 实现原理

### 1.1 我们到底实现了什么？

产品里的「自动化部署」容易被听成「AI 写完就上生产」。这里钉死的是另一件事：人说要发预发 → 确认 → **程序**按配置同步并重启服务。  
模型只参与日常聊天，**不**拼 SSH、**不**跑 rsync、**不**持有私钥内容。

| 人做的 | 系统干的 | 达到的效果 |
|--------|----------|------------|
| 说「部署到预发 / 发布到 staging」 | 意图旁路，直接 prepare API | 不进 Deep Agents，避免幻觉「已部署」 |
| 看确认卡（环境、ref、目标机/流水线） | prepare **零副作用**只做门禁检查 | 没点确认就绝不发版 |
| 点「确认部署」 | confirm 再检门禁 + 90s 防双击 → SSH 或 Actions | 真同步到预发 |
| 看过程条 / 探活地址 | poll `local-*` 内存 Job 或 GitHub run | 成功可点开访问；失败见日志 |

**技术落点（整包）：**

| 层次 | 路径 |
|------|------|
| 业务包 | `apps/local_dev/`：`deploy_prepare.py`、`deploy_confirm.py`、`deploy_local_ssh.py`、`deploy_github.py`、`deploy_config.py` |
| 探活 | `probe_deploy_health`（HTTP 2xx，走 `safe_http`） |
| HTTP | `apps/api/routes/local_dev.py`：`/deploy/prepare`、`/deploy/confirm`、`/deploy/poll`、`GET /deploy/status` |
| 意图 | `chatIntent.js`：`looksLikeDeploy` / `rawLooksLikeDeploy`（**没有** `_looksLikeDeployCore`） |
| 确认卡 | `LocalDevDeployGateCard.vue` |
| 配置族 | `DEPLOY_*`（设置页「自动化部署」+ 热更新） |

### 1.2 和「写码」「提交」「自动化任务」差在哪？

| | 写码（08）/ 提交（09） | **预发部署（本篇）** | 自动化任务（11） |
|--|----------------------|----------------------|------------------|
| 谁发起 | 写需求 / 「提交今天的代码」 | 「部署到预发」 | 时钟或「立即执行」 |
| 谁干活 | Cursor / git | **程序** SSH/rsync 或 Actions | Deep Agents 查/搜/写摘要 |
| 会不会发版 | 不会 | **会**（人确认后） | **明确禁止** |
| 读什么版本 | 工作区脏文件 / commit | **已提交 ref**（worktree 检出） | 与发版无关 |

设置页也是两套：`DEPLOY_*` 给发版；企微/飞书给自动化任务。

**技术上怎么隔开：**

| 点 | 实现 |
|----|------|
| 意图 | `looksLikeDeploy`；内部匹配用 `rawLooksLikeDeploy` |
| 与提交互斥 | `looksLikeLocalCommitBatch` 里若 `rawLooksLikeDeploy` 则 false |
| 优先级 | ChatView：**部署排在提交、写码前面** |
| 模型不碰 SSH | confirm 后 FastAPI 直调 `deploy_*.py` |

### 1.3 总开关、环境白名单、两种执行器

| 配置 | 含义 |
|------|------|
| `DEPLOY_ENABLED` | 总开关，默认 **关**；设置页打开并「保存并热更新」 |
| `DEPLOY_ENV_WHITELIST` | 允许环境名，默认含 `staging` |
| `DEPLOY_ALLOW_PRODUCTION` | 是否允许生产（默认关） |
| `DEPLOY_CI_PROVIDER` | 执行器：`local_ssh` 或 `github_actions` |

**代码默认：** `DEPLOY_CI_PROVIDER` 解析缺省为 **`github_actions`**。  
**江西中软现场推荐：** **`local_ssh`**——境外 Actions 连国内轻量机 `:22` 经常失败；Actions 路径仍保留作备选。

| provider | 实际干什么 |
|----------|------------|
| `local_ssh` | 临时 `git worktree` 检出 ref → 白名单构建 → SSH + rsync → 可选 `systemctl restart` → HTTP 探活 |
| `github_actions` | GitHub `workflow_dispatch` → 轮询 run 状态（构建/SSH 在 runner 上） |

### 1.4 为什么读的是「已提交 ref」，不是脏工作区？

**人话：** 你可能正在分支上改半截；预发要的是「已经 commit 上去的那个版本」，不能把未保存的脏文件直接 rsync 上去。

**技术点：** local_ssh 用 `git worktree add --detach` 检出 `ref`；部署前推荐顺序：写码 → 提交并 push → 再部署（ref 指向该分支或 tag）。

### 1.5 安全上钉死了什么？

| 约束 | 技术实现 |
|------|----------|
| 私钥只存本机路径 | settings 不存私钥内容；不进 Prompt |
| 路径不穿越 | sync 路径 `resolve` + `relative_to`；ref 禁 `..` |
| 浅路径 + `--delete` 拒绝 | 防误删 `/www/wwwroot` |
| 构建无 `shell=True` | 命令白名单字符 + `shlex.split`；禁 `;|&&` 等 |
| poll 防 Token 滥用 | 未配置仓时拒绝客户端乱传 `repo` |
| confirm 防双击 | 同 user/env/ref/provider **90s** 锁 |
| 终端态停轮询 | 成功/失败后 `stopPoll()`，**不**无限 poll |

## 2. 实现流程（人话 + 技术点怎么落地）

> 每节先讲「人看到什么 / 为什么这样」，再给 **技术点表** 和调用链。

### 2.1 意图识别：为什么一句话不进 Agent？

**人话：** 部署是开关 + 配置 + 确认问题；发送前拦住，直接画确认卡，避免模型说「已部署」却什么都没跑。

```text
ChatView.vue send()
  → looksLikeDeploy(text) === true
       → 内部：业务「部署工单」等排除后 → rawLooksLikeDeploy(t)
  → prepareLocalDevDeploy({ message })
  → POST /api/local-dev/deploy/prepare
  → 不走 POST /api/chat/stream
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 核心匹配 | `rawLooksLikeDeploy`（**不是** `_looksLikeDeployCore`） |
| 对外导出 | `looksLikeDeploy`：再排除贴码/审码/MES「部署计划」等 |
| 互斥 | 同句像部署时，提交批返回 false；部署优先于写码 |

---

### 2.2 prepare：只做门禁检查，绝不发版

**人话：** 猜环境（预发/生产）、定 ref、读 `DEPLOY_*` 快照，逐项检查开关/白名单/SSH 或 Token，把结果填进确认卡。此阶段不 worktree、不 rsync、不 dispatch。

```text
前端 api.js → POST /api/local-dev/deploy/prepare
           → routes/local_dev.py::prepare_local_dev_deploy
           → deploy_prepare.prepare_deploy(...)
```

**（1）猜环境、定 ref**

| 输入 | 处理 |
|------|------|
| 原话含「生产 / production」 | `target_env=production`（仍可能被白名单挡） |
| 含「预发 / staging / 测试」 | `staging` |
| 都没有 | `default_deploy_env()`（白名单第一项，常为 staging） |
| `ref` 空 | `default_deploy_ref()` ← `DEPLOY_DEFAULT_REF` 或 `LOCAL_DEV_WORK_BRANCH` |

**（2）检查项（写入 `checks[]` / `blocking_reasons[]`）**

| 检查 id | 过关条件 | 失败时人看到 |
|---------|----------|--------------|
| `enabled` | `DEPLOY_ENABLED` | 「总开关关闭」——拨钮未保存常见于此 |
| `env` | `env_allowed(target_env)` | 「环境未授权」 |
| `ci` / `token`（local_ssh） | `validate_local_ssh_settings`；私钥路径像私钥文件 | 缺主机/用户/路径等 |
| `ci` / `token`（github） | `DEPLOY_GITHUB_REPO` + workflow；Token 非空 | Actions 未配齐 |

**（3）local_ssh 硬拦**

- 本机项目路径必须是 git 仓  
- 私钥文件存在且像 `BEGIN … PRIVATE KEY`（防填公钥）  
- `DEPLOY_SSH_APP_PATH` 不能过浅（禁 `/`、`/www`、`/www/wwwroot`）  
- Host 不能写成 `IP:22`（端口另字段）；`restart_cmd` 须匹配白名单正则  

**（4）前端画卡**

`LocalDevDeployGateCard`：环境、ref、SSH 目标或 Actions 仓/workflow；有 blocker 则确认按钮灰掉。

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 零副作用 | prepare 只返回 `ready_for_confirm` / `can_trigger_ci` 等 |
| 配置快照 | `get_deploy_config()` ← env + `settings.json` |
| 可换项目 | `DEPLOY_SSH_SYNC_PAIRS` / `BUILD_STEPS` / `RSYNC_EXCLUDES`；留空用 monorepo 默认 |

---

### 2.3 confirm：再检门禁 + 90s 锁 + 分流执行器

**人话：** 点确认后再跑一遍 prepare，防止弹卡后有人关了开关还点确认；同一环境/ref 90 秒内连点第二次会判 duplicate。

```text
POST /api/local-dev/deploy/confirm
  body: { decision, env?, ref?, message? }
  → confirm_deploy(...)（deploy_confirm.py）
       ├─ cancel/skip → 直接返回未触发
       ├─ confirm/deploy/ok → 再 prepare_deploy；未 ready 则拒绝
       ├─ ref 安全：禁 ".."；须匹配 ^[A-Za-z0-9._/\-]+$
       ├─ 90s 幂等 key = user|env|ref|provider
       └─ 按 ci_provider：
            local_ssh → trigger_local_ssh_deploy → run_id=local-{12hex}
            github_actions → trigger_workflow_dispatch → GitHub run_id
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 先写入 `_RECENT` 再执行 | 避免两并行请求都穿过时间窗 |
| API 重启 | 进程内字典清空（可接受：最多再部署一次） |
| `ok=false` | 路由层 HTTP 400 + `detail=error` |

---

### 2.4 执行器 A：本机 SSH（国内预发主路径）

**人话：** 后台线程在临时目录挂 worktree → 按配置安全构建 → 只把 release 产物 rsync 到远端 → 可选重启 → HTTP 探活。状态在 **API 进程内存** `_JOBS`，前端用 `local-…` 的 run_id 轮询。

```text
trigger_local_ssh_deploy（deploy_local_ssh.py）
  → run_id = local- + token_hex(6)
  → 并发部署 > 1 → 拒绝
  → 线程 _execute_job：
       A1  tempfile + git worktree add --detach {ref}   # 不动 IDE 当前分支
       A2  BUILD_STEPS：resolve+relative_to；shell=False；超时 900s
       A3  按 SYNC_PAIRS 拷到 release/
       A4  ssh 探测 + rsync -az --delete（excludes 挡 .env/node_modules/…）
       A5  可选 RESTART_CMD（白名单正则，如 systemctl restart zr-aicoding-api）
       A6  probe_deploy_health(DEPLOY_HEALTH_URL)
       A7  status: queued → in_progress → completed(+success|failed)
  → finally：worktree remove + 删临时目录
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 为何 worktree | 部署读已提交快照，不 rsync 脏工作区 |
| `--delete` | 远端多余文件会删 → APP 路径绝不能浅（validate 已拦） |
| 探活 | 空 URL → skipped；非 2xx / 超时 → 整次失败（文件可能已同步，卡上写明） |
| 内存 Job | 重启 `./scripts/dev.sh` 后旧 `local-*` 查不到 |

---

### 2.5 执行器 B：GitHub Actions（备选）

**人话：** 适合 runner 能连上目标机的场景；国内轻量机常连不上。WorkBuddy 只负责 `workflow_dispatch` + 轮询，真正构建/SSH 在 runner 上。

```text
deploy_github.py
  → POST …/actions/workflows/{workflow}/dispatches
       Authorization: Bearer {DEPLOY_GITHUB_TOKEN}
       body: { ref, inputs: { environment: staging } }  # 键名可配
  → 期望 204；422（无 inputs）→ 降级再试仅 {ref}
  → 尽力取 run_id；失败不阻断触发结果
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 仓名 | `owner/name` 正则校验 |
| Token | 只服务端读，不回传前端明文 |
| 示例流水线 | `docs/写码与审码/示例-deploy-staging.yml` |

---

### 2.6 轮询 poll：过程条怎么更新？

**人话：** 确认卡定时问进度；成功或失败就停，不要终态后还死轮询。GitHub 暂不可达时返回可达的失败态，前端可继续试但不崩。

```text
LocalDevDeployGateCard
  → POST /api/local-dev/deploy/poll { run_id, workflow?, ref? }
       ├─ run_id 以 local- 开头或 provider=local_ssh
       │     → get_local_ssh_run_status（内存 _JOBS）
       └─ 否则 → 强制系统配置的 DEPLOY_GITHUB_REPO
                 → get_workflow_run_status / find_latest_workflow_run
  → done/success/failed/cancelled → stopPoll()（成功亦立刻停）
```

另：`GET /api/local-dev/deploy/status` 可供查看部署能力/配置摘要（与 prepare 门禁配合）。

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 超时 | `DEPLOY_POLL_TIMEOUT_SEC` / prepare 返回的 `poll_timeout_sec` |
| 防滥用 | poll 禁止客户端乱传别的 `repo` |
| 终态 | `markSucceeded` / 失败分支均 `stopPoll()` |

### 2.8 从头到尾一眼版

```text
【说话】looksLikeDeploy / rawLooksLikeDeploy
        ↓
【prepare】读开关/白名单/SSH或Token，画确认卡（零副作用）
        ↓
【confirm】再检门禁 + 90s 防双击
        ├─ local_ssh：worktree → 构建 → rsync → restart → 探活（_JOBS）
        └─ github_actions：dispatches → runner（GitHub run）
        ↓
【poll】直到成功/失败 → stopPoll；成功展示 visit_url
```

---

### 2.9 出问题时先查哪？

| 现象 | 人话原因 | 技术上先看 |
|------|----------|------------|
| 按钮总关 / 不能确认 | 总开关未保存；环境未授权 | `DEPLOY_ENABLED`、`settings.json`；`blocking_reasons` |
| Actions 卡在 SSH | 境外 runner 连国内机 | 改 `DEPLOY_CI_PROVIDER=local_ssh` |
| 探活失败 | 服务没起来、URL 错、防火墙 | `DEPLOY_HEALTH_URL`；`health_ok` / `log_tail` |
| 构建失败 | BUILD_STEPS 与项目不符 | 改设置或留空用默认 |
| 以为会自动上生产 | 概念混了 | `DEPLOY_ALLOW_PRODUCTION` 默认关；须人说并过白名单 |
| poll 一直转 | 终态未停或 API 重启丢 Job | 卡片是否 `stopPoll`；`local-*` 是否仍在内存 |

## 3. 技术及用法（速查）

| 模块 | 关键函数 | 干什么 |
|------|----------|--------|
| `chatIntent.js` | `looksLikeDeploy`、`rawLooksLikeDeploy` | 意图拦截 |
| `deploy_prepare.py` | `prepare_deploy` | 零副作用门禁 |
| `deploy_confirm.py` | `confirm_deploy` | 再检 + 90s 锁 + 分流 |

**配置族（设置页保存并热更新，或环境变量）：**

| 变量 | 含义 |
|------|------|
| `DEPLOY_ENABLED` | 总开关（默认关） |
| `DEPLOY_CI_PROVIDER` | 代码默认 `github_actions`；**江西现场推荐 `local_ssh`** |
| `DEPLOY_ENV_WHITELIST` / `DEPLOY_ALLOW_PRODUCTION` | 环境治理 |

| `DEPLOY_GITHUB_*` / `GITHUB_TOKEN` | Actions 仓、workflow、Token、inputs 键名 |
| `DEPLOY_HEALTH_URL` | 探活 / 成功后 visit |
| `DEPLOY_POLL_TIMEOUT_SEC` | 前端轮询上限 |

路径安全：sync/build cwd 必须落在项目根内；浅 APP 路径 + `rsync --delete` 会被拒。

## 4. 后续可以怎么做、不要做什么

**可以做：**

1. 生产二次确认 + 变更窗（P1-3e）  
2. 部署后「查数验收」接运维/查数 Tools（探活已有，查数仍可选）  
3. 国内可达 CI（CODING 等）再评估；当前国内预发主推 `local_ssh`  

**不要做：**

1. 模型直接拿私钥 ssh / 在 Prompt 里拼 rsync  
2. 默认自动生产；写码或提交成功后静默发版  
3. 把旧图谱站 `80/8000` 与 ERP 预发 `8090/8009` 混在同一条 restart 里  
4. 终态后继续无限 poll  

---

## 自测路径（验收）

1. `DEPLOY_ENABLED=1` 并**保存热更新**；江西现场将 `DEPLOY_CI_PROVIDER` 设为 `local_ssh`。  
2. 「部署到预发」→ 确认卡检查项全绿 → 确认 → 过程可见 → 探活 URL 可打开（如 `http://<IP>:8090/`）。  
3. 开关关掉后应不能真发版；连点确认应触发 90s duplicate。  
4. 成功或失败后轮询应停止；勿动旧图谱 `80/8000`，后端示例端口 `8009`。
