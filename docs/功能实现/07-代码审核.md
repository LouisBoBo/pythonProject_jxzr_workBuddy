# 07 · 代码审核

> **一句话**：你选**公开 Git 仓**或**本机 IDE 工程** → Agent 只读列文件、分批读源码 → 按 P0/P1/P2 出中文「代码审核报告」。  
> **不是**：写码改仓、自动 commit/push，也不是功能 09「提交今天的代码」那条批审门禁（范围与 API 都不同）。

---

## 1. 实现原理

### 1.1 我们到底实现了什么？

要对**整仓或整个 IDE 工作区**做结构化检查，输出带严重级别的中文报告（P0 阻断 / P1 重要 / P2 建议）。  
全程**只读**：不 `git commit`、不 Cursor 改文件、不部署。  
和写码车道**对等、互斥**：`workbuddy_lane=code_review` 时禁止出现 `:::cursor_dev_*`。

| 人做的 | 系统干的 | 达到的效果 |
|--------|----------|------------|
| 说「审核这个仓库 / 本机工程」 | 前端出源选择卡，确认后 SSE + `code_review` | 明确来源再开审 |
| 只贴一个裸 Git URL | `isBareGitRepoUrlMessage` **先澄清**写还是审 | 避免误开写码或误开审码 |
| 确认 Git URL / 分支 | 浅克隆 → 列业务源码 → 分批 `read_batch` | 过程区显示第几批 |
| 确认 IDE 工作区 | Bridge 配对 → 扩展列文件/读批次 | 本机工程不上传整仓到云 |
| 等终稿 | Skill 规定的 `## 🔍 代码审核报告` | P0/P1/P2 分级中文结论 |

**技术落点（整包）：**

| 层次 | 路径 |
|------|------|
| 意图 | `chatIntent.js`：`looksLikeCodeReview`、`looksLikeGitRepoReview`、`isBareGitRepoUrlMessage` |
| 前端卡 | `CodeReviewSourcePickCard`、`GitRepoPickCard`、`IdeWorkspacePickCard`；设置页 `IdeBridgePairCard` |
| 工具包 | `apps/agent/tools/ide_review/`（`tool.py`、`git_review.py`、`batch_plan.py`…） |
| Skills | `code-review`、`git-code-review`、`ide-code-review` |
| Bridge API | `apps/api/routes/ide_bridge.py`（前缀 `/api/ide/bridge`） |
| 扩展 | `apps/vscode-workbuddy-bridge/` |
| 开关 | `IDE_REVIEW_ENABLED`（控制是否注册 `request_ide_*`） |

### 1.2 两条取码来源，差在哪？

| | **Git 公开仓** | **本机 IDE** |
|--|----------------|--------------|
| 适用 | 有 HTTPS 地址、可浅克隆 | 工程在开发者电脑上 |
| 代码怎么到 Agent | `git_review` 克隆/镜像 → list → read_batch | 扩展读文件 → Bridge poll/result |
| 依赖 | 网络 + 公开仓（无私仓 token 则失败） | `IDE_REVIEW_ENABLED` + 扩展配对 |
| 禁区 | 审 Git 时不要调 `request_ide_*` 结案 | 审 IDE 时不要用 Git 标记/贴码路径冒充 |

**技术上怎么隔开（与写码 / 提交批）：**

| 点 | 实现 |
|----|------|
| 车道互斥 | `code_review` 禁 `:::cursor_dev_*`；`code_dev` 禁 `request_git_*` / `request_ide_*` |
| 裸 URL 澄清 | `isBareGitRepoUrlMessage`：几乎只有 URL → **不**自动开审/开写 |
| ≠ 提交批审 | 功能 09：`looksLikeLocalCommitBatch` → `/api/local-dev/commit-batch/*`；Skill `commit-batch-review` 非全仓报告 |
| 写码动作词 | `looksLikeGitRepoReview`：若 `hasCodeDevActionWords` → **false**，避免「改这个仓」误开审 |

### 1.3 为什么要「分批读」？

**人话：**  
一个仓库几千个文件，不能一次塞进模型上下文。  
先过滤业务源码，再按批读；用户在过程区看到「第 i / N 批」，最后汇总终稿。

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 业务源码过滤 | `local_files.is_functional_source_rel` | 丢掉无关静态/锁文件等 |
| 分批计划 | `batch_plan.py` | 线程级 list→batches（常见批次大小约 5，TTL 约 1h） |
| Git list/read | `request_git_list_source_files`、`request_git_read_batch` | 浅克隆缓存；多轮读 |
| IDE list/read | `request_ide_list_source_files`、`request_ide_read_batch` | Bridge 入队 → 扩展回传 |
| 报告增强 | `enrich.py` / `review.py` | 统一严重级别与结构 |

### 1.4 Skill 分层钉死了什么？

| Skill | 作用 |
|-------|------|
| `code-review` | 方法论：什么叫 P0/P1/P2、报告结构 |
| `git-code-review` | Git：list → read_batch → 终稿；`request_git_review` 仅抽样/兜底，**禁止**当唯一结案 |
| `ide-code-review` | IDE：同上 + Bridge 约定 |

| 约束 | 技术实现 |
|------|----------|
| 只读 | 工具拒绝在 `code_dev` lane 下当写码用；不 commit |
| Git 工具常挂 | `request_git_*` 始终注册 |
| IDE 工具开关 | 仅 `IDE_REVIEW_ENABLED=1` 时挂 `request_ide_*` |
| Bridge 安全 | 只读用户授权工作区；`bridge_token` 配对过期须重配 |

## 2. 实现流程（人话 + 技术点怎么落地）

> 每节先讲「人看到什么 / 为什么这样」，再给 **技术点表** 和调用链。

### 2.1 意图、澄清与源选择卡

**人话：** 说「审核 / code review」或「审这个 Git 仓」→ 先出「IDE vs Git」源选择（或直接 Git/IDE 确认卡）。若消息几乎只有一个仓库 URL、没说审也没说改 → **先问清楚**，不要擅自开审或开写。

```text
ChatView（在贴码之后）：
  !hasPastedSourceFence && isBareGitRepoUrlMessage(content)
    → 澄清卡片：要「写码」还是「审核」？
  !fence && (looksLikeGitRepoReview | looksLikeCodeReview)
    → pushCodeReviewSourcePick
         ├─ CodeReviewSourcePickCard（IDE vs Git）
         ├─ GitRepoPickCard（URL / ref）
         └─ IdeWorkspacePickCard（workspace_root）
              （Bridge 未配对 → 引导设置页 IdeBridgePairCard）
```

**技术点：**

| 点 | 函数 | 怎么做的 |
|----|------|----------|
| 审码意图 | `looksLikeCodeReview` | 审核/审查/code review 等关键词 |
| Git 审仓 | `looksLikeGitRepoReview` | review + URL 或「审仓库」；写码动作词则否 |
| 裸 URL | `isBareGitRepoUrlMessage` | 几乎仅 URL → 澄清，不自动开审 |
| URL 提取 | `extractGitRepoUrl` | 公开 HTTPS / `*.git` |

---

### 2.2 确认后进入 `code_review` 车道

**人话：** 点确认后，对话带上「Git 仓库已确认 / 本机工程已确认」标记和 `workbuddy_lane=code_review`，加载审码 Skills，并禁止写码围栏。

```text
beginIdeReviewStream / Git 确认流
  → POST /api/chat/stream
       page_context.workbuddy_lane = code_review
       消息含【Git仓库已确认】或【本机工程已确认】…
  → agent.py 车道块：
       加载 code-review + git-code-review / ide-code-review
       禁止 :::cursor_dev_*
       _REVIEW_LANE_BRIEF 注入
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 显式 lane 优先 | `page_context.workbuddy_lane` > 消息标记（`CODE_REVIEW_MARKERS`） |
| 工具拒写码 lane | `ide_review/tool.py`：在 `code_dev` 下拒绝审码工具滥用 |
| 与贴码互斥 | 有贴码围栏时 ChatView 先走功能 06 |

---

### 2.3 Git 仓审核链路

**人话：** 确认公开 HTTPS 仓与分支 → 浅克隆 → 列业务源码 → 多轮按批读 → 汇总 P0/P1/P2 报告 → 清临时目录。

```text
用户确认 GitRepoPickCard
  → Skill git-code-review
  → request_git_list_source_files(repo_url, ref)
       → git_review.py 浅克隆到临时/缓存目录
       → local_files.is_functional_source_rel 过滤
       → 返回相对路径列表
  → 多轮 request_git_read_batch(paths[] / batch_index)
       → batch_plan.py 控制每批文件数与字符上限
       → 过程区：「第 i/N 批」
  → 终稿：## 🔍 代码审核报告（P0/P1/P2）
  → 任务结束清理临时克隆（按实现清理策略）
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| list/read | `request_git_list_source_files`、`request_git_read_batch` | 主路径 |
| 抽样兜底 | `request_git_review` | **禁止**当作全仓唯一结案 |
| 私仓 | HTTPS 无 token 会失败 | 须公开仓或后续凭据扩展 |
| 字符上限 | `IDE_REVIEW_BATCH_MAX_CHARS` 等 | 防单批爆上下文 |

---

### 2.4 本机 IDE 审核链路

**人话：** 先装 `vscode-workbuddy-bridge` 并在设置页配对 → 确认工作区根 → Bridge 列文件、按批回传内容 → 同样出中文分级报告。

```text
前置：IdeBridgePairCard → bridge_token 存 bridge_store / bridge_token
  IDE_REVIEW_ENABLED=1 → 注册 request_ide_*；/api/ide/bridge/* 可用

确认 IdeWorkspacePickCard
  → Skill ide-code-review
  → request_ide_list_source_files(workspace_root)
       → routes/ide_bridge.py 入队
       → extension.js 本机列文件 → poll / result 回传
  → request_ide_read_batch(paths[])
       → 同上 Bridge 往返
  → 终稿：## 🔍 代码审核报告
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 开关 | `IDE_REVIEW_ENABLED` | 未开则无 IDE 工具 |
| 配对 | `bridge_token.py` / `bridge_store.py` | 过期须重配 |
| API | `/api/ide/bridge` register/heartbeat/poll/result/… | 任务队列式往返 |
| 可选 MCP | `IDE_REVIEW_MCP=1` | MCP provider vs mock（`review.py`） |

---

### 2.5 与提交批审（功能 09）对照

| 项目 | **全仓审码（本篇）** | 提交批审（功能 09） |
|------|----------------------|---------------------|
| 触发 | 「审核仓库 / 本机工程」 | `looksLikeLocalCommitBatch`（「提交今天的代码」） |
| API | `/api/chat/stream` + Agent | `/api/local-dev/commit-batch/*` |
| 范围 | 用户指定仓/工程 | 当日 Job `synced_files` ∩ git dirty |
| 之后 | **只出报告** | 还要 `git commit` + `push`（人确认） |
| Skill | `code-review` / `git-` / `ide-` | `commit-batch-review`（`disable-model-invocation`） |
| 模块 | `ide_review/tool.py` | `commit_gate.py` + `batch_commit.py` |

可共用部分 `enrich` 规则词典，但**路由完全分开**，不要把全仓报告当成提交门禁。

### 2.6 从头到尾一眼版 + 排查

```text
【意图】looksLikeCodeReview / looksLikeGitRepoReview
        （裸 URL → 先澄清写 vs 审）
        ↓
【选源】CodeReviewSourcePickCard → Git / IDE 确认卡
        ↓
【车道】workbuddy_lane=code_review（禁 cursor_dev 围栏）
        ↓
【取码】request_git_* 或 request_ide_* ：list → read_batch×N
        ↓
【终稿】## 🔍 代码审核报告（P0/P1/P2）
```

| 现象 | 人话原因 | 技术上先看 |
|------|----------|------------|
| 克隆失败 | 私仓/网络/URL 错 | HTTPS、权限、日志 |
| IDE pending 卡住 | 扩展没跑 / 未配对 | `IDE_REVIEW_ENABLED`；bridge poll；token |
| 同时弹写码卡 | lane 错成 `code_dev` | `page_context.workbuddy_lane`；是否出了 `:::cursor_dev_*` |
| 报告像贴码 | 误走 `paste_code` | 是否有大围栏被功能 06 截胡 |
| 以为会自动提交 | 概念混了 | 提交走功能 09 commit-batch，不是本篇 |

## 3. 技术及用法（速查）

| 模块 | 关键函数 / 组件 | 干什么 |
|------|-----------------|--------|
| `ide_review/tool.py` | `request_git_list_source_files`、`request_git_read_batch`、`request_ide_*` | Agent 只读工具入口 |
| `git_review.py` | 浅克隆 / 镜像 / list | Git 来源 |
| `batch_plan.py` | 线程级分批 | 控 token 与批次数 |
| `local_files.py` | `is_functional_source_rel` | 业务源码过滤 |
| `enrich.py` / `review.py` | 严重级别与报告结构 | 增强 |
| `bridge_store.py` / `bridge_token.py` | 配对与任务 | IDE Bridge |
| `routes/ide_bridge.py` | `/api/ide/bridge/*` | 扩展往返 |
| Skills | `code-review`、`git-code-review`、`ide-code-review` | 剧本 |
| 前端卡 | `CodeReviewSourcePickCard`、`GitRepoPickCard`、`IdeWorkspacePickCard`、`IdeBridgePairCard` | 选源与配对 |

**配置：**

| 变量 | 含义 |
|------|------|
| `IDE_REVIEW_ENABLED` | 是否注册 IDE 工具并启用 Bridge |
| `IDE_REVIEW_MCP` | 是否走 MCP provider |
| `IDE_REVIEW_BATCH_MAX_CHARS` | 单批字符上限（默认约 65536） |
| `IDE_GIT_REVIEW_FILE_LIMIT` | 抽样工具默认文件数上限 |

手册：[`../写码与审码/IDE代码审核开发者接入手册.md`](../写码与审码/IDE代码审核开发者接入手册.md)；**实现以本篇为准**。

## 4. 后续可以怎么做、不要做什么

**可以做：**

1. 报告结构化落库，方便「上次 P0 是否已修」  
2. 与提交批门禁对齐同一套严重级别词典（仍保持 API 分离）  
3. 私仓凭据扩展（显式设计，勿把 token 写进 prompt）  

**不要做：**

1. 审核过程中调用写码 propose / 自动改仓 / 自动 commit  
2. 一次读全仓无分批（token 与超时会爆；现有 batch 是有意的）  
3. 把功能 09 commit-batch 并进 `code_review` SSE 当「审完就提交」  
4. 裸 Git URL 不经澄清就自动开审或开写  

---

## 自测路径（验收）

1. Git：给可访问的公开 HTTPS 仓 → 确认卡 → 过程有分批 → 终稿带 P0/P1/P2。  
2. IDE：`IDE_REVIEW_ENABLED=1` 且配对成功 → 审一小目录 → 过程区有分批，终稿有报告标题。  
3. 只贴裸仓库 URL → 应先澄清「写还是审」，**不**直接开审。  
4. 同一句勿同时弹出写码确认卡（`code_review` 禁 `:::cursor_dev_*`）。  
5. 「提交今天的代码」→ 应走功能 09，不走本篇全仓报告。
