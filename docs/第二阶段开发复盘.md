## 1. 阶段目标与结果

**目标（产品锚点）：**  
让实施 / 运维在公司 MES/ERP 上，用自然语言完成日常查询与**受控变更**，过程可审计、结果可回看。  
明确不做：研发全自动（写代码 → 测 → 部署）。

**结果：**  
在一期可运行骨架上，补齐「谁在操作」与「导入必须人确认」，并落本地写操作审计；查询主链路保持可用。达到**功能验证可验收**，未按上线级做多机与业务签字。

| 维度 | 状态 |

| 产品方向锁定（实施/运维，非研发全自动） | ✅ |
| M0 ERP 登录 + token 透传 | ✅ |

## 3. 分里程碑回顾

### 3.1 M0 — ERP 登录

**做了什么**

- Web 登录页；未登录不可进对话
- `POST /api/auth/login` 代理 ERP 登录；`GET /api/auth/me`
- 对话 / 历史 / 上传等带 `Authorization: Bearer` + `X-User-Name`
- `platform_api` 请求级 token：工具调用走**当前用户** ERP 身份
- 开关：`AUTH_REQUIRED`（默认 true）

**验收要点**

- 未登录被拦；ERP 账号登录后侧栏有用户名；平台调用带该 token

---

### 3.2 M1 — 真场景（部分）

**已具备（多承接一期 + 联调）**

- 自然语言查生产计划、工单等主路径可用
- 实体目录 / Skills / 过程区展示继续服务查询体验

**未整包收口（本阶段不再扩）**

- 实施高频场景清单文档、实体守卫试点、M1 冒烟脚本等计划项未全部勾完
- 导出「实施能稳定找到文件」等体验项未单独验收

**结论：** M1 以「查询可验证」支撑二期演示即可，不作为本阶段完整里程碑关闭条件。

---

### 3.3 M2 — 敢写（受控导入 + 审计）

**做了什么**

| 项 | 说明 |
|----|------|
| 写工具清单 | `WRITE_TOOLS`：当前仅 `import_file_to_platform` |
| 确认中间件 | `MesWriteConfirmMiddleware`；挂起、只读预览、不调 ERP |
| API | `/api/writes/.../confirm|cancel`、pending、audit |
| Web | SSE `confirm` + `WriteConfirmCard`；确认/取消后卡片消失 |
| 正文 | 固定「文件预览摘要 + 表格」；去掉误导性「请再点确认」文案 |
| 审计 | `audit.jsonl`；含 user / thread / 文件 / 时间 / 结果 |
| 查导入人 | 工具 `query_write_audit` + 提示词指引 |
| 查询窗口 | 默认近 30 天 + 分页，避免全量扫 |
| 开关 | `REQUIRE_WRITE_CONFIRM`（默认 true，可一键关） |

**功能验证验收清单（已对齐）**

1. 查询仍正常、无确认卡
2. 导入先出确认卡，未确认不写 ERP
3. 取消无副作用；确认后可写入
4. 审计能查到人 / 时间 / 文件
5. `REQUIRE_WRITE_CONFIRM=false` 可回滚行为

**本阶段明确暂缓**

- 其它 ERP「更新类」写接口纳入确认
- 多 API 实例共享 `data/writes`
- 试点实施业务签字「敢用」

详见 [`M2写操作确认交付说明.md`](./M2写操作确认交付说明.md)。

## 5. 隐患与边界（功能验证够用，上线前再看）

1. **以确认卡 + 审计为准**：模型仍可能「嘴上说已导入」
2. **确认后 API 直执导入**，不走 LangGraph resume
3. **审计 / pending 在本地磁盘**，单机验证 OK；多机要共享存储或改库
4. **审计默认近 30 天**，不是全历史；更久需显式 `since` / `lookback_days`
5. **写确认范围目前只有导入文件**

回滚写确认：`.env` 设 `REQUIRE_WRITE_CONFIRM=false` 后重启 API。
