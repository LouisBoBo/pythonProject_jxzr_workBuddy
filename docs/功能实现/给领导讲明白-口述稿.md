# 给领导讲明白：ZR WorkBuddy 是怎么实现的（口述稿）

> 用途：领导问「你们这东西到底怎么做出来的」时，**照着说**。  
> 原则：少提文件名、少提框架名；用「谁在干活、人点哪里、机器干什么」讲清楚。  
> 日期：2026-08-26

---

## 开场 60 秒（先说这三句）

**第一句：它是什么**  
WorkBuddy 是挂在咱们现有 MES 上的**工作助手**：同一扇对话框里，能问工艺、查数据、审代码、改功能、提交、部署到预发。它**不是**再做一套 MES。

**第二句：怎么干活（最重要）**  
里面其实是**两拨人分工**：

1. **参谋**：大模型（DeepSeek 等）——听懂人话、查资料、给方案、写说明。  
2. **施工队**：专门的程序——真去查 MES、真改文件、真推送、真部署。  

参谋**不能**自己偷偷改生产库、改代码仓、发版；必须**人点确认卡**，施工队才动手。

**第三句：为什么要这样**  
避免「AI 嘴上说已经改好了，其实没改」或「AI 乱连服务器」。  
**人确认 → 程序执行 → 留痕迹。** 这就是我们的实现原则。

---

## 用一个生活比喻记住整盘棋

把 WorkBuddy 想成**厂里的总调度台**：

| 角色 | 对应什么 | 干什么 |
|------|----------|--------|
| 你（用户） | 厂长 / 工程师 | 说话下指令 |
| 对话框 | 调度台话筒 | 统一入口 |
| 大模型 | 懂行的参谋 | 听懂、解释、出主意 |
| 确认卡 | 「请签字」的单子 | 人点头才生效 |
| 工具程序 | 施工队 / 仓库员 | 查数、导入、改码、发版 |
| 系统配置 | 档案室 | 表结构、接口文档、账号、钥匙 |

领导若只问一句「怎么实现的」：  
> **「自然语言进对话框 → 参谋理解意图 → 危险动作弹确认单 → 专用程序去执行 → 结果回对话里。」**

## 十大功能：每个 30 秒怎么讲

### 1. PCB 专业对话

**怎么讲**：  
「问阻焊、阻抗、飞针这些，就是**问参谋**。它靠行业知识和我们写好的答疑规矩直接讲，**不查咱们厂实时数据库**，所以不会把科普说成『今天查到 32 单』。」

**别跟领导说**：Skill 名、prompt 路径。

---

### 2. MES 查数 / 导出 / 分析看板

**怎么讲**：  
「先在系统配置里挂上咱们厂的**接口说明书**和账号，系统生成『能查哪些业务对象』的目录。  
你在对话里问『今天急单有哪些』，参谋会叫**查数程序**真去打 MES 接口拿数；要导出就生成 Excel；要看板就算出图数据，页面用图表显示。  
接口没有的能力（比如某些追溯），我们规定**如实讲缺口**，不许编造。」

**一句话**：资料包定能查什么 → 对话问 → 程序打 MES → 表/图/文件回来。

---

### 3. 文件导入（受控写入）

**怎么讲**：  
「上传 Excel 说要导入，参谋只能**起草一张导入申请单**，列出导到哪、大概多少行。  
你点确认，**后台程序**才真正写入 MES；不点就永远不写。谁导过什么，有审计记录可查。」

**一句话**：AI 填单，人签字，程序入库。

---

### 4. MES 表结构摸底（「系统能干什么」）

**怎么讲**：  
「这和查实时数据不是一回事。  
摸底是读咱们上传的**表结构说明文档**，整理成：有哪些业务模块、常见流程串哪些表、和接口目录是否对得上，还能导出摸底报告。  
问『MES 有啥功能』走摸底；问『今天有多少工单』走查数。」

**一句话**：读说明书画地图，不是查库存。

---

### 5. API 接口健康分析

**怎么讲**：  
「把接口文档（Swagger）给它，或者导入网关错误日志。  
程序会建一张接口清单，在**安全的测试环境**里挨个探一下通不通，对照日志看哪些老出错，最后出一份**中文健康报告**。  
用来帮实施判断：文档靠不靠谱、哪条接口有病。」

**一句话**：体检接口文档和日志，不是改业务代码。

---

### 6. 粘贴代码分析

**怎么讲**：  
「工程师把一段代码贴进对话框问有没有坑，参谋**当场在聊天里**指出问题并给改法。  
它不打开你们整个工程，也不改仓库，就是『看这一段』。」

**一句话**：看纸上这段代码，不动整栋楼。

---

### 7. 代码审核

**怎么讲**：  
「要审整个仓库或本机工程时：  
- Git：按地址把代码**只读**拉下来分批看；  
- 本机：通过 VS Code 小插件把文件**只读**递给参谋。  
最后按严重程度出中文审核报告。**只看病开方，不开刀改代码。** 和写码是两条线，互不抢。」

**一句话**：只读体检报告，不自动改仓。

---

### 8. 写码改功能

**怎么讲**：  
「两段：  
第一段，参谋在对话里把需求问清楚，给出方案，弹出确认卡（改本机目录还是改 GitHub）。  
第二段，你确认后，交给 **Cursor 施工队**去真改文件——默认改本机工程，也可以改白名单的远程仓，推到工作分支。  
**没点确认，一行代码都不会动。** 改完也不会自动合到主分支、不会自动上生产。」

**一句话**：参谋出图纸，人签字，Cursor 施工；默认人工合主干。

---

### 9. 人触发提交

**怎么讲**：  
「改了很多轮之后，人说『提交今天的代码』。  
系统只把**这一批改过的文件**拿去过安全门禁（有严重问题就不让过），你填中文说明并确认，程序再 `git 提交` 并推到远程工作分支。  
推失败了可以只重试推送，不会乱重新交一遍。  
这不是写码结束自动提交，必须人喊一声。」

**一句话**：人喊提交 → 只审本批 → 签字 → 程序入库推送。

---

### 10. 人触发预发部署

**怎么讲**：  
「人说『部署到预发』，弹出确认卡。确认后有两种施工方式：  
- 常见：本机用钥匙（SSH）把编好的包同步到预发服务器并重启对应服务；  
- 或：触发 GitHub 上的发布流水线。  
成功了可以自动访问一下页面探活，把访问地址给你。  
总开关默认关着；**只做预发，不自动上生产。** AI 不会自己拿钥匙登服务器。」

**一句话**：人喊部署 → 签字 → 程序按配置发预发 → 探活给链接。

## 领导爱追问的 8 个问题（标准答）

**Q1：核心技术是什么？**  
> 对话理解用大模型；查数/摸底/审核编排用我们写的业务工具；改代码用 Cursor；提交和部署用我们自己的后台程序。不是一个模型包办。

**Q2：数据安不安全？会不会乱写生产？**  
> 查数用单独配置的 MES 接口账号；写入、改码、发版都要人点确认卡；部署默认只有预发白名单。模型不能直接当超级管理员。

**Q3：和 ChatGPT 网页版有什么区别？**  
> ChatGPT 主要是聊天。我们接了咱们厂的资料包和接口，能查真数、能受控导入、能改咱们工程并提交部署，全程在一个产品里留痕。

**Q4：换一家 MES 怎么办？**  
> 换资料包：表结构 + 接口文档 + 接口账号。不靠把厂名写死在程序里。换厂是配置，不是重做产品。

**Q5：写码会不会直接上生产？**  
> 不会。写码推工作分支；提交是人触发；部署默认预发。上生产要另开治理（二次确认等），现在刻意没做成一键生产。

**Q6：审核和写码会不会互相打架？**  
> 不会。前端会标「现在是审码还是写码」。审码只读；写码另走确认。提交批审也只审「这一批」，不是跟全仓审核混成一锅。

**Q7：为啥有时说查不到？**  
> 因为我们要求**诚实**：接口没有日期条件、没有 Lot 追溯，就明确说缺口。这对实施可信，比编个漂亮数字重要。

**Q8：你们落地到哪一步了？**  
> 试点水位：懂资料包、查数分析、运维话术、确认后写码、人触发提交、人触发预发部署——主链路已通。生产一键发布、自动回滚等还在缓开清单里。

## 现场演示时怎么串（2 分钟版）

1. 「这是统一对话框。」  
2. 问一句工艺 → 「这是参谋答疑，不查库。」  
3. 问一句今日工单 → 「这是真打 MES。」  
4. （可选）打开看板 → 「数算完，页面画图。」  
5. 提一句写码确认卡 → 「没签字不动代码。」  
6. 提一句提交 / 预发 → 「入库和发版也是人喊才动。」  

收尾金句：  
> **「AI 负责懂人话，程序负责干实事，人负责拍板。」**
