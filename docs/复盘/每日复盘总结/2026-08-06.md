业务样例：登录页「企业编码」下拉（固定选项、默认江西中软）在 `hebo` 落地并推送。

### 2.2 核心路由：写码 ↔ 审核对等互斥

- **问题**：UI 改登录页需求已选仓、锁技术栈后，却走进 Git 全仓审核（`request_git_*` / clone 超时）。
- **根因**：仅因对话里出现 GitHub 仓上下文，就被 `agent_wrapper` 强行导向审核；写码讨论仍走 Deep Agents 且模型误调审核工具。
- **原则（产品硬约束）**：写码与审核是**两条对等核心车道**，按用户真实意图分流，**没有优先级**；URL 单独出现 ≠ 审核。
- **处理**：
  - 前端意图：`looksLikeCodeDevIntent` / `looksLikeGitRepoReview` / `looksLikeCodeReview` 互斥；含改/写/实现等动词 → 写码。
  - 显式 `workbuddy_lane: code_dev | code_review` 写入 `page_context`。
  - `resolve_workbuddy_lane()`（`apps/api/agent_wrapper.py`）：写码注入禁审路由；审核走 list→batch。
  - `code_dev` 下硬拒 `request_git_*` / `request_ide_*`（`ide_review/tool.py`）。
  - Agent / Skill / `entity_catalog` 文案改为对等分支表述；写码流清理残留 `git_repo_url`。

### 2.3 完成态体验

- 流式摘要：`_merge_assistant_delta` 三元组 + 终稿 `replace_text`；多份 `## 已完成` 折叠。
