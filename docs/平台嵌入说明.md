# 平台嵌入说明（M3 / 优化 #5）

> 目标：从公司 MES/ERP **带登录身份打开助手**；请求可关联操作人；可选带上当前页业务上下文。  
> **不是**完整 SSO/OIDC；平台侧用已有 ERP `access_token` 即可起步。

---

## 推荐嵌入方式

| 方式 | 说明 | 适用 |
|------|------|------|
| **iframe** | 平台页内嵌助手 Web | 同域或已配 CORS |
| **新开页 / 新标签** | `window.open` 打开助手 URL | 实现最快 |

入口 URL（Web，默认 `http://127.0.0.1:5180`）：

```text
/?embed=1
  &access_token=<ERP_JWT>
  &username=<登录名>
  &user_id=<可选，JWT sub>
  &display_name=<可选，侧栏展示名>
  &entity=<可选，如 work-orders / production-plans>
  &plan_no=<可选>
  &order_no=<可选>
```

前端启动时会：

1. 用 `access_token` 写入 **sessionStorage** 会话（`from_embed`；关标签即失效，不进 localStorage）  
2. 展示名优先取 JWT claim，其次才用 URL 的 `username` / `display_name`  
3. 保存页上下文，对话时随请求带到 API  
4. **从地址栏去掉 token**（`history.replaceState`），降低泄露风险  
5. `embed=1` 时隐藏侧栏，以嵌入布局展示  

> 安全注意：勿把带真实 `access_token` 的完整 URL 发到聊天/工单；示例请用占位符。

示例（本地）：

```text
http://127.0.0.1:5180/?embed=1&access_token=<ERP_JWT>&username=admin&entity=work-orders&plan_no=PP-0801
```

---

## 身份与请求头

与独立登录一致：

| Header | 含义 |
|--------|------|
| `Authorization: Bearer <access_token>` | ERP JWT；调平台 API 时透传；**归属以 JWT `sub` 为准** |
| `X-User-Name` | 展示/兼容；JWT 已有用户名 claim 时服务端忽略此头覆盖 |

审计、写确认、出站调用日志已带 `username` / `user_id`（见 M2）。

普通登录页仍把会话放在 **localStorage**（刷新保持登录）；仅嵌入链路用 sessionStorage。

---

## 页上下文（可选）

对话请求体可带：

```json
{
  "message": "这个计划进度怎么样？",
  "thread_id": "session-admin-…",
  "page_context": {
    "entity": "production-plans",
    "plan_no": "PP-0801",
    "order_no": null,
    "source": "embed"
  }
}
```

Agent 会收到一行「平台上下文」前缀，便于直接查对应实体/单号，无需用户再说一遍。

---

## 会话与历史隔离

- 新会话 `thread_id` 含用户标识，避免全员共用 `default`  
- 历史列表 / 详情 / 删除按 **当前登录用户的 `user_id`（JWT sub）** 过滤；不能打开他人会话  
- 升级前「无主」旧会话：**不会**出现在列表里（避免多用户抢领）；若客户端仍持有该 `thread_id`，`get` / `save` 时可认领为自己的

## CORS

| 变量 | 默认 | 说明 |
|------|------|------|
| `CORS_ALLOW_ORIGINS` | `*` | 逗号分隔平台前端源；上线改为具体域名 |

示例：

```bash
CORS_ALLOW_ORIGINS=https://mes.example.com,http://127.0.0.1:5180
```

---

## 平台前端对接清单

1. 用户已在平台登录，能拿到 `access_token`  
2. 打开助手 URL，带上 token + username（+ 可选页上下文）  
3. iframe 时注意：父页与助手不同源时，cookie 无关（我们用 Bearer，不依赖第三方 cookie）  
4. 上线前收紧 `CORS_ALLOW_ORIGINS`  

---

## 验收

1. 带 `embed=1&access_token&username` 打开 → 无需再登登录页，侧栏隐藏  
2. 侧栏/顶栏显示用户名（或 `display_name`）  
3. 带 `plan_no` 问「这个计划怎样」→ 工具侧能对上生产计划  
4. 用户 A 的历史列表看不到用户 B 的会话  
5. `make smoke-embed-identity` 通过
