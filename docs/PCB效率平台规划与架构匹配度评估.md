## 总判

**不满足「规划全文可落地」的宣称；满足「可在此骨架上分阶段演进」的技术前提。**

当前仓库产品锚点是：**实施与运维在自有 MES/ERP 上，用自然语言完成日常查询与受控变更**。架构模式（大模型 + Skills + Tools + Middleware + 对话持久化）与规划中的「Skills + 连接器」一致，但规划里的 **RAG 知识中心、企业微信 SSO/岗位权限、通用连接器层、会话标签分享、全员文档生成** 等底座 **尚未建设**。

```text
[规划目标]  RAG + SSO/岗位权限 + 连接器层 + 可插拔 Skills + LLM
                │                    │              │
                │缺失                 │缺失           │已对齐
                ▼                    ▼              ▼
[当前仓库]  静态表结构文档      ERP 账密/JWT    Deep Agents Skills
            + schema 工具       嵌入 token     + Tools + entities
                               （非完整 SSO）   + MES 实体子集
                                               + 可选 IDE/Git 审核
```

## 一、底座层对照（规划第一节）

| 规划项 | 满足度 | 现状要点 |
|--------|--------|----------|
| 企业私有知识库 RAG | **不满足** | 无向量库/切片/ACL/版本/审核发布。仅有静态 Markdown（如 [`中软MES数据库表结构.md`](./中软MES数据库表结构.md)）+ schema 工具，不是 RAG |
| 账号与企业微信 SSO | **不满足** | ERP 账密 + JWT；嵌入可带 `access_token`（[`平台嵌入说明.md`](./平台嵌入说明.md)），明确非完整 SSO；无岗位 RBAC |
| 对话持久化 | **部分满足** | UI 历史库 + LangGraph checkpoint 已有（[`会话上下文管理说明.md`](./会话上下文管理说明.md)）；**无**标签/搜索/收藏/分享 |
| 外部 API 连接器 | **部分满足** | 有 ERP HTTP 实体（工单/生产计划 2 个）+ 可选 IDE Bridge/公开 Git；**无**统一 Connector 抽象，无 PM/报价库/工艺参数库/私有 Git 搜索提交 |
| 技能库 Skills | **基本满足（架构）** | Deep Agents progressive disclosure（[`DeepAgents-Skills使用指南.md`](./DeepAgents-Skills使用指南.md)）；Skill=剧本，Tool=执行；可启停靠代码/开关，未做成管理后台「权限+知识库绑定」配置面 |

**架构结论：** Skills/Tools/Middleware 分层可承载规划中的「可插拔技能」；**缺少独立 RAG 服务与 Connector 注册层**，这两块是规划 P0 与现状最大断层。

### 证据路径（底座）

| 能力 | 关键路径 |
|------|----------|
| Skills 挂载 | `apps/agent/agents/agent.py`（`create_deep_agent` + `skills=["/skills/"]`） |
| MES 实体白名单 | `apps/agent/tools/query_tool/entities.json` |
| ERP 登录 | `apps/api/routes/auth.py`、`docs/ERP登录对接说明.md` |
| 会话持久化 | `apps/agent/checkpoint_store.py`、`apps/api/routes/history.py` |
| IDE / 公开 Git | `apps/agent/tools/ide_review/`、`IDE_REVIEW_ENABLED` |

## 二、全员通用功能（规划第二节）

| 规划项 | 满足度 | 说明 |
|--------|--------|------|
| 内部知识库智能问答 + 引用跳转 | **不满足** | Skill `pcb-domain-chat` 为纯 LLM 领域聊，无公司资料检索与原文引用 |

## 三、业务部门 / 研发 / PCB 深度（规划第三～五节）

飞书文档中销售/实施/售后/产品及 PCB 知识层细则若未完整展开，按可见条目与仓库现状评估：

| 方向 | 与现状关系 |
|------|------------|
| 实施运维查工单/计划、受控导入、审计 | **强对齐当前产品**（实体查询 + HITL 写确认 + 审计） |
| 销售报价、售前方案、售后工单系统、项目管理 | **基本未覆盖**（缺连接器与 RAG） |
| 研发代码助手（规范/公共类增强） | **部分**：贴码分析 + IDE/Git 全仓审核已有；非「基于内部规范库生成」的 Copilot |
| 数据库辅助（表含义/关系） | **部分**：schema 文档工具强；业务 NL→可执行 SQL 对生产库 **无** |
| 接口文档生成 / BUG 库关联 / 测试用例表 | **弱/无**（有 API 健康分析与沙箱探活，非文档生成与历史 BUG RAG） |
| PCB 差异化（工艺/DFM/报价引擎） | **弱**：领域聊 Skill 有；无工艺/报价数据与 DFM 工具链 |

已落地相关 Skills（节选）：`query-mes-data`、`ops-query-playbook`、`import-export-data`、`analyze-mes-schema`、`analyze-api-health`、`pcb-domain-chat`、`paste-code-analyze`、`code-review`、`ide-code-review`、`git-code-review`。

## 四、技术架构「能不能撑住规划」

### 能复用、应延续

- **Deep Agents + Skills + Tools + Middleware**：与规划「技能 = Prompt + 工具 +（未来）知识绑定」同构；新能力优先加 Skill/Tool，而不是另起 Agent 框架。
- **FastAPI + Vue 对话壳 + SSE 过程面板 + HITL**：适合继续做全员入口与确认流。
- **ERP 身份透传 + 实体白名单**：可作为「连接器」第一类实现范式，扩展 `entities.json` / 专用 Tool。
- **可选 IDE/Git 车道**：覆盖研发侧「审代码」子集，与规划研发阶段部分重叠。

### 必须新增的架构层（否则规划 P0 落不了）

1. **RAG 子系统**：接入/切片/索引/权限过滤/引用回链；与 Agent 通过 `retrieve_knowledge` 类 Tool 挂接。
2. **身份与授权**：企业微信（或统一 IdP）+ 岗位/项目数据域；工具与知识检索统一鉴权。
3. **Connector 注册与配置**：工单/PM/报价/工艺参数/Git 私有仓等适配器，统一错误、超时、审计。
4. **会话元数据**：标签、全文检索、收藏、分享（在现有 history SQLite 上扩展即可起步）。
5. **技能运营面**（可后置）：启停、绑定知识库、按客户打包——规划有，现状仅有代码级 Skill。

### 产品方向冲突点（需产品决策，非纯技术）

[`第二阶段产品方向.md`](./第二阶段产品方向.md) 明确主用户是实施/运维、非目标含「通用企业 Agent」。若要承接本规划全文，需要 **产品锚点扩面**（全员效率平台），否则应把规划裁成「在现有微 WorkBuddy 上先做 RAG + 扩实体」，避免范围爆炸。

## 五、分阶段满足路径（路线，非本评估交付代码）

在不推倒 Deep Agents 骨架的前提下：

| 阶段 | 目标 | 相对现状 |
|------|------|----------|
| 近端 | 补 **RAG MVP**（Markdown/PDF 先）+ 回答带引用；扩 MES 实体；会话搜索 | 补规划 P0 最大洞，仍服务实施运维 |
| 中端 | 企业微信登录/岗位权限；工单/报价等 1～2 个强连接器；文档模板 Skill | 开始吃销售/售后场景 |
| 远端 | 私有 Git/规范库增强代码助手；BUG/用例库；PCB 工艺与报价差异化 | 规划第四～五节 |

---

## 六、给领导 / 规划方的一句话

> 当前框架的 **Skills + Tools + MES 连接 + 对话审计** 适合作为 PCB 内部 AI 平台的 **执行与编排内核**；但规划中的 **企业知识库 RAG、SSO/岗位权限、通用连接器、全员文档与会话协同** 尚未具备，因此 **不能说规划已满足**，只能说 **技术路线兼容，需按 P0 补齐底座后再谈第一阶段全员 MVP**。
