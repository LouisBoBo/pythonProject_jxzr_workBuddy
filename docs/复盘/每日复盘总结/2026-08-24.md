## 2. 今日做了什么

### 2.1 路由隔离：提交批审 vs 全量审码

| 维度 | 全量审码 | 提交批审（commit_batch） |
|------|----------|---------------------------|
| 触发 | 「审核工程」→ `workbuddy_lane=code_review` | 「提交今天的代码」→ local-dev API |
| 执行 | Deep Agents + ide/git/code-review Skill | `commit_gate` → 确认卡 → git |
| 输出 | `## 🔍 代码审核报告` | 确认卡：过程 + 结论（无报告终稿） |

文档：`写码后审码门禁与自动提交P1方案.md` §2.5、§3。

### 2.2 专用 Skill：`commit-batch-review`

- 路径：`apps/agent/skills/commit-batch-review/`（`disable-model-invocation: true`）
- 执行器：`apps/local_dev/commit_batch_review.py`（API 直调 LLM，只输出 JSON）
- 门禁链：Skill 批审 → ide_review 规则 → 本地正则；敏感路径始终先扫

### 2.3 本批文件范围收窄

- **待提交** = WorkBuddy 同步池 ∩ Git 待提交 ∩ **业务源码**（排除 `package.json`、lock、`vite.config.*`、`.css`、文档等）
- 确认卡展示：本批待提交 / 业务源码池 / 已排除非业务 N 个
- 实现：`git_commit.filter_pending_commit_files` + `ide_review.is_functional_source_rel`

### 2.4 提交确认卡与 push 重试

| 场景 | 行为 |
|------|------|
| 首次提交 + push 成功 | 正常 succeeded |
| push 网络超时（本地已 commit） | 任务 reopen 为 `awaiting_commit`，确认卡 **「重试推送」** |
| 任务已是 `succeeded` 再点重试 | `ensure_push_retry_confirmable` 自动 reopen（修「不在等待提交确认状态」） |
| 无新文件可说「提交今天的代码」 | **push-only** 确认卡，只 push 不 commit |
| `synced_files` 为空的重试 | `commit_synced_files` 跳过 commit，直接 push 当前分支 |

前端：`LocalDevCommitGateCard.vue`（过程步骤、push 重试按钮）；`ChatView.vue` 批提交流程。

### 已修（BUG / 安全）

| 现象 | 处理 |
|------|------|
| 提交批审误走全量审码 Skill / 出长报告 | 独立 `commit-batch-review` + API 直调 |
| 本批 24 文件 vs 实际 1 个登录页 | 同步池 ∩ Git 待提交 + 非业务文件过滤 |
| push 失败后任务 `succeeded`，无法重试 | reopen + 确认卡保留；API 允许 push 重试 |
| 重试时 `synced_files=[]` 不执行 push | `push=true` 且无文件 → 仅 push 当前分支 |
| reopen 未校验 job 归属 | `ensure_push_retry_confirmable` 增加 `user_id` |
| `finalize` 非法 status 静默 `pass` | 改为明确返回错误 |
| ide_review 测试与 Skill 优先级冲突 | 单测 mock 分离两条降级路径 |

### 仍存边界 / 技术债

1. **需重启 API** 后验收今日全部行为（push 重试、过滤、Skill 批审）。
2. 非网络类 push 失败（如权限/token）也会保留重试按钮，需用户自行换凭证。
3. 「今日同步池」仍汇总当天多条写码 job；若只想要**最后一次 job** 的文件，可再加收窄规则。
4. Skill 批审依赖 LLM Key；无 Key 时降级 ide_review / 正则。
5. 大改未 commit / 未推送 / 未发版。
