## 2. 今日做了什么

### 2.1 飞书写表主路径与任务口径

- 打通：自动化任务 → 查 MES 工单 → `bitable_json` → 飞书多维表格  
- 「每日生产数据」定为**工单明细留档**；禁止稼动率/日产/工序良率汇总段  
- 允许挂在**单张工单**上的良率/检验数；字段含工序、完工时间  

### 2.2 踩坑与处理

| 现象 | 根因 | 处理 |
|------|------|------|
| 任务「成功」但写表失败 | 摘要硬截 **4000** 字，`bitable_json` 被砍断 | 写表用完整回复；落库截断并保住 JSON；半截 JSON 可回收已完整行 |
| 表里多出良率汇总/稼动等 | Prompt 仍按日报/工序良率去查 | 改指令：只查工单；禁止非工单段 |
| 工单良率能不能加 | 禁得过死 | 允许工单级良率；禁止单独「工序良率」段 |
| 工序、完工时间列为空 | MES 有 `current_process` / `actual_end_time`；Agent 误判 filter 无声明=无字段 | 强制字段映射；写表前按工单号 **MES 回填** |
| 空列≠没建列 | JSON 未带键，飞书仍建了空列 | 回填后新写入行应有值；历史空行需重跑/清表 |

### 2.3 关键结论

1. 「查什么写什么」不能只靠 Prompt：防截断、防误判字段、必要时确定性回填。  
2. **筛参 ≠ 返回字段**：以 `records[].keys` 为准。  
3. 企微与写表解耦正确：一边失败不影响另一边。
