# 第二阶段开发计划（M1 → M4）

> 产品边界见 [`第二阶段产品方向.md`](./第二阶段产品方向.md)（已锁定）  
> 原则：承接现有 Monorepo，不推倒重来；第 3 条（研发全自动）不进本计划。

---

## 总览

| 里程碑 | 主题 | 主要改动面 |
|--------|------|------------|
| M0 | ERP 登录 | 登录页、`/api/auth/login`、token 透传到 ERP |
| M1 | 真场景（查 / 导） | `entities.json`、Skills、提示词、可选 Web 结果表 |
| M2 | 敢写（受控变更） | Middleware HITL、写工具确认、审计落盘 |
| M3 | 进平台 | 嵌入页 / token 身份、上下文透传 |
| M4 | 稳态 | 配置热加载、运维文档、部署与日志约定 |

建议顺序：**M0 →（M1 可部分已完成）→ M2 → M3 → M4**。

---

## M0 — ERP 登录（已实现）

详见 [`ERP登录对接说明.md`](./ERP登录对接说明.md)。

**验收：** 未登录无法进对话；用 ERP 账号登录后侧栏显示用户名；对话请求带 Bearer，平台调用用该 token。

## M1 — 真场景

**验收：** 实施用自然语言稳定完成 ≥3 个高频「查询」+ ≥1 个「导出」；生产计划 / 工单等实体选错率可接受。

### 任务清单

| ID | 任务 | 落点文件 | 说明 |
|----|------|----------|------|
| M1.1 | 梳理实施高频话术清单（文档） | `docs/实施高频场景清单.md`（新建） | 至少 5 条：查计划、查工单、按状态筛、导出、库存/订单若平台有则登记 |
| M1.2 | 按话术补齐 / 校对实体与别名 | [`apps/agent/tools/query_tool/entities.json`](../apps/agent/tools/query_tool/entities.json) | 与真实 ERP `path` 对齐；缺实体先 mock 或对接后登记 |
| M1.3 | 强化实体选择提示词规则 | [`apps/agent/tools/query_tool/entity_catalog.py`](../apps/agent/tools/query_tool/entity_catalog.py) | 「计划≠工单」等硬规则；别名最长匹配保持 |
| M1.4 | 试点开实体守卫 | [`apps/agent/middleware/entity_guard.py`](../apps/agent/middleware/entity_guard.py)、`.env.example` | 预发 `ENABLE_ENTITY_GUARD=true`；观察误杀再调 |
| M1.5 | 实施向 Skills | [`apps/agent/skills/`](../apps/agent/skills/) | 新增如 `ops-query-playbook`：异常工单、计划状态汇总话术；避免再 dump 全文到过程区 |
| M1.6 | 导出路径可预期 | [`apps/agent/tools/file_ops.py`](../apps/agent/tools/file_ops.py)、`config.py` | 文档写清导出目录；实施能找到文件 |
| M1.7 | （可选）查询结果表格式展示 | `apps/web/src/views/ChatView.vue` 等 | 对结构化 records 渲染简单表，不阻塞 M1 验收 |
| M1.8 | 冒烟用例脚本 | `scripts/smoke_m1.sh` 或 `docs` 内手工清单 | 固定 3～5 句中文 → 期望 entity / 有数据 |

### 完成定义（DoD）

- [ ] 场景清单成文并与业务对齐  
- [ ] 至少覆盖：生产计划、工单（及清单中另 1 个实体，若平台具备）  
- [ ] `ENABLE_ENTITY_GUARD` 在预发可开且误杀可解释  
- [ ] 实施同学按清单自测通过

## M2 — 敢写

**验收：** 导入 / 更新类操作必须「人确认后才执行」；审计能按会话查出写操作；试点环境实施敢点。

### 任务清单

| ID | 任务 | 落点文件 | 说明 |
|----|------|----------|------|
| M2.1 | 定义写操作工具清单 | 文档 + 代码常量 | 至少：`import_file_to_platform`；若有 update API 一并列入 |
| M2.2 | HITL / 确认中间件 | `apps/agent/middleware/` 新建（如 `write_confirm.py`） | 写工具调用前中断，返回待确认摘要；确认后继续 |
| M2.3 | API：确认 / 取消端点 | [`apps/api/routes/chat.py`](../apps/api/routes/chat.py) 或新建 `routes/confirm.py` | 与 thread_id、pending action id 绑定 |
| M2.4 | Web：确认卡片 | `apps/web` | 展示将写入的实体、行数、样例；确认 / 取消按钮 |
| M2.5 | 审计落盘可查 | [`apps/agent/middleware/audit_tools.py`](../apps/agent/middleware/audit_tools.py)、`data/` 或 SQLite | 现仅 logger → 增加结构化文件/表：`user/thread/tool/args/time/result` |
| M2.6 | 审计查询 API（只读） | `apps/api/routes/` | 运维按 thread 或时间查写操作 |
| M2.7 | 环境开关 | `.env.example` | 如 `REQUIRE_WRITE_CONFIRM=true`（默认 true） |

### 完成定义（DoD）

- [ ] 未确认时写工具不会改平台数据  
- [ ] 确认后一次导入可成功，取消无副作用  
- [ ] 审计记录含会话与工具参数摘要  
- [ ] 试点实施签字「敢用」

## M3 — 进平台

**验收：** 从公司平台入口打开助手；请求带操作者身份；历史/审计能关联到人（不仅是 `thread_id=default`）。

### 任务清单

| ID | 任务 | 落点文件 | 说明 |
|----|------|----------|------|
| M3.1 | 嵌入方案选型落地 | `docs/平台嵌入说明.md`（新建） | 默认：**iframe / 新开页 + URL 参数**（实现成本低）；与平台前端约定入口 |
| M3.2 | 身份透传 | [`apps/api`](../apps/api/)、[`apps/web`](../apps/web/) | Header 或 query：`user_id` / `display_name` / 可选签名 token；API 校验（共享密钥即可起步） |
| M3.3 | 会话绑定用户 | [`apps/api/routes/history.py`](../apps/api/routes/history.py)、chat 请求体 | `thread_id` 与 `user_id` 入库；禁止全员共用 default |
| M3.4 | 审计带上 user | audit middleware + API | 与 M2.5 字段对齐 |
| M3.5 | 上下文透传（可选） | chat 请求 | 如当前页 `entity`、选中 `plan_no`，写入 system 附加上下文 |
| M3.6 | CORS / 域名 | `apps/api/main.py` | 收紧为公司平台域名（替换 `*`） |

### 完成定义（DoD）

- [ ] 平台菜单可打开助手  
- [ ] 同一浏览器两人会话互不串、审计能区分人  
- [ ] 嵌入说明文档可供前端同事对接

## M4 — 稳态

**验收：** 运维按文档可独立启停、看日志、改实体配置；配置变更成本可接受。

### 任务清单

| ID | 任务 | 落点文件 | 说明 |
|----|------|----------|------|
| M4.1 | 实体目录热加载或 reload API | `entity_catalog.py`、`apps/api` | 改 `entities.json` 不必整进程盲重启用；或提供「重载目录」管理接口 |
| M4.2 | 结构化日志约定 | 审计 + uvicorn | 日志路径、级别、轮转写进运维文档 |
| M4.3 | 运维手册 | `docs/运维手册.md`（新建） | 启停、`.env`、健康检查、对接 ERP、常见故障（402、实体不生效、导出找不到） |
| M4.4 | 部署清单 | `docker-compose.yml`、README | 预发/生产差异：`MES_RELOAD`、密钥、CORS、ERP URL |
| M4.5 | （小步）过程区噪音 | ProcessPanel / agent_wrapper | 默认折叠 `read_file` 技能步；不重做思考流 |
| M4.6 | 回归清单 | `docs` 或脚本 | M1～M3 关键路径回归 |

### 完成定义（DoD）

- [ ] 运维同学按手册完成一次独立部署演练  
- [ ] 实体增补流程 ≤「改 JSON + 重载/重启」且有文档  
- [ ] 无未文档化的「只有开发知道」的开关  

---

## 明确排除（本计划外）

- 自动写平台业务代码 / 自动测 / 自动部署流水线  
- 多租户 SaaS、通用 Agent 市场  
- 大改处理过程为 Cursor 级思考流（仅 M4.5 小步）  

---

## 建议排期粒度（供内部填日期）

| 里程碑 | 量级（人周，示意） | 依赖 |
|--------|-------------------|------|
| M1 | 1～2 | ERP 可联调、场景清单有业务输入 |
| M2 | 2～3 | M1；需定 HITL UX |
| M3 | 1～2 | M2；需平台前端给入口 |
| M4 | 1 | M1～M3 基本完成 |

---

## 开工顺序（开发执行时）

1. 建 `docs/实施高频场景清单.md`，与实施对齐后冻结 M1 范围  
2. 改 `entities.json` + Skills + 预发开 entity guard  
3. 再开 M2 HITL（不要与 M1 大范围并行）  
4. M3 与平台前端对齐嵌入后再动 CORS/身份  
5. M4 收尾文档与热加载
