# 03 · 文件导入与受控写入

> **一句话**：上传 CSV/Excel → 模型**提议**导入 → Middleware 挂 pending + 预览 → 人点确认卡 → API 用**同一段** `import_file_to_platform` 真写入 MES。  
> **不是**：模型回复「已导入」就算写进库；确认后也**不再**让模型二次 tool_call 当执行。

---

## 1. 实现原理

### 1.1 我们到底实现了什么？

往 MES 写数据 = 生产数据变更。若模型说完就真写，用户可能没看清目标实体、行数、样例行，事后也说不清是谁干的。

所以采用 **HITL**：提议和执行分开。

| 人配的 / 人点的 | 系统干的 | 达到的效果 |
|----------------|----------|------------|
| 上传文件 +「导入某某实体」 | 模型发起 `import_file_to_platform` | 表达意图 |
| （自动） | `WriteConfirmMiddleware` 拦截 → pending + 只读预览 | **未确认前 MES 无写入** |
| 确认卡点确认 / 取消 | `POST .../confirm` 或 `.../cancel` | 确认后 API 直执；取消不写 |
| （事后） | `write_store` 审计 | 可查谁导了什么 |

**技术落点（整包）：**

| 层次 | 路径 |
|------|------|
| 上传 | `POST /api/upload`（`routes/chat.py`）→ `DATA_DIR/uploads/...` |
| Skill | `apps/agent/skills/import-export-data/SKILL.md` |
| 写工具 | `tools/file_ops.import_file_to_platform` |
| 写清单 | `middleware/write_tools.py`：`WRITE_TOOLS = {import_file_to_platform}` |
| 拦截 | `middleware/write_confirm.py`：`WriteConfirmMiddleware` |
| Pending | `middleware/write_store.py` → `data/writes/pending/` |
| 确认 API | `apps/api/routes/writes.py`：`/api/writes/actions/{id}/confirm\|cancel` |
| 前端 | `WriteConfirmCard.vue`、`api.js` 的 `confirmWrite` / `cancelWrite` |

### 1.2 和「查数 / 模型嘴上说完」差在哪？

| | **读（查数）** | **写提议（本篇）** | **确认后执行** |
|--|----------------|--------------------|----------------|
| Tool | `query_platform_data` 等 | `import_file_to_platform` | 同名函数，API 直调 |
| 改 MES | 否 | **否**（被 Middleware 拦住） | **是** |
| 确认卡 | 无 | 弹出 | 已确认 |

**技术上怎么隔开：**

| 点 | 实现 |
|----|------|
| 仅写工具进集合 | `WRITE_TOOLS` 目前**只有** `import_file_to_platform`（导出不算写） |
| 剥离伪造参数 | Middleware 丢掉模型伪造的 `_write_confirmed` / `_action_id` |
| 执行权在 API | `writes.py` → `_execute_write` → **同一** `import_file_to_platform` |
| 开关 | `REQUIRE_WRITE_CONFIRM` 默认 true；关仅适合本地调试，**不建议生产关** |

### 1.3 为什么确认后还要跑「同一段」导入函数？

**人话：**  
预览和真导入必须同一套解析/行数校验/HTTP，否则「卡上看着 10 行，实际灌了别的」。确认 API 认领 pending 后直接调该函数，不经过模型再编一次参数。

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 预览 | `_preview_import` → `preview_file` | 只读前几行，**不**调 MES 写接口 |
| 挂单 | `create_pending_action` | 落盘 `data/writes/pending/{action_id}.json` |
| 认领 | `claim_action` | pending → executing，防双击 |
| 真写 | `import_file_to_platform` | 校验 `MAX_IMPORT_ROWS` 后调 MES |
| TTL | `WRITE_CONFIRM_TTL_SEC` | 默认 1800s，过期 pending 失效 |

### 1.4 安全上钉死了什么？

| 约束 | 技术实现 |
|------|----------|
| 人未确认不写 MES | `WriteConfirmMiddleware` + 默认 `REQUIRE_WRITE_CONFIRM` |
| 只能确认自己的单 | `_assert_owner(user_id)` |
| 行数上限 | `MAX_IMPORT_ROWS`（导入函数内校验） |
| 路径不穿越 | `upload_paths`：上传落在 `DATA_DIR` 内 |
| 审计可查 | confirm/cancel 写 store；`GET /api/writes/audit` |

## 2. 实现流程（人话 + 技术点怎么落地）

> 核心：**模型只提议，Middleware 挂单，用户确认后 API 直执。**

### 2.1 人怎么把文件送进对话？

**人话：** 在对话里上传附件，或先上传再说明「导入到某某」。文件进服务器用户目录，路径经校验，防止 `../` 跑出数据目录。

```text
POST /api/upload（chat.py）
  → 存 DATA_DIR/uploads/{user}/{uuid}_{filename}
  → upload_paths 校验路径在 DATA_DIR 内
  → 返回相对路径 → messages.attachments
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 鉴权 | 上传需登录 |
| 路径安全 | resolve + 相对 `DATA_DIR` 校验 |

---

### 2.2 模型提议时，Middleware 怎么拦住？

**人话：** 你说「把这份 Excel 导入物料主数据」后，会出现确认卡和预览，**此时 MES 还没有任何新数据**。过程条里是「待确认」，不是「已导入成功」。

```text
用户话术 + Skill import-export-data
  → SSE → 模型 tool_call: import_file_to_platform(file_path, entity, ...)

WriteConfirmMiddleware.wrap_tool_call()（write_confirm.py）
  IF tool.name in WRITE_TOOLS:          # 仅 import_file_to_platform
    1. 剥离伪造的 _write_confirmed / _action_id
    2. _preview_import() → preview_file()（只读预览）
    3. create_pending_action() → data/writes/pending/{action_id}.json
    4. 返回 ToolMessage（含 __write_confirm__ + action_id）
    不调用真实写 MES handler
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 是否拦截 | `REQUIRE_WRITE_CONFIRM` | 默认 true；中间件组装见 `middleware/__init__.py` |
| 写集合 | `WRITE_TOOLS` | 仅 `import_file_to_platform` |
| 标记 | `WRITE_CONFIRM_MARKER`（`__write_confirm__`） | 供 wrapper 识别推 SSE |
| TTL | `WRITE_CONFIRM_TTL_SEC` | pending 过期 |

---

### 2.3 确认卡怎么到前端？

**人话：** 聊天气泡旁（或消息内）出现确认卡：目标实体、行数、样例行。点取消则不作废业务数据（本来就没写）；点确认才进入下一步。

```text
agent_wrapper 提取 write confirm
  → SSE { type: "confirm", action_id, preview, entity, ... }
  → WriteConfirmCard.vue
  → 用户未点确认前：MES 侧无写入
```

**技术点：**

| 点 | 怎么做的 |
|----|----------|
| 前端 API | `confirmWrite` / `cancelWrite`（`api.js`） |
| 展示 | 行数样例、目标实体；避免把「待确认」文案做成「已成功」 |

---

### 2.4 人点确认后，API 怎么直执？

**人话：** 点确认后，后端认领这张单、用保存的参数调用同一导入函数、写审计。失败会在状态/审计里留下痕迹，而不是假装成功。

```text
POST /api/writes/actions/{action_id}/confirm（writes.py）
  1. _assert_owner(user_id)
  2. claim_action()          # pending → executing
  3. _execute_write()
       → import_file_to_platform(...)   # 真调 MES HTTP
  4. mark_action(confirmed | failed)
  5. 审计可查 GET /api/writes/audit

取消：
POST /api/writes/actions/{action_id}/cancel
  → pending 标记 cancelled，不执行
```

**技术点：**

| 点 | 函数 / 模块 | 怎么做的 |
|----|-------------|----------|
| 防假确认 | confirm 路由 | **不再**让模型二次 tool_call |
| 行数 | `import_file_to_platform` | 超过 `MAX_IMPORT_ROWS` 直接错误返回 |
| 双击 | `claim_action` | 原子认领，避免并行执行两次 |

---

### 2.5 和读操作一眼对照

| Tool | 改 MES | 确认卡 |
|------|--------|--------|
| `query_platform_data` | 否 | 无 |
| `import_file_to_platform`（提议，经 Middleware） | 否 | 弹出 |
| `import_file_to_platform`（confirm 后 API） | **是** | 已确认 |
| `export_platform_data` | 否（只写本地导出目录） | 无（不在 `WRITE_TOOLS`） |

---

### 2.6 出问题时先查哪？

| 现象 | 人话原因 | 技术上先看 |
|------|----------|------------|
| 没弹确认卡 | 开关关了或中间件未加载 | `REQUIRE_WRITE_CONFIRM`；`build_custom_middleware` |
| 确认后仍无数据 | MES 写接口失败 | audit；MES 4xx/日志 |
| 403 owner | 换用户登录 | action 绑定的 `user_id` |
| 提示行数过大 | 超上限 | `MAX_IMPORT_ROWS` |
| 卡过期 | 拖太久 | `WRITE_CONFIRM_TTL_SEC`；重新提议 |

## 3. 技术及用法（速查）

| 模块 | 关键函数 | 干什么 |
|------|----------|--------|
| `write_confirm.py` | `WriteConfirmMiddleware`、预览/挂单逻辑 | 拦截写工具 |
| `write_tools.py` | `WRITE_TOOLS`、`WRITE_CONFIRM_MARKER` | 声明哪些算「写」 |
| `write_store.py` | `create_pending_action`、`claim_action`、审计读写 | pending / 审计落盘 |
| `file_ops.py` | `import_file_to_platform`、`preview_file` | 预览与真导入 |
| `routes/writes.py` | confirm / cancel / pending / audit | 人机确认 API |
| `routes/chat.py` | `POST /api/upload` | 上传 |
| Skill `import-export-data` | （剧本） | 何时导入、如何描述预览 |
| 前端 | `WriteConfirmCard.vue`、`confirmWrite` / `cancelWrite` | UI |

**配置：**

| 变量 | 含义 |
|------|------|
| `REQUIRE_WRITE_CONFIRM` | 是否拦截写工具（默认 true） |
| `WRITE_CONFIRM_TTL_SEC` | pending 过期秒数（默认 1800） |
| `MAX_IMPORT_ROWS` | 单次导入行数上限 |

关联：[`../产品规划/M2写操作确认交付说明.md`](../产品规划/M2写操作确认交付说明.md)。

## 4. 后续可以怎么做、不要做什么

**可以做：**

1. 更多写工具纳入同一 `WRITE_TOOLS` + 确认卡体验  
2. 导入失败按行号回显、部分成功策略（需业务先定规则）  

**不要做：**

1. 生产关闭 `REQUIRE_WRITE_CONFIRM`  
2. 让模型在确认后再「自己决定」调一次写工具当执行  
3. 预览走一套解析、确认后再走另一套互不一致的导入逻辑  

---

## 自测路径（验收）

1. 上传小 CSV → 说导入某实体。  
2. **必须**出现确认卡；未点确认 MES 无新数据。  
3. 点确认 → 成功反馈；`GET /api/writes/audit`（或页面审计）能查到本次。  
4. 点取消 → 无写入；pending 为 cancelled。  
5. 超大文件 / 超 `MAX_IMPORT_ROWS` → 明确错误，不静默截断当成功。
