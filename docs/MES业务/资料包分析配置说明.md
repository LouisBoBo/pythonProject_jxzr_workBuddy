# 资料包分析配置说明（换平台通用）

> 数据分析**不写死**某一套 MES 的实体 id、路径或状态值。  
> 换平台：新建/切换资料包 → 导入 OpenAPI + 按需覆盖配置 → 同一套工具即可用。

## 配置优先级

```text
内置 metrics_default.json（通用口径）
  + metric_packs（仅当资料包声明，如 pcb）
  + mes_profiles/{平台}/metrics.json（按 id 覆盖/停用）
```

```text
内置 group_by / brief 默认
  ← profile.json.analysis / metric_packs
  ← analysis.json（同目录，可整段覆盖）
```

## 必做（每个平台）

1. **系统配置 → MES 接入**：平台名称、表结构、OpenAPI、接口账号  
2. 确认 `list_platform_entities` 非空  

## 建议（贴合该厂口径）

### `metric_packs`（可选行业包）

资料包 `analysis.json` 声明 `"metric_packs": ["pcb"]` 后加载内置 `metric_packs/pcb.json`。

PCB 包当前口径（均靠 **entity_hints**，不写死实体 id）：

| id | 用途 | 字段角色（可选） |
|----|------|------------------|
| `daily-output` | 当日/日产出；趋势优先 `analyze_time_trend` | `time_field_hints` / `value_field_hints` |
| `daily-output-overview` | 看板/概览类产出 | category/value hints |
| `aoi-fail-topn` | 检测/缺陷码不良 Top | `category_field_hints`（缺陷码）/ value |
| `scrap-rate` | 报废/良率 | `rate_field_hints` 或 **分子+分母**；缺分母只报件数 |
| `wip-by-process` | 工序在制 | 无工序维接口则绑不上 |

报废率规则：`prefer_rate_field_else_ratio_if_both_else_count_only` —— **禁止**只有分子就口算率。

```json
{
  "version": 1,
  "metrics": [
    {
      "id": "wip",
      "label": "在制",
      "entity_hints": ["工单", "制造订单", "MO"],
      "aliases": ["在制", "WIP"],
      "definition": "本厂：状态=生产中",
      "include_in_brief": true,
      "clauses": [
        {
          "field_role": "status",
          "field_hints": ["Status", "状态"],
          "include_values": ["生产中", "Producing"]
        }
      ]
    },
    { "id": "aoi-fail-topn", "disabled": true }
  ]
}
```

- **覆盖**：同 `id` 整段替换内置  
- **停用**：`{ "id": "xxx", "disabled": true }`  
- **禁止**写死其它厂的实体英文 id（如目录没有就不要写 `work-orders`）

### `analysis.json`（分组与简报）

```json
{
  "group_by_labels": ["状态", "优先级", "车间"],
  "brief_metric_ids": ["wip", "urgent-unfinished", "completed-today"],
  "brief_metric_limit": 4,
  "metric_packs": ["pcb"]
}
```

| 字段 | 含义 |
|------|------|
| `group_by_labels` | 分析简报尝试的分组「角色名」；记录里没有对应列则跳过 |
| `brief_metric_ids` | 简报优先跑的口径 id |
| `metric_packs` | 加载内置可选包（当前：`pcb`） |
| `dashboard_template` | 默认看板 id（内置 `pcb_ops`；可用资料包 `dashboards/{id}.json` 覆盖） |
| `time_field_hints` | **时间维**：当日/趋势口径优先尝试的日期字段名（资料包可覆盖）；绑不上筛参时强制 caveat，禁止说「今天完工了 N」 |
| `value_labels` | 枚举英文码 → 中文展示（如 `pending`→`待开工`）；**仅影响表格/图表类目**，查数 filters 仍传 API 英文码 |
| `analysis_demos` | 可选：覆盖/禁用看板编排，如 `{ "pcb-ops-board": { "enabled": false } }` |

也可把 `metric_packs` / `analysis` 写在 `profile.json` 里。

### 汇总 / 聚合（M1，可选）

`summarize_platform_data` 默认对**本页返回记录**分组，并在结果里带 `caveats`（本页≠全库）。  

若现场有真正的分组/统计接口，可在 **`entities.json` 对应实体**上声明（不写死 path）：

```json
{
  "id": "work-orders",
  "path": "/api/work-orders",
  "aggregate": {
    "path": "/api/work-orders/stats",
    "group_param": "groupBy",
    "method": "GET"
  }
}
```

或：

```json
"paths": { "aggregate": "/api/work-orders/stats" },
"aggregate_param": "groupBy"
```

解析失败或接口报错时**自动降级**为本页汇总，并追加 caveat；不影响 `query_platform_data` / 出图。

### 趋势折线（M1-4）

对话「最近 7 天产量/完工趋势」→ `analyze_time_trend`：

- 默认 `grain=day`、`window=7`；可改 `week`
- 时间列：入参 `time_field` → `analysis.time_field_hints` → 记录列启发式
- 数值：不传 `value_field` 按条数；传入则求和（如 `actual_qty`）
- 无日期列：**不出假趋势**，返回 error + caveat
- 默认自动折线图；口径仍是本页分桶，非全库时间序列

### PCB 运营看板编排（可选）

对话说「打开PCB运营看板」→ `run_analysis_demo`（简报 → 多图看板 → 急单样例）。  
普通「值班简报 / 产线日报」仍走 `run_ops_scene`，不受影响。

- 内置：`demo_playbooks/pcb_ops_board.json`
- 资料包覆盖：`demos/pcb_ops_board.json`
- 关闭：`analysis.json` → `"analysis_demos": { "pcb-ops-board": { "enabled": false } }`

### 运营看板（可选）

对话「打开 PCB/品质运营看板」→ `render_analysis_dashboard`。  
内置模板：`apps/agent/tools/query_tool/dashboard_templates/pcb_ops.json`（按 hints 绑定，不写死实体 id）。  
卡序：**K1 工序在制（报表）→ K2 急单 → K3 设备产量 → K4 不良 Top → K5 工序良率 → Lot 缺口**。  
资料包可放 `dashboards/pcb_ops.json` 覆盖；缺接口的卡会标缺口，不影响其它查数。

### `ops_scenes.json`

按 id 覆盖场景别名、是否 `include_chart`；`disabled: true` 可关掉某场景。
