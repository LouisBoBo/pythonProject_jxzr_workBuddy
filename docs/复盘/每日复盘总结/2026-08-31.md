## 2. 今日做了什么

### 2.1 安全与健壮性自检（代码侧）

围绕近期部署确认卡、自动化执行器、AI 改写指令等改动做了审计并落地修复：

| 级别 | 问题 | 处理 |
|------|------|------|
| 高 | 执行器未再校验 `cwds`；`repo_digest` 可扫任意路径 | 执行前 `_sanitize_cwds`；digest 限制仓库根内 |
| 高/中 | `runtime.json` 崩溃后僵尸锁永久占住 | 超过 6h 自动回收 + 单测 |
| 中 | 部署终态后仍可能被状态翻转拉起轮询 | ChatView 终态后忽略一切后续 poll |
| 中 | 软失败停表未通知父组件；HTTP 挂死 | 发 `unreachable`；45s 超时 + AbortController |
| 中 | `visit_url` 可进非 http(s) | 卡片与正文仅允许 `http(s):` |
| 中 | 坏 RRULE / 单任务异常拖垮整 tick | BYHOUR 容错；调度 per-task try |
| 中 | `rrule` / 改写 API / `DEPLOY_HEALTH_URL` 校验不足 | max_length、超时、通用 502、`assert_http_url_allowed` |

相关单测 9 条通过。残留：多 worker 文件锁、自动化硬工具白名单、任务按用户隔离等（未改）。

### 2.2 插件化方案（设计侧，未写实现）

- 诉求：整功能（Agent + API + Web）像 DSH 插件一样热插拔、只更一个包。  
- 约束：主 harness 仍 Deep Agents，**不**迁 Cordis/DSH。  
- 文档落盘：`docs/插件/`（README、架构设计方案、plugin.yaml 模板）；仓库根 `plugins/` 仅留实现阶段代码包说明。  
- **§10 成本与价值评估**：完整热插拔约 11–15 人周，对当前桌面单用户体量 ROI 偏弱；**默认推荐路线 B**（模块化 + 启动注册 + 重启生效，约 4–6 人周）。

### 2.4 关键结论

1. 「能跑」不等于「能停」：部署轮询、僵尸锁、脏 cwd 都是收口类问题，要在设计 IO/状态机时默认做完。  
2. 插件化叙事有价值，但 **热插拔 ≠ 模块化**；现阶段优先边界清晰与分包，不必付 DSH 级热更全价。  
3. 设计文档应落在 `docs/`；`plugins/` 留给运行时包，避免文档与代码目录混用。
