# 实施高频场景清单（查 / 导）

> 对齐优化项 **#4**：实体与高频话术。  
> 演示实体以 `entities.json` 为准；当前可操作：**工单**、**生产计划**。  
> 库存 / 订单等真实 ERP 资源**未对接**前只登记话术，不进通用 CRUD 目录（避免 `/api/v1/...` 误打）。

---

## 已覆盖（可对话验收）

| # | 用户说法（示例） | 期望实体 | 期望工具行为 | 备注 |
|---|------------------|----------|--------------|------|
| 1 | 查一下工单 / 看看生产工单 / 有哪些派工单 | `work-orders` | `query_platform_data` | 可用用户原话回复，参数用英文 id |
| 2 | 查生产计划 / 排产计划 / 排程计划 / 看看排产 | `production-plans` | `query_platform_data` | **禁止**用工单数据充数 |
| 3 | 查一下状态是 pending 的工单 / 进行中的工单 | `work-orders` | `query_platform_data(filters={"status": ...})` | Mock：`pending` / `in_progress` / `completed` |
| 4 | 把工单导出来 / 导出生产计划成 Excel | 对应实体 | `export_platform_data` | 告知导出路径 |
| 5 | 异常工单 / 高优先级工单 / 紧急单 | `work-orders` | filters：`priority=high|urgent` 或 status | 见 `ops-query-playbook` |
| 6 | 计划里 draft / 已确认的有哪些 | `production-plans` | filters：`status=draft|confirmed` | Mock 样例含两种状态 |

## 实体硬边界

| 说法族 | → entity | 不要答成 |
|--------|----------|----------|
| 工单、生产工单、派工单、WO、工作订单 | `work-orders` | 生产计划 |
| 生产计划、排产、排程、PP、排产单 | `production-plans` | 工单 |

短词「计划」若语境不清：先 `list_platform_entities`，或反问「生产计划还是工单计划数量？」；**不要默认改查另一实体**。

## 手工冒烟（对话）

1. 「查工单」→ 实体为工单，有记录  
2. 「查排程计划」→ 实体为生产计划，**不是**工单号 `WO-…`  
3. 「查 pending 工单」→ 仅 pending（或明确说明过滤条件）  
4. 「导出工单 csv」→ 给出文件路径  
5. （可选）`ENABLE_ENTITY_GUARD=true` 时故意混实体应被拦并改查  

无 LLM 别名断言：`make smoke-entity-phrases`
