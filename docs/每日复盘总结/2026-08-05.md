## 2. 今日做了什么（按主题）

### 2.1 衔接模型（弃厚画像）

- 去掉「按用户+仓库落库画像」作为主路径。
- **同窗口**：对话上下文续聊，不重选仓。
- **新窗口**：先出「先选仓库」卡（已有项目 / 新项目）。
- 已有项目：`GET /api/cursor-dev/repos/inspect` 现场读 GitHub；并结合本机写码 job 连续性推断技术栈/工作分支。

### 2.2 交互与意图

- 放宽写码意图（如「ERP系统新增首页」也能进写码车道）。
- 强制「能勾选就不输入」：Skill + `buildCodingDiscussPrompt`。
- 空仓误判为「新项目再问技术栈」：改为多分支探测 + 从成功 job（登录 FastAPI+Vue）锁定技术栈；前端兜底剥掉误出的技术栈组。

### 2.3 GitHub 预检 403

- 根因：未配 Token，匿名 API **限流** 返回 403，预检硬失败阻断写码。
- 处理：限流/临时 403 **软失败**，仍走 Cursor Cloud；错误文案写清限流与配 Token 建议。

### 2.4 分支策略

- 禁止 `dev/workbuddy-功能名-xxxx` 一功能一支。
- 固定工作分支：`CURSOR_DEV_WORK_BRANCH=hebo`（本机已写入 `.env`）；Prompt 严禁再开功能后缀分支；默认不开 PR。
- 样例仓：登录/首页/smoke 分支 **fast-forward 合并进 main**，创建 **hebo**（与 main 同 tip），删除旧功能分支；用户已将默认分支设为 **hebo**。

## 3. 自检：发现问题与仍存风险

### 3.1 已暴露并已修

| 问题 | 原因 | 处理 |
|------|------|------|
| 新窗直接出技术栈卡、无选仓 | 「新增首页」未命中写码意图 → 走普通 Agent | 放宽意图 + 无仓却出 options 时改弹选仓 |
| 读仓后仍问技术栈 | 只看空 `main`，代码在功能分支；UI 文案与判定矛盾 | 扫工作分支 + job 连续性锁定；文案按 `treat_as_new` 分支 |
| 长文 A~D 逼用户打字 | Skill/提示不够硬 | 铁律 + 空仓选项卡模板 |
| 写码失败 HTTP 403 | 匿名 GitHub 限流，预检硬拦 | 软失败继续 Cloud |
| 一功能一支 | Prompt「分支前缀」诱导随机后缀 | 一人/固定一支 + 仓库收口 |

### 3.2 仍存风险 / 未闭环（明日优先关注）

1. **未配 `GITHUB_TOKEN`**：读仓/预检仍易撞限流；软失败可写码，但 inspect 变慢或不稳。建议管理员补 classic PAT（repo 只读）。
2. **Cursor Cloud 是否 100% 服从「固定分支名」**：依赖 Prompt 约束；SDK 仍可能自建 agent 分支，需实开一轮写码验证只推 `hebo`。
3. **大量改动仍未提交进 WorkBuddy git**：写码车道相关文件多在工作区，复盘文档外需择机整理提交，避免环境漂移。
4. **`/profiles` API 仍保留**：主路径已不用，属死代码/半废弃，后续可删或标 deprecated，避免同事误用。
5. **烟测脚本与新 Prompt 签名**：已改 d4/d5/d7/live；若 CI 还有旧调用需再扫一遍。
6. **登录账号与分支名**：WorkBuddy 登录用户曾是 `admin`，靠 `CURSOR_DEV_WORK_BRANCH=hebo` 覆盖；换环境若忘配 `.env` 会回到 `dev/wb/{用户名}`。

### 3.3 流程自检（有无做错）

- 合并样例仓时 smoke 与 README 冲突，采用 `--theirs` 后提交，**README 可能偏简**（需在 GitHub `hebo` 上肉眼确认是否接受）。
- 改默认分支因无 API Token 未能自动化，依赖用户手动——已完成，无遗留。
- 未对「合 main 后 Cloud 是否仍引用已删功能分支」做回归；连续性已优先 `hebo`，旧 job 里的 legacy 名仅作代码来源提示。
