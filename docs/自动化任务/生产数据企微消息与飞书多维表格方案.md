# 生产数据：企微消息 + 飞书多维表格（功能验证）

> 日期：2026-08-28  
> 状态：**企微消息已实现；飞书多维表格写数 P0 已实现**（append 一行；按日期 upsert 为 P1）  
> 操作步骤见：[操作指南-查生产数据写飞书多维表格.md](./操作指南-查生产数据写飞书多维表格.md)  
> 定位：**功能验证** — 公司日常用企微，飞书多维表格用于验证「结构化落库 + 趋势分析」价值，不依赖公司全面切换飞书  
> 关联：[`PCB早报企微推送方案.md`](./PCB早报企微推送方案.md)、生产日报模板（`mes-daily-production-report`）

## 1. 决策结论（为何这样拆）

领导说「查数推送到飞书」时，常见两种理解：

| 理解 | 通道 | 价值 |
|------|------|------|
| 到点给人看 | **消息** | 触达、提醒、当日扫一眼 |
| 数据沉淀可分析 | **表** | 历史台账、趋势图、周报月报素材 |

**本方案提供两条独立能力（不是捆绑套餐）：**

| 通道 | 用途 | 理由 |
|------|------|------|
| **企业微信群** | **消息推送**（早报摘要） | 公司已用企微；与现有 PCB 早报 / 生产日报推送一致 |
| **飞书多维表格** | **结构化存数**（日汇总行） | 验证「数据资产 + 图表趋势」；试点租户即可，**不要求公司全员迁飞书** |

### 1.1 互不干涉（硬约束）

```text
企微消息  ←→  飞书多维表格
    ↑              ↑
 各自开关        各自开关
 各自成败        各自状态字段
```

| 规则 | 说明 |
|------|------|
| **不是组合必选** | 任务可只开企微、只开写表、两个都开、或两个都关；**禁止**实现成「开写表必须同时推企微」或反过来 |
| **开关独立** | `push_to_wecom` 与 `bitable_sync.enabled` 互不依赖；总开关 `WECOM_PUSH_*` / `FEISHU_BITABLE_*` 也各自控制 |
| **失败独立** | 企微失败不影响写表；写表失败不影响企微；运行记录分别记 `delivery_*` / `bitable_*` |
| **任务可拆** | 可建两个任务：A 只推企微摘要、B 只写多维表格；也可一个任务同时勾选（用户自愿，非强制） |

同一任务「两个都开」只是**可选用法**（一次查数两边都更新），不是架构要求。验证期常见拆法：现网生产日报只开企微；另建「写飞书表」任务专做台账验证。

**不做（本阶段）：**

- 飞书群机器人发消息（公司不用飞书聊天）
- MES ↔ 飞书双向同步
- 用飞书替代 MES 实时大屏
- 把写表做成企微推送的前置/后置依赖

## 2. 端到端流程

查数成功后，**按任务开关分别走旁路**（未开启的通道直接 skip，互不调用）：

```text
Scheduler
  → executor.execute_automation（查数 → summary / 可选 rows）
  → store.update_run（先落盘）
  → if push_to_wecom:     delivery → 企微     → 记 delivery_*
  → if bitable_sync.on:   bitable_sync → 飞书表 → 记 bitable_*
  （两段 if 并列，无先后依赖；任一段异常 try/except 隔离）
```

**原则**

1. **先落盘、再分发**：查数成功 ≠ 企微成功 ≠ 写表成功。  
2. **查数与通道解耦**：执行指令决定「查什么」；各通道开关决定「发不发 / 写不写」。  
3. **通道彼此解耦**：实现上 `deliver_wecom` 与 `sync_bitable` 两个独立函数，禁止互相 import 成功条件。  
4. **密钥不进任务 JSON**：企微 Webhook、飞书 App Secret 仅系统配置。  
5. **可单独关掉**：关飞书总开关或任务未配表 → 只走企微（或都不走）；反之亦然。

## 4. 飞书多维表格（通道 B · 待实现）

### 4.1 写什么（P0：每日 1 行汇总）

建议表头（列名可按试点表微调，用 `field_map` 对齐）：

| 列名 | 含义 | 示例 |
|------|------|------|
| 日期 | 业务「昨日」 | 2026-08-27 |
| 在制工单 | 张 | 28 |
| 未完工 | 张 | 46 |
| 紧急未完工 | 张 | 23 |
| 平均稼动率% | 设备利用率日均 | 83.5 |
| 日产合计 | 件 | 7930 |
| 良率下限% | 工序良率区间 | 97.86 |
| 良率上限% | | 97.88 |
| 需关注摘要 | 文本节选 | 紧急待开工 4 张… |
| 数据来源 | 固定 | ZR WorkBuddy |

表内可建：**按日期折线（稼动率）**、**产量柱状**、**紧急未完工趋势** — 用于向领导演示「自动台账 + 分析」。

### 4.2 飞书侧准备（试点租户即可）

1. 开放平台创建企业自建应用，开通多维表格读写权限。  
2. 发布版本；目标 base 中 **添加该应用** 为可编辑。  
3. 记录 `app_token`、`table_id`；表头与 `field_map` 一致。  
4. 配置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`（系统配置，加密存）。

### 4.3 任务级配置（草案）

```json
{
  "name": "每日生产数据写入飞书表",
  "push_to_wecom": false,
  "bitable_sync": {
    "enabled": true,
    "app_token": "bascxxxx",
    "table_id": "tblxxxx",
    "mode": "append",
    "field_map": {
      "date": "日期",
      "wip_count": "在制工单",
      "open_count": "未完工",
      "urgent_open": "紧急未完工",
      "utilization_avg": "平均稼动率%",
      "output_total": "日产合计",
      "yield_min": "良率下限%",
      "yield_max": "良率上限%",
      "note": "需关注摘要"
    }
  }
}
```

上例为 **只写表、不推企微**。若只要企微：`push_to_wecom: true` 且不配 / 关闭 `bitable_sync`。若两边都要：两开关都开（可选，非必须）。

- `mode: append` — P0 每日追加；同一天多次「立即测试」会多行（P1 再做按日期 upsert）。  
- 未配 `bitable_sync` 或 `enabled: false` → 跳过写表，不影响企微。

### 4.4 数据怎么进表（推荐路径）

| 阶段 | 做法 | 说明 |
|------|------|------|
| **P0** | Agent 摘要后附带严格 JSON `rows[]`，`bitable_writer` 解析映射 | 上线快；靠 Prompt 约束数字 |
| **P1** | 生产日报类任务：固定查数脚本组装 row，再写表；Agent 只写给人看的摘要 | 数字更稳，演示更敢说「与 MES 一致」 |

写表 HTTP 仅允许 `open.feishu.cn`，走 `safe_http`；App Secret 不进日志。

### 4.5 运行记录扩展（草案）

| 字段 | 说明 |
|------|------|
| `delivery_status` 等 | 沿用企微推送状态 |
| `bitable_status` | sent / failed / skipped |
| `bitable_error` | 失败原因 |
| `bitable_record_ids` | 本次写入的记录 id（可选） |

前端运行记录「推送」列旁增加 **写表** 状态，避免与企微混淆。

## 6. 分期与验收

| 阶段 | 内容 | 验收 |
|------|------|------|
| **现状** | 企微消息已通 | 生产日报立即测试 → 群内有摘要 |
| **P0 写表** | append 1 行 + 配置 + 运行记录 | 仅开写表即可验收；**不要求**同任务开企微；关飞书开关 → skipped |
| **P1** | 按日期 upsert；生产日报固定查数写表 | 同日重跑不重复行；数字与运行摘要一致 |
| **P2（可选）** | 设备明细多行；若用户自愿同开企微，消息可附表链接 | 演示趋势图；触达仍可选 |

**功能验证演示话术（可对领导说）：**

> 查数来自公司 MES。**企微群推送**与**飞书多维表格写数**是两套独立能力：  
> 日常触达用企微；表用于验证「自动台账 + 趋势」。可以只用其一，也可以同任务都开——互不绑架。

## 7. 与「自定义自动化任务」的关系

- **查什么**：任务「执行指令」（生产日报模板或用户自定义）。  
- **发企微**：仅由 `push_to_wecom` 决定。  
- **写飞书表**：仅由 `bitable_sync.enabled`（及表配置）决定。  
- **各干各的**：A 任务只推消息、B 任务只写表、C 任务两个都开 —— 三种合法；实现不得默认捆绑。

## 8. 风险与边界

| 风险 | 应对 |
|------|------|
| 公司不用飞书，领导看不到表 | 验证期用试点账号演示；日常触达靠企微；表用于「价值证明」 |
| LLM 填错数字 | P0 约束 JSON；P1 固定查数写表 |
| 立即测试刷出重复行 | 文档说明；P1 upsert |
| 密钥泄露 | Secret 加密；任务只存 app_token/table_id |
